Events სრულად, AbortController, საკონტროლო პროექტი

წინა გაკვეთილში ვისწავლეთ, როგორ ვცვლით DOM-ს. ახლა ვისწავლოთ, როგორ ვარეაგირებთ მომხმარებლის მოქმედებებზე — დაწკაპუნება, აკრეფა, ფორმის გაგზავნა. და ბოლოს, ამ ცოდნით, პორტფოლიოს პროექტი საბოლოოდ, სრულად ინტერაქტიული გახდება.

1. რა არის Event

Event არის „მოვლენა", რომელიც ბრაუზერში ხდება — დაწკაპუნება, კლავიშის დაჭერა, გვერდის ჩატვირთვა, ფორმის გაგზავნა და ა.შ. JavaScript-ს შეუძლია „მოუსმინოს" ამ მოვლენებს და შესაბამისად უპასუხოს.

2. addEventListener

ეს არის სტანდარტული, თანამედროვე გზა event handler-ის მისაბმელად ელემენტზე: 

const button = document.querySelector("#submit-btn");

button.addEventListener("click", function() {
  console.log("ღილაკზე დაწკაპუნდა!");
});

// ან arrow function-ით (უფრო ხშირად გამოსაყენებელი, თანამედროვე კოდში)
button.addEventListener("click", () => {
  console.log("ღილაკზე დაწკაპუნდა!");
});

ხშირად გამოსაყენებელი event ტიპებია: click, submit (ფორმაზე), input/change (input ველზე), keydown/keyup (კლავიატურაზე), mouseover/mouseout (კურსორზე), load (გვერდის/სურათის ჩატვირთვაზე).

მესამე არგუმენტი — options ობიექტი (თანამედროვე, ხშირად გამოტოვებული)

addEventListener-ს შეუძლია მესამე, options ობიექტის მიღება — სამი განსაკუთრებით სასარგებლო თვისებით: 

// once — listener თავად "იშლება" პირველივე გამოძახების შემდეგ
button.addEventListener("click", () => console.log("მხოლოდ ერთხელ!"), { once: true });

// passive — ეუბნება ბრაუზერს "არასდროს არ დავიძახებ preventDefault()-ს"
// გამოსადეგია scroll/touch event-ებზე — ბრაუზერი მაშინვე იწყებს სქროლვას, listener-ის მოლოდინის გარეშე
window.addEventListener("scroll", () => { /* ... */ }, { passive: true });

Listener-ის მოხსნა — removeEventListener და AbortController

ჩვეულებრივი გზა listener-ის მოსახსნელად — removeEventListener — მოითხოვს ზუსტად იმ ფუნქციის „მითითებას" (reference), რომელიც თავდაპირველად დაემატა: 

function handleClick() {
  console.log("დაწკაპუნდა");
}

button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick); // იგივე ფუნქციის მითითება საჭიროა

როცა ბევრი listener გვაქვს, რომელთა ერთდროულად მოცილებაც გვინდა — მოსახერხებელია signal პარამეტრი, AbortController-თან ერთად (დღეს ფართოდ მხარდაჭერილი, MDN-ის მიხედვით): 

const controller = new AbortController();

button.addEventListener("click", handleClick, { signal: controller.signal });
input.addEventListener("input", handleInput, { signal: controller.signal });
window.addEventListener("resize", handleResize, { signal: controller.signal });

// ერთი გამოძახება — სამივე listener ერთდროულად მოიხსნება!
controller.abort();

რატომ არის ეს მნიშვნელოვანი: React-ის მოდულში (მე-22 გაკვეთილი, useEffect) ხშირად საჭირო იქნება, კომპონენტის „გაქრობისას" ყველა მისი event listener მოვაცილოთ, რომ „memory leak" არ გამოვიწვიოთ — AbortController ამის ყველაზე სუფთა, თანამედროვე გზაა.

3. Event Object

Event handler ფუნქცია ავტომატურად იღებს event object-ს, რომელიც შეიცავს ინფორმაციას მომხდარ მოვლენაზე — მათ შორის, თუ რომელმა ელემენტმა გამოიწვია ის: 

button.addEventListener("click", (event) => {
  console.log(event.type);    // "click"
  console.log(event.target);  // კონკრეტული ელემენტი, რომელზეც დაწკაპუნდა (შეიძლება იყოს შვილი)
});

// input-ის მნიშვნელობის წაკითხვა ცოცხლად, აკრეფისას
const searchInput = document.querySelector("#search");
searchInput.addEventListener("input", (event) => {
  console.log(event.target.value); // მიმდინარე ტექსტი input-ში
});

target vs currentTarget — ხშირი გაუგებრობა

event.target არის ის ელემენტი, სადაც event რეალურად მოხდა (შეიძლება იყოს ჩადგმული შვილი). event.currentTarget კი — ის ელემენტი, რომელზეც listener თავად არის მიმაგრებული. Event delegation-ში ეს განსხვავება კრიტიკულია: 

list.addEventListener("click", (event) => {
  console.log(event.target);        // კონკრეტული <li> ან მისი შიგნით <span>, სადაც რეალურად დაწკაპუნდა
  console.log(event.currentTarget); // ყოველთვის list — სადაც listener დევს
});

4. preventDefault — ბრაუზერის ნაგულისხმევი ქცევის შეჩერება

ზოგიერთ ელემენტს (ფორმას, ბმულს) აქვს ნაგულისხმევი ქცევა — მაგ. ფორმის submit ავტომატურად ტვირთავს გვერდს ხელახლა. event.preventDefault() აჩერებს ამ ნაგულისხმევ ქცევას, რომ ჩვენ თავად, JavaScript-ით ვმართოთ, რა მოხდეს. 

const form = document.querySelector("#contact-form");

form.addEventListener("submit", (event) => {
  event.preventDefault(); // აჩერებს გვერდის ავტომატურ ხელახლა ჩატვირთვას

  const email = document.querySelector("#email").value;
  console.log("გაგზავნილი ელფოსტა:", email);
  // აქ შესაძლებელია მონაცემების fetch-ით სერვერზე გაგზავნა (გავეცნობით შემდეგ გაკვეთილებში)
});

preventDefault() ასევე გამოსადეგია ბმულებზეც — მაგ. თუ გვინდა, ბმულმა JavaScript-ის ლოგიკა შეასრულოს ახალ გვერდზე გადასვლის ნაცვლად.

5. Event Delegation

მოვლენათა ბაბლინგი (bubbling) — event, რომელიც შვილ ელემენტზე ხდება, ავტომატურად „ადის" მშობელამდეც. ეს საშუალებას გვაძლევს, ერთი listener დავამაგროთ მშობელზე, ბევრი ინდივიდუალური listener-ის მაგივრად: 

const list = document.querySelector("#todo-list");

list.addEventListener("click", (event) => {
  if (event.target.tagName === "LI") {
    console.log("დაწკაპუნდა:", event.target.textContent);
  }
});
// მუშაობს ყველა <li>-ზეც, თუნდაც ისინი JS-ით მოგვიანებით დაემატოს!

მე-15 გაკვეთილის closest() ხშირად უფრო საიმედოა, ვიდრე event.target.tagName-ის შემოწმება — განსაკუთრებით მაშინ, თუ card-ის შიგნით ჩადგმულია სხვა ელემენტებიც (მაგ. <span> ტეგი-ჩიპები): 

grid.addEventListener("click", (event) => {
  const card = event.target.closest(".project-card"); // "ზემოთ ავდივართ" ხემდე, სანამ card-ს ვერ ვიპოვით
  if (!card) return; // დაწკაპუნდა card-ის გარეთ — არაფერი გვინდა

  console.log("დაწკაპუნდა card-ზე:", card.querySelector("h3").textContent);
});

6. საკონტროლო პროექტი — პორტფოლიო საბოლოოდ ინტერაქტიულია

მე-12-დან მე-15 გაკვეთილამდე ავაწყვეთ მონაცემები, ფუნქციები, მოდულები და DOM-ზე რენდერი — მაგრამ card-ებზე დაწკაპუნება ჯერ არაფერს აკეთებდა. ახლა, Events-ის ცოდნით, დავამატოთ სამი რეალური ინტერაქცია.

ინტერაქცია 1 — ფილტრის ღილაკები (All / Featured)

<!-- index.html-ში, #project-grid-ის წინ -->
<div class="filter-row" id="filter-row">
  <button data-filter="all">ყველა</button>
  <button data-filter="featured">⭐ მხოლოდ გამორჩეული</button>
</div>
// app.js-ში — event delegation ორ ღილაკზე, ერთი listener-ით
const filterRow = document.querySelector("#filter-row");

filterRow.addEventListener("click", (event) => {
  const btn = event.target.closest("button");
  if (!btn) return;

  const filter = btn.dataset.filter; // "all" ან "featured"
  const filtered = filter === "featured" ? getFeaturedProjects(projects) : projects;
  renderProjects(filtered); // მე-15 გაკვეთილის ფუნქცია — ხელახლა გამოძახებადია!
});

ინტერაქცია 2 — Event Delegation card-ებზე, "ნახვის" თვალთვალით

const grid = document.querySelector("#project-grid");

grid.addEventListener("click", (event) => {
  const card = event.target.closest(".project-card");
  if (!card) return;

  const title = card.querySelector("h3").textContent;
  tracker.markViewed(title); // მე-13 გაკვეთილის closure-ფუნქცია!
  card.classList.toggle("is-expanded"); // მარტივი ვიზუალური უკუკავშირი
});

ინტერაქცია 3 — საკონტაქტო ფორმის ვალიდაცია, preventDefault-ით

const form = document.querySelector(".contact-form");

form.addEventListener("submit", (event) => {
  event.preventDefault(); // გვერდის ხელახლა ჩატვირთვა არ გვინდა

  const email = form.querySelector("#email").value.trim();
  if (!email.includes("@")) {
    console.log("⚠️ გთხოვთ, მიუთითოთ ვალიდური ელფოსტა");
    return;
  }

  console.log("✅ ფორმა წარმატებით 'გაიგზავნა' (დემო):", email);
  form.reset(); // ველების გასუფთავება
});

შედეგი: პორტფოლიო ახლა სრულად ინტერაქტიულია — ფილტრი ცოცხლად ცვლის card-ებს, card-ზე დაწკაპუნება „აღნიშნავს" მას ნანახად, ფორმა კი უსაფრთხოდ „მუშავდება" გვერდის გადატვირთვის გარეშე. ერთადერთი, რაც აკლია — რეალური სერვერი, რომელსაც ფორმა გაეგზავნება — ამას Fetch/AJAX-ის გაკვეთილებში (მე-19) მივხედავთ.

გაიმეორე — შეკითხვები

  1. რას აკეთებს { once: true } და როდის დაგვჭირდება ის?
  2. რატომ არის { passive: true } სასარგებლო scroll/touch event-ებზე?
  3. რას აკეთებს AbortController event listener-ების კონტექსტში, და რატომ არის ის უკეთესი, ვიდრე ცალ-ცალკე removeEventListener-ის გამოძახება?
  4. რა განსხვავებაა event.target-სა და event.currentTarget-ს შორის?
  5. რატომ არის closest(".project-card") უფრო საიმედო, ვიდრე event.target.tagName === "..." შემოწმება?
  6. რატომ საჭიროებს ფორმის submit ღილაკი preventDefault()-ს, სხვა ღილაკებისგან განსხვავებით?

პრაქტიკული დავალებები

  1. დაამატე ღილაკს click event listener, რომელიც ცვლის მისი ტექსტის შემცველობას დაწკაპუნებისას.
  2. დაამატე input ველს input event listener, რომელიც ცოცხლად აჩვენებს აკრეფილი სიმბოლოების რაოდენობას გვერდზე.
  3. დაწერე ერთი listener { once: true }-ით და ერთი — ჩვეულებრივი — შეადარე, რამდენჯერ გამოიძახება თითოეული 5 დაწკაპუნების შემდეგ.
  4. დაწერე AbortController-ის მაგალითი — მიამაგრე 2-3 listener ერთი signal-ით, შემდეგ ერთი ღილაკით ყველა ერთდროულად მოაცილე.
  5. შექმენი მარტივი ფორმა და დაამატე submit event, სადაც preventDefault()-ის შემდეგ Console-ში ბეჭდავ input-ის მნიშვნელობას.
  6. შექმენი სია (<ul>-ში 4-5 <li>) და event delegation-ის გამოყენებით (listener მშობელზე) დაბეჭდე, რომელ ელემენტზე დაწკაპუნდა — გამოიყენე event.target და event.currentTarget ორივე, დააკვირდი განსხვავებას.
  7. (რთული) ააწყვე მარტივი "to-do" — input + ღილაკი „დამატება". დაწკაპუნებისას (ან Enter-ზე) createElement-ის გამოყენებით დაამატე ახალი <li> სიაში, ხოლო თითოეულ <li>-ზე დაწკაპუნებამ წაშალოს ის (event delegation-ის გამოყენებით).
  8. (საკონტროლო პროექტი) გახსენი მე-12-მე-15 გაკვეთილების პორტფოლიოს პროექტი და დაამატე სამივე ინტერაქცია ზემოთ ნაჩვენები კოდით — ფილტრის ღილაკები, card-ზე დაწკაპუნების თვალთვალი, და ფორმის ვალიდაცია. დარწმუნდი, რომ ყველა listener event delegation-ს იყენებს სადაც შესაძლებელია, ცალკეული ელემენტების ხელით დამუშავების ნაცვლად.
