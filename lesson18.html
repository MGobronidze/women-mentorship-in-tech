Promises სრულად, Event Loop, To-Do App პროექტი

რეალურ აპლიკაციებში ბევრი რამ არ ხდება მყისიერად — მონაცემების წამოღება სერვერიდან, ტაიმერები. ამ გაკვეთილში ვსწავლობთ, როგორ ვმართავთ ამ „დროში გაწელილ" ოპერაციებს — და ბოლოს, ყველაფერს ვიყენებთ სრული To-Do აპლიკაციის ასაწყობად.

1. setTimeout — ასინქრონულობის უმარტივესი მაგალითი

JavaScript არის ერთნაკადიანი (single-threaded) ენა — ერთდროულად მხოლოდ ერთ ბრძანებას ასრულებს. მაგრამ ბრაუზერს (და Node.js-ს) აქვს მექანიზმი, რომელიც საშუალებას გვაძლევს, გარკვეული კოდი „გადავდოთ" მოგვიანებით შესასრულებლად — setTimeout. 

console.log("1. დაწყება");

setTimeout(() => {
  console.log("3. 2 წამის შემდეგ");
}, 2000);

console.log("2. გაგრძელება — ეს დაბეჭდვა setTimeout-ს არ ელოდება!");

// კონსოლში გამოვა: "1. დაწყება" → "2. გაგრძელება..." → (2 წამის შემდეგ) "3. 2 წამის შემდეგ"

ეს არის ასინქრონულობის არსი: setTimeout არ „აჩერებს" დანარჩენ კოდს — ის მხოლოდ გეგმავს ფუნქციას მომავალში შესასრულებლად.

2. Callbacks და Callback Hell

Callback არის ფუნქცია, რომელსაც სხვა ფუნქციას გადავცემთ, რომ ის „მოგვიანებით" გამოიძახოს (მაგ. მონაცემების მზაობისას). პრობლემა ჩნდება, როცა ბევრი ასინქრონული ოპერაცია ერთმანეთზეა დამოკიდებული: 

// Callback Hell — ჩადგმული callback-ების "პირამიდა", ძნელად წასაკითხი
getUser(userId, (user) => {
  getOrders(user.id, (orders) => {
    getOrderDetails(orders[0].id, (details) => {
      console.log(details); // ყოველი დონე უფრო შორდება მარცხენა კიდეს
    }, handleError);
  }, handleError);
}, handleError);

ეს სტრუქტურა (ე.წ. „pyramid of doom") ძნელად იკითხება და ძნელად გამართავს — სწორედ ამის გადასაჭრელად შემოვიდა Promise.

3. Promises

Promise არის ობიექტი, რომელიც წარმოადგენს მომავალში დასრულებულ (ან წარუმატებელ) ოპერაციას. მას აქვს სამი მდგომარეობა: pending (მიმდინარეობს), fulfilled (წარმატებული) და rejected (წარუუმატებელი). 

const fetchUser = new Promise((resolve, reject) => {
  setTimeout(() => {
    const success = true;
    if (success) {
      resolve({ name: "ანა", id: 1 }); // წარმატება
    } else {
      reject(new Error("მომხმარებელი ვერ მოიძებნა")); // შეცდომა
    }
  }, 1000);
});

fetchUser
  .then((user) => console.log("მიღებულია:", user))
  .catch((error) => console.error("შეცდომა:", error.message))
  .finally(() => console.log("დასრულდა (წარმატებით ან არა)"));

.then() ჯაჭვად შესაძლებელია, რაც Callback Hell-ის პრობლემას წყვეტს — ჩადგმის ნაცვლად, ოპერაციები ერთმანეთის „ქვემოთ" გრძელდება: 

getUser(userId)
  .then(user => getOrders(user.id))
  .then(orders => getOrderDetails(orders[0].id))
  .then(details => console.log(details))
  .catch(error => console.error(error)); // ერთი catch ყველა ჯაჭვის ნაბიჯისთვის

Promise-ის კომბინატორები — all, allSettled, any, race

როცა ერთდროულად, პარალელურად რამდენიმე Promise-ის დასრულებას ველოდებით (არა ერთმანეთზე დამოკიდებულს, როგორც ზემოთ), ოთხი მეთოდი გვეხმარება — თითოეული განსხვავებულად რეაგირებს შეცდომებზე:

მეთოდი ეს ხდება გამოყენების შემთხვევა
Promise.all() Fail-fast — ერთის წარუმატებლობაც საკმარისია, რომ მთელი ოპერაცია ჩავარდეს ყველა შედეგი აუცილებელია, ან არცერთი არ გინდა
Promise.allSettled() არასდროს „ჩავარდება" — ყოველთვის აბრუნებს ყველას შედეგს (status: "fulfilled"/"rejected") ნაწილობრივი წარუმატებლობაც მისაღებია — გინდა ყველა შედეგის ნახვა
Promise.any() წყდება პირველივე წარმატებაზე გჭირდება მხოლოდ ერთი, ნებისმიერი წარმატებული შედეგი
Promise.race() წყდება პირველივე დასრულებაზე (წარმატება ან შეცდომა) "ვინც პირველი მოვა" — მაგ. timeout-ის იმიტაცია 
// allSettled — ყოველთვის იცის ყველა შედეგი, რაც ჩავარდა და რაც არა
const results = await Promise.allSettled([saveTodo(a), saveTodo(b), saveTodo(c)]);

const successful = results.filter((r) => r.status === "fulfilled");
const failed = results.filter((r) => r.status === "rejected");
console.log(`${successful.length} წარმატებული, ${failed.length} ჩავარდა`);

4. async/await

async/await არის სინტაქსური „შაქარი" Promise-ების თავზე — საშუალებას გვაძლევს, ასინქრონული კოდი დავწეროთ ისე, თითქოს ის სინქრონული იყოს (მარტივად წასაკითხი, ზემოდან ქვემოთ): 

async function loadUserData() {
  try {
    const user = await getUser(userId);        // "ელოდება" Promise-ის დასრულებას
    const orders = await getOrders(user.id);
    const details = await getOrderDetails(orders[0].id);
    console.log(details);
  } catch (error) {
    console.error("რაღაც არასწორად წავიდა:", error.message); // try/catch ცვლის .catch()-ს
  }
}

await გამოსაყენებელია მხოლოდ async ფუნქციის შიგნით. ის „აჩერებს" კონკრეტულად ამ ფუნქციის შესრულებას (არა მთელ პროგრამას!), სანამ Promise არ დასრულდება — შემდეგ აგრძელებს შემდეგი ხაზიდან.

ხშირი შეცდომა — არასაჭირო თანმიმდევრული await

თუ ორი await ერთმანეთზე არ არის დამოკიდებული, მათი თანმიმდევრული დალოდება ტყუილად ანელებს კოდს: 

// ნელი — 2 წამი ჯამში, თუ ორივე ოპერაცია თითო წამს სჭირდება
const todos = await fetchTodos();     // ელოდება დასრულებას...
const settings = await fetchSettings(); // ...მხოლოდ შემდეგ იწყებს ამას

// სწრაფი — 1 წამი ჯამში, ორივე პარალელურად
const [todos2, settings2] = await Promise.all([fetchTodos(), fetchSettings()]);

წესი: await თანმიმდევრულად მხოლოდ მაშინ გამოიყენე, როცა მეორე ოპერაციას ნამდვილად სჭირდება პირველის შედეგი — წინააღმდეგ შემთხვევაში, Promise.all()-ით დაიწყე ორივე ერთდროულად.

5. Microtask Queue vs Macrotask Queue — Event Loop

ეს არის ერთ-ერთი ყველაზე ხშირად დასმული, „გამოცდილი" JavaScript-ის კითხვა — რატომ ასრულდება Promise-ის .then() ხშირად უფრო ადრე, ვიდრე setTimeout(..., 0), თუნდაც ორივე „მომავალში" იყოს დაგეგმილი? 

console.log("1. სინქრონული");

setTimeout(() => console.log("4. setTimeout (macrotask)"), 0);

Promise.resolve().then(() => console.log("3. Promise .then (microtask)"));

console.log("2. ისევ სინქრონული");

// შედეგი: "1. სინქრონული" → "2. ისევ სინქრონული" → "3. Promise .then" → "4. setTimeout"
// მიუხედავად იმისა, რომ setTimeout კოდში ადრე წერია!

ახსნა: JavaScript-ის „event loop" ჯერ ასრულებს მთელ სინქრონულ კოდს, შემდეგ სრულად ცარიელჰყოფს microtask queue-ს (Promise-ის .then/catch/finally callback-ები — მაღალი პრიორიტეტის) — და მხოლოდ ამის შემდეგ იღებს ერთ დავალებას macrotask queue-დან (setTimeout, event handler-ები). 

┌─────────────────────────────┐
│  1. Call Stack (სინქრონული)  │  ← ჯერ ეს სრულად სრულდება
└─────────────────────────────┘
┌─────────────────────────────┐
│  2. Microtask Queue          │  ← შემდეგ ეს, მთლიანად (Promise .then)
└─────────────────────────────┘
┌─────────────────────────────┐
│  3. Macrotask Queue          │  ← მხოლოდ ბოლოს, ერთი დავალება ციკლზე (setTimeout)
└─────────────────────────────┘

პრაქტიკული დასკვნა: ამ დეტალის ზედმიწევნით ცოდნა ყოველდღიურ კოდში იშვიათად გჭირდება, მაგრამ ხსნის ბევრ „უცნაურ" ქცევას, რომელსაც დიდ, რთულ აპლიკაციებში ხშირად ხვდები — და ეს არის ზუსტად ის თემა, რომელსაც ხშირად ტექნიკურ გასაუბრებაზე გეკითხებიან.

6. საკონტროლო პროექტი — To-Do App, ასინქრონული ლოგიკით

ახლა ავაწყოთ სრული To-Do აპლიკაცია, რომელიც იყენებს 1-დან 18-ე გაკვეთილამდე ნასწავლ ყველა ძირითად კონცეფციას — მასივები/ობიექტები, ფუნქციები/closure, DOM-რენდერი, Event Delegation, და ახლა — ასინქრონული „შენახვა", თითქოს რეალურ სერვერზე გავდიოდეთ (სერვერის იმიტაცია setTimeout-ით, რეალური backend-ის გარეშე).

HTML — საბაზისო სტრუქტურა

<section class="todo-app">

    <input type="text" id="todo-input" placeholder="ახალი დავალება..." required>
    <button type="submit">დამატება</button>
  </form>

  <p id="todo-status"></p>  <!-- "ინახება..." / "შენახულია" / შეცდომა -->

JS — მონაცემები და "სერვერის" იმიტაცია

let todos = []; // { id, text, completed }
let nextId = 1;

// "სერვერზე შენახვის" იმიტაცია — Promise, 20% შანსით ჩავარდება (რეალისტური სცენარისთვის)
function saveTodoToServer(todo) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (Math.random() < 0.2) {
        reject(new Error("ქსელის შეცდომა — ვერ შეინახა"));
      } else {
        resolve({ ...todo, savedAt: Date.now() }); // spread — immutable განახლება (მე-14 გაკვეთილი)
      }
    }, 800); // 800ms "ქსელის დაყოვნება"
  });
}

JS — DOM რენდერი და Event Delegation (მე-15/16 გაკვეთილები)

function createTodoElement(todo) {
  const { id, text, completed } = todo; // destructuring, მე-14
  const li = document.createElement("li");
  li.dataset.id = id;
  if (completed) li.classList.add("completed");

  li.insertAdjacentHTML("beforeend", `
    <input type="checkbox" ${completed ? "checked" : ""}>
    <span>${text}</span>
    <button class="delete-btn" aria-label="წაშლა">✕</button>
  `);
  return li;
}

function renderTodos() {
  const list = document.querySelector("#todo-list");
  const fragment = document.createDocumentFragment(); // batch insert, მე-15

  for (const todo of todos) {
    fragment.appendChild(createTodoElement(todo));
  }

  list.innerHTML = "";
  list.appendChild(fragment);
}

// Event Delegation — ერთი listener მთელი სიისთვის (მე-16 გაკვეთილი)
document.querySelector("#todo-list").addEventListener("click", (event) => {
  const li = event.target.closest("li");
  if (!li) return;
  const id = Number(li.dataset.id);

  if (event.target.matches(".delete-btn")) {
    todos = todos.filter((t) => t.id !== id); // filter, მე-12
    renderTodos();
  } else if (event.target.matches("input[type='checkbox']")) {
    todos = todos.map((t) => (t.id === id ? { ...t, completed: !t.completed } : t)); // map + spread, immutable
    renderTodos();
  }
});

JS — async/await + try/catch, loading state

const form = document.querySelector("#todo-form");
const input = document.querySelector("#todo-input");
const status = document.querySelector("#todo-status");

form.addEventListener("submit", async (event) => {
  event.preventDefault(); // preventDefault, მე-16

  const text = input.value.trim();
  if (!text) return;

  const newTodo = { id: nextId++, text, completed: false };

  status.textContent = "⏳ ინახება...";
  status.setAttribute("data-state", "pending");

  try {
    await saveTodoToServer(newTodo); // "სერვერზე" შენახვის მოლოდინი
    todos.push(newTodo);
    renderTodos();
    input.value = "";
    status.textContent = "✅ შენახულია";
    status.setAttribute("data-state", "success");
  } catch (error) {
    status.textContent = `⚠️ ${error.message} — სცადე ხელახლა`;
    status.setAttribute("data-state", "error");
  }
});

JS — Promise.allSettled: "ყველას სინქრონიზაცია" ღილაკი

async function syncAllTodos() {
  status.textContent = `⏳ ${todos.length} დავალების სინქრონიზაცია...`;

  const results = await Promise.allSettled(
    todos.map((todo) => saveTodoToServer(todo)) // ყველა პარალელურად, ერთდროულად
  );

  const failed = results.filter((r) => r.status === "rejected").length;
  status.textContent = failed === 0
    ? "✅ ყველა დავალება წარმატებით სინქრონიზდა"
    : `⚠️ ${failed} დავალება ვერ სინქრონიზდა, დანარჩენი — წარმატებით`;
}

რატომ allSettled, არა all: თუ 10 დავალებიდან ერთი ჩავარდება, Promise.all() მთელ ოპერაციას „ჩაშლიდა" — allSettled კი გვაჩვენებს ზუსტად, რომელი 9 შევინახეთ წარმატებით და რომელი ერთი ვერა.

პრაქტიკული დავალებები

  1. დაწერე setTimeout-ის გამოყენებით 3 შეტყობინება, რომლებიც ცალ-ცალკე დროის დაყოვნებით გამოჩნდება Console-ში — დააკვირდი, რომ ისინი არ ელოდებიან ერთმანეთს.
  2. შექმენი მარტივი Promise, რომელიც 50% შემთხვევაში resolve-დება და 50%-ში reject-დება (Math.random()-ის გამოყენებით) — გამოსცადე .then()/.catch().
  3. გადაწერე წინა დავალების Promise async/await-ისა და try/catch-ის გამოყენებით.
  4. დაწერე 3 Promise (სხვადასხვა setTimeout-ის დაყოვნებით) და გამოსცადე Promise.all(), Promise.allSettled() და Promise.race() ერთსა და იმავე მასივზე — შეადარე შედეგები.
  5. დაწერე მოკლე console.log მაგალითი, რომელიც აჩვენებს microtask-ის პრიორიტეტს macrotask-ზე (Promise.resolve().then() vs setTimeout(..., 0)).
  6. (რთული) დაწერე async ფუნქცია, რომელიც იყენებს Promise.all()-ს ორი ან მეტი დამოუკიდებელი Promise-ის პარალელურად დასასრულებლად (ერთმანეთის მოლოდინის ნაცვლად) — შეადარე შესრულების დრო თანმიმდევრულ (sequential await) მიდგომასთან.
