ფუნქციები სრულად, Scope, Closure, საკონტროლო პროექტი

ფუნქცია არის კოდის ხელახლა გამოსაყენებელი ბლოკი. ეს გაკვეთილი — ერთ-ერთი ყველაზე მნიშვნელოვანია მთელ კურსში, რადგან ფუნქციები და scope-ი JavaScript-ის „ჩონჩხს" წარმოადგენს. ბოლოს კი, ამ ცოდნით, დავხვეწავთ წინა შეხვედრაზე დაწყებულ პორტფოლიოს პროექტს.

1. Function Declaration

ეს არის ფუნქციის „კლასიკური" გამოცხადება — function საკვანძო სიტყვით:

function greet(name) {
  return `გამარჯობა, ${name}!`;
}

console.log(greet("ანა")); // "გამარჯობა, ანა!"

Function Declaration-ს აქვს განსაკუთრებული თვისება — hoisting (დეტალურად შემდგომ გაკვეთილში): მისი გამოძახება შესაძლებელია ფაილში მისი გამოცხადებამდეც კი.

Default პარამეტრები — ნაგულისხმევი მნიშვნელობები

თუ ფუნქციის გამოძახებისას არგუმენტი არ გადაეცემა (ან undefined-ია), default parameter ავტომატურად „ჩაანაცვლებს" მას წინასწარ განსაზღვრული მნიშვნელობით — ეს გვათავისუფლებს ხელით შემოწმებისგან (if (name === undefined)): 

function greet(name = "სტუმარო") {
  return `გამარჯობა, ${name}!`;
}

console.log(greet());        // "გამარჯობა, სტუმარო!" — არგუმენტი არ გადაეცა
console.log(greet("ანა"));   // "გამარჯობა, ანა!" — გადაცემული მნიშვნელობა იმარჯვებს
console.log(greet(undefined)); // "გამარჯობა, სტუმარო!" — undefined ითვლება "არგადაცემულად"

Default პარამეტრი შეიძლება იყოს გამოსახულებაც, თუნდაც სხვა პარამეტრზე დამოკიდებული: 

function createUser(name, role = "მომხმარებელი", id = Date.now()) {
  return { name, role, id };
}

2. Function Expression

ფუნქცია ინახება ცვლადში — ინახება, როგორც ჩვეულებრივი მნიშვნელობა:

const greet = function(name) {
  return `გამარჯობა, ${name}!`;
};

console.log(greet("მარი"));

Function Expression-ის არ არის hoisted — მისი გამოძახება გამოცხადებამდე Error-ს გამოიწვევს.

Named Function Expression — სახელი debugging-ისთვის

Function Expression-ს შესაძლებელია ჰქონდეს სახელიც — ეს სახელი ხელმისაწვდომია მხოლოდ ფუნქციის საკუთარ სხეულში (რეკურსიისთვის) და ჩანს DevTools-ის stack trace-ში, დებაგირებისას გაცილებით გასაგები რომ იყოს: 

const factorial = function calcFactorial(n) {
  if (n <= 1) return 1;
  return n * calcFactorial(n - 1); // საკუthარი სახელით საკუთარ თავს იძახებს
};

console.log(factorial(5)); // 120
// calcFactorial(n) გარედან არ არსებობს — მხოლოდ ფუნქციის შიგნით ჩანს

IIFE — Immediately Invoked Function Expression

IIFE არის ფუნქცია, რომელიც განისაზღვრება და მაშინვე გამოიძახება, ერთ ნაბიჯად — ძირითადად გამოიყენებოდა ცვლადების „იზოლირებისთვის" (რათა მათ გლობალური scope არ "დაებინძურებინათ"), სანამ ES6 მოდულები (მე-14 გაკვეთილი) იარსებებდა: 

(function() {
  const secret = "ეს ცვლადი მხოლოდ აქ არსებობს";
  console.log("IIFE გაეშვა!");
})(); // ბოლო () მაშინვე უშვებს ფუნქციას

console.log(typeof secret); // "undefined" — secret გარეთ საერთოდ არ ჩანს

თანამედროვე კონტექსტი: დღეს IIFE-ის ბევრი ისტორიული გამოყენება ჩანაცვლებულია ES6 მოდულებით (<script type="module">) და block scope-ით (let/const) — თითოეულ მოდულს უკვე აქვს საკუთარი, იზოლირებული scope, IIFE-ის გარეშეც. მაინც ღირს მისი ცოდნა — ხშირად ჯერ კიდევ გვხვდება ძველ ბიბლიოთეკებში და ზოგიერთ bundler-ის გენერირებულ კოდში.

3. Arrow Function

ES6-მა შემოგვთავაზა უფრო მოკლე სინტაქსი ფუნქციისთვის — arrow function (=>): 

// სრული ფორმა
const greet = (name) => {
  return `გამარჯობა, ${name}!`;
};

// მოკლე ფორმა — ერთი გამოსახულება, ავტომატური return
const greetShort = name => `გამარჯობა, ${name}!`;

// პარამეტრის გარეშე / რამდენიმე პარამეტრით
const sayHi = () => console.log("გამარჯობა!");
const add = (a, b) => a + b;

this — კონკრეტული განსხვავება, მაგალითით

this JavaScript-ში არის სპეციალური საკვანძო სიტყვა (keyword), რომელიც მიუთითებს იმ ობიექტზე, რომლის კონტექსტშიც ამჟამად სრულდება კოდი. მარტივად რომ ვთქვათ: this პასუხობს კითხვას — „ვინ იძახებს ამ ფუნქციას?“

Arrow function-ს, ჩვეულებრივი ფუნქციისგან განსხვავებით, არ აქვს საკუთარი this — ის „ისესხებს" მშობელი (lexical) scope-ის this-ს. მაგალითად: 

const card = {
  title: "ჩემი ბარათი",

  // ჩვეულებრივი ფუნქცია — this ეხება იმას, ვინც ფუნქციას "იძახებს" (card ობიექტს)
  showRegular: function() {
    console.log(this.title); // "ჩემი ბარათი" — this === card
  },

  // Arrow function — this "სესხულობს" გარე (გლობალურ) scope-ს, არა card-ს!
  showArrow: () => {
    console.log(this.title); // undefined — this აქ არ არის card
  },
};

card.showRegular(); // "ჩემი ბარათი"
card.showArrow();    // undefined

ჩვეულებრივი ფუნქციისთვის this-ის მნიშვნელობა განისაზღვრება გამოძახების მომენტში. როდესაც წერ card.showRegular(), ფუნქციის მარცხნივ წერია card. ეს ნიშნავს, რომ ფუნქცია უშუალოდ card ობიექტმა გამოაძახა. ფუნქციის შიგნით this ხდება card ობიექტი, ამიტომ this.title აბრუნებს "ჩემი ბარათი".

Arrow function-ს საერთოდ არ აქვს საკუთარი this. ის არ დაგიდევს, თუ ვინ იძახებს მას (card. წერია წინ თუ სხვა რამ). ის this-ს იღებს იმ გარემოდან (Scope), სადაც ეს ობიექტი შეიქმნა. card ობიექტის ჩანაწერი { ... } არ ქმნის ახალ Scope-ს (Scope-ს ქმნის მხოლოდ ფუნქციები). შესაბამისად, showArrow-ს გარშემო არსებული გარემო არის გლობალური არეალი (window ბრაუზერში). Arrow function-მა this „ისესხა“ გლობალური არეალიდან, სადაც title ცვლადი საერთოდ არ არსებობს (ანუ window.title არის undefined). ამიტომ დაიბეჭდა undefined.

პრაქტიკული წესი: ობიექტის მეთოდებისთვის (როცა this-ს იმ ობიექტზე ამოწმებ) გამოიყენე ჩვეულებრივი function. Arrow function საუკეთესოა callback-ებისთვის (მაგ. array.map(item => ...)), სადაც სწორედ გვინდა, რომ this „მემკვიდრეობით" მიეღოს გარე კონტექსტიდან — ამ დეტალს React-ის მოდულში პრაქტიკაში დავინახავთ.

4. Function Scope და Block Scope

Scope განსაზღვრავს, სად „ჩანს" ცვლადი კოდში. var-ს აქვს function scope (ჩანს მთელ ფუნქციაში), ხოლო let/const-ს — block scope (ჩანს მხოლოდ იმ { }-ში, სადაც გამოცხადდა): 

if (true) {
  var x = 1;    // function/global scope — "გაჟონავს" block-იდან
  let y = 2;    // block scope — ჩანს მხოლოდ ამ { }-ში
}

console.log(x); // 1 — ✅ ხელმისაწვდომია
console.log(y); // ❌ ReferenceError: y is not defined

სწორედ ეს „გაჟონვა" არის ერთ-ერთი მთავარი მიზეზი, რატომ ერიდებიან თანამედროვე დეველოპერები var-ს — მისი scope ინტუიციურ არ არის.

5. Lexical Scope და Scope Chain

Lexical scope ნიშნავს, რომ ცვლადის „ხილვადობა" განისაზღვრება იმით, სად არის ფუნქცია დაწერილი კოდში (არა სად გამოიძახება). შიდა ფუნქციას აქვს წვდომა გარე ფუნქციის ცვლადებზე — ეს ქმნის scope chain-ს: 

function outer() {
  const outerVar = "გარეთ";

  function inner() {
    const innerVar = "შიგნით";
    console.log(outerVar); // ✅ ხედავს გარე ფუნქციის ცვლადს (scope chain)
    console.log(innerVar); // ✅ საკუთარი ცვლადი
  }

  inner();
  console.log(innerVar); // ❌ Error — გარე ფუნქცია ვერ ხედავს შიდას
}

6. Closure — ჩაკეტვები

Closure (ჩაკეტვა) მარტივი სიტყვებით არის ფუნქციის „პირადი მეხსიერება“. როდესაც ფუნქცია ქმნის შიდა ფუნქციას და მას გარეთ აბრუნებს, ეს შიდა ფუნქცია თან მიაქვს და იმახსოვრებს იმ ცვლადებს, რომლებიც მის გარშემო იყვნენ შექმნის მომენტში. 

function makeCounter() {
  let count = 0; // ეს ცვლადი "ჩაიკეტება" დაბრუნებულ ფუნქციასთან ერთად

  return function() {
    count++;
    return count;
  };
}

const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2 — "ახსოვს" წინა მნიშვნელობა!
console.log(counter()); // 3

Closure-ი პრაქტიკაში ხშირად გამოიყენება: private მონაცემების შესაქმნელად (გარედან count-თან პირდაპირი წვდომა არ არსებობს), event handler-ებში კონტექსტის შესანარჩუნებლად და React-ის hooks-ის (მოგვიანებით ვნახავთ) მუშაობის საფუძვლადაც.

პრაქტიკული გამოყენება — Memoization (closure-ზე დაფუძნებული cache)

Memoization არის ოპტიმიზაციის ტექნიკა — ფუნქცია „იმახსოვრებს" უკვე გამოთვლილ შედეგებს, რომ იმავე არგუმენტით ხელახლა გამოძახებისას არ გაიმეოროს ძვირადღირებული გამოთვლა. ეს closure-ის ერთ-ერთი ყველაზე პრაქტიკული, რეალურ პროექტებში ნახული გამოყენებაა: 

function memoize(fn) {
  const cache = {}; // closure-ით "დაცული" cache — გარედან პირდაპირი წვდომა არ არსებობს

  return function(n) {
    if (n in cache) {
      console.log(`(cache-იდან: ${n})`);
      return cache[n];
    }
    console.log(`(გამოითვლება: ${n})`);
    const result = fn(n);
    cache[n] = result;
    return result;
  };
}

function slowSquare(n) {
  for (let i = 0; i < 500000000; i++) {} // განზრახ "ნელი" გამოთვლა
  return n * n;
}

const fastSquare = memoize(slowSquare);
fastSquare(5); // "(გამოითვლება: 5)" — ნელი, პირველად
fastSquare(5); // "(cache-იდან: 5)" — მყისიერი, მეხსიერებიდან

7. საკონტროლო პროექტი — ფუნქციები პორტფოლიოს პროექტში

წინა შეხვედრაზე (მე-12 გაკვეთილი) ავაწყვეთ პორტფოლიოს გვერდი და data.js — სადაც filter/map/reduce პირდაპირ, თანმიმდევრულად ვწერდით. ახლა, ფუნქციების ცოდნით, ეს ლოგიკა გადავაქციოთ სუფთა, სახელიან, ხელახლა გამოსაყენებელ ფუნქციებად — ზუსტად ისე, როგორც რეალურ პროექტებში ხდება.

„მანამდე" — თანმიმდევრული, ერთჯერადი კოდი (მე-12 გაკვეთილიდან)

// ეს კოდი მუშაობს, მაგრამ ხელახლა გამოყენებადი არ არის — ლოგიკა "ჩარჩენილია" ერთ ადგილას
const featuredProjects = projects.filter((p) => p.featured);
const summaries = projects.map((p) => `${p.title} (${p.year})`);

„შემდეგ" — სახელიანი ფუნქციები (Declaration/Expression/Arrow — შესაბამისად არჩეული)

// Function Declaration — მთავარი, სახელიანი "API" ფუნქციები project-utils.js-ში
function getFeaturedProjects(projectList = projects) {
  return projectList.filter((p) => p.featured);
}

function getProjectsByTag(projectList, tag) {
  return projectList.filter((p) => p.tags.includes(tag));
}

// Arrow function — მოკლე, ერთხაზიანი "დამხმარე" ფუნქციები
const formatProjectSummary = (project) => `${project.title} (${project.year})`;
const countTags = (projectList) =>
  projectList.reduce((total, p) => total + p.tags.length, 0);

// Function Expression — Object.groupBy-ზე "შეფუთული" სახელიანი ვერსია
const groupByYear = function groupProjectsByYear(projectList) {
  return Object.groupBy(projectList, (p) => p.year);
};

Closure-ზე დაფუძნებული ახალი ფუნქცია — "ნახვების" თვალთვალი

დავამატოთ ერთი ახალი, closure-ზე დაფუძნებული ფუნქცია — createViewTracker() — რომელიც "იმახსოვრებს", რომელი პროექტები „დათვალიერდა" (ლოგირდა), makeCounter-ის იმავე პატერნით, მაგრამ პროექტისთვის რეალურად გამოსადეგი ვერსიით: 

function createViewTracker() {
  const viewedTitles = []; // closure-ით "დაცული" კერძო მდგომარეობა

  return {
    markViewed(title) {
      if (!viewedTitles.includes(title)) {
        viewedTitles.push(title);
      }
      console.log(`ნანახია: ${title} (სულ: ${viewedTitles.length})`);
    },
    getViewedCount() {
      return viewedTitles.length;
    },
  };
}

const tracker = createViewTracker();
tracker.markViewed("To-Do აპლიკაცია");
tracker.markViewed("პორტფოლიოს საიტი");
tracker.markViewed("To-Do აპლიკაცია"); // უკვე ნანახია — არ დაემატება ხელახლა
console.log("სულ განხილული პროექტი:", tracker.getViewedCount()); // 2

რატომ არის ეს refactoring ღირებული: ფუნქციები (1) მალავენ დეტალებს („როგორ" გამოითვლება), ჩანს მხოლოდ „რას" აკეთებენ; (2) ხელახლა გამოსაყენებელია — getFeaturedProjects() შეგვიძლია გამოვიძახოთ ნებისმიერ ადგილას; (3) ცალკე ტესტვადია. მომდევნო კვირებში, DOM-ისა (მე-15) და event-ების (მე-16) სწავლის შემდეგ, ეს ზუსტად ეს ფუნქციები გამოვიძახოთ ღილაკზე დაწკაპუნებისას, რომ შედეგი Console-ის ნაცვლად პირდაპირ გვერდზე გამოვსახოთ — არქიტექტურა უკვე მზადაა ამისთვის.

პრაქტიკული დავალებები

  1. დაწერე ერთი და იგივე ფუნქცია სამივე ფორმით — Declaration, Expression და Arrow — რომელიც ორ რიცხვს ამრავლებს.
  2. დაწერე ფუნქცია default პარამეტრით (მაგ. ფასდაკლების პროცენტი, ნაგულისხმევად 0) და გამოსცადე ის არგუმენტით და მის გარეშე.
  3. დაწერე IIFE, რომელიც ერთხელ, გვერდის ჩატვირთვისას, Console-ში ბეჭდავს მისალმებას.
  4. დაწერე ობიექტი მეთოდით, რომელიც იყენებს this-ს — ჯერ ჩვეულებრივი ფუნქციით, შემდეგ იგივე arrow function-ით — შეადარე Console-ის შედეგები.
  5. დაწერე კოდი, სადაც var-ითა და let-ით გამოცხადებულ ცვლადებს ადარებ block scope-ში — დააკვირდი განსხვავებას Console-ში.
  6. დაწერე ორი ჩადგმული ფუნქცია (outer/inner), სადაც inner ფუნქცია იყენებს outer-ის ცვლადს — ეს დაასაბუთებს scope chain-ს.
  7. დაწერე makeCounter-ის მსგავსი closure ფუნქცია, მაგრამ ისეთი, რომელიც საწყისი მნიშვნელობის (ორმაგდება) ნაცვლად აკლებს რიცხვს.
  8. (რთული) დაწერე closure-ზე დაფუძნებული „ბანკის ანგარიშის" სიმულაცია — ფუნქცია, რომელიც აბრუნებს ორ ფუნქციას (deposit და getBalance), სადაც balance ცვლადი მთლიანად „დაცულია" გარედან პირდაპირი წვდომისგან.
