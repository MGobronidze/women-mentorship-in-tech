DOM სრულად, Performance, საკონტროლო პროექტი

აქამდე JavaScript-ს ვწერდით „ცალკე" — ახლა ვაკავშირებთ მას რეალურ გვერდთან. DOM არის ის ხიდი, რომლითაც JavaScript ხედავს და ცვლის HTML-ს რეალურ დროში. და, ბოლოს, ამ ცოდნით, პორტფოლიოს პროექტის მონაცემები საბოლოოდ რეალურად გამოვსახავთ გვერდზე — Console-ის ნაცვლად.

1. რა არის DOM

DOM (Document Object Model) არის HTML დოკუმენტის „ხის" სახის წარმოდგენა მეხსიერებაში, რომელსაც ბრაუზერი ქმნის გვერდის ჩატვირთვისას. თითოეული HTML ტეგი DOM-ში ხდება node (კვანძი) — და JavaScript-ს შეუძლია ამ კვანძების წაკითხვა, შეცვლა, დამატება თუ წაშლა. 

<!-- HTML -->
<body>
  <h1>სათაური</h1>
  <p>ტექსტი</p>
</body>

// DOM ხედავს ამას, როგორც ხის სტრუქტურას:
// document
//   └─ body
//       ├─ h1 ("სათაური")
//       └─ p ("ტექსტი")

2. defer და async — სკრიპტების ჩატვირთვა

<script> ტეგის მდებარეობა და ატრიბუტები გავლენას ახდენს იმაზე, თუ როდის სრულდება JS კოდი, HTML-ის დამუშავებასთან შედარებით: 

<!-- ჩვეულებრივი: ჩერდება HTML-ის დამუშავება, სანამ სკრიპტი არ ჩაიტვირთება და გაეშვება -->
<script src="script.js"></script>

<!-- defer: ჩატვირთვა ხდება პარალელურად, გაშვება — HTML-ის სრულად დამუშავების შემდეგ -->
<script src="script.js" defer></script>

<!-- async: ჩატვირთვა და გაშვება ხდება პარალელურად,  როგორც კი JavaScript  ფაილის გადმოწერა 
(ჩატვირთვა) დასრულდება, ბრაუზერი იმავე წამს აჩერებს HTML-ის დამუშავებას და უშუალოდ იწყებს 
გადმოწერილი JavaScript კოდის შესრულებას. -->
<script src="script.js" async></script>

საუკეთესო პრაქტიკა: გამოიყენე defer, თუ სკრიპტს სჭირდება DOM-თან მუშაობა (რაც ხშირად ასეა) — ეს უზრუნველყოფს, რომ ყველა HTML ელემენტი უკვე არსებობდეს, სანამ JS მათ „მოძებნის".

შეხსენება მე-14 გაკვეთილიდან: <script type="module"> ავტომატურად იქცევა defer-ის მსგავსად — ცალკე defer ატრიბუტის დამატება მოდულებზე საჭირო აღარ არის.

3. Query Selectors — ელემენტების პოვნა

// ID-ით — აბრუნებს ერთ ელემენტს
const header = document.getElementById("main-title");

// CSS სელექტორით — აბრუნებს პირველ დამთხვევას
const firstCard = document.querySelector(".card");

// CSS სელექტორით — აბრუნებს ყველა დამთხვევას (NodeList)
const allCards = document.querySelectorAll(".card");

// კლასის/ტეგის მიხედვით (ძველი, მაგრამ ჯერ კიდევ გამოსადეგი API)
const byClass = document.getElementsByClassName("card");
const byTag = document.getElementsByTagName("li");

querySelector/querySelectorAll დღეს ყველაზე ხშირად გამოსაყენებელია, რადგან იღებს ნებისმიერ ვალიდურ CSS სელექტორს — Class, ID, atrribute, ჩადგმულს: 

const item = document.querySelector("#nav .links li:first-child");
const emailInputs = document.querySelectorAll("input[type='email']");

querySelectorAll აბრუნებს NodeList-ს, არა ჩვეულებრივ მასივს — მას აქვს forEach, მაგრამ არა map/filter პირდაპირ. საჭიროების შემთხვევაში, მასივად გარდაქმნა: Array.from(nodeList).

closest() და matches() — „ზემოთ ძებნა" და პირობითი შემოწმება

// closest() — ეძებს უახლოეს წინაპარს (ან თავად ელემენტს), რომელიც სელექტორს ემთხვევა
const card = someInnerElement.closest(".project-card"); // "ზემოთ ავდივართ" ხემზე, სანამ არ ვიპოვით

// matches() — ამოწმებს, ემთხვევა თუ არა ელემენტი კონკრეტულ სელექტორს
if (element.matches(".featured")) {
  console.log("ეს გამორჩეული ელემენტია");
}

closest() განსაკუთრებით გამოსადეგი გახდება მე-16 გაკვეთილში, event delegation-ის დროს — როცა event ხდება შვილ ელემენტზე, მაგრამ გვინდა ვიცოდეთ, რომელ „მშობელ" card-ს ეკუთვნის ის.

4. ელემენტების შექმნა და ატრიბუტების მინიჭება

DOM-ის ცვლილება ხდება არა მხოლოდ არსებული ელემენტების პოვნით, არამედ ახლების შექმნითაც: 

// ახალი ელემენტის შექმნა
const newCard = document.createElement("div");

// კლასის და ატრიბუტების მინიჭება
newCard.classList.add("card");
newCard.setAttribute("data-id", "42");
newCard.id = "card-42";

// შემცველობის ჩასმა
newCard.textContent = "ეს არის ახალი ბარათი"; // უსაფრთხო — HTML-ად არ განიხილება
newCard.innerHTML = "<strong>ეს</strong> ბარათი";  // HTML-ად განიხილება — ფრთხილად, XSS რისკი მომხმარებლის ტექსტთან

// DOM-ში ჩასმა (მშობელი ელემენტის მითითებით)
const container = document.querySelector(".container");
container.appendChild(newCard);

// წაშლა
newCard.remove();

უსაფრთხოების წესი: textContent-ს გამოიყენე, როცა უბრალო ტექსტს ამატებ (განსაკუთრებით, თუ ეს ტექსტი მომხმარებლისგან მოდის) — innerHTML ტექსტს პარსავს ((Parsing) ნიშნავს ტექსტის წაკითხვას, გაანალიზებას და მისი კოდის სტრუქტურად გადაქცევას.) HTML-ად, რაც შეიძლება საშიში იყოს (Cross-Site Scripting).

insertAdjacentHTML() — თანამედროვე, სწრაფი ალტერნატივა

innerHTML += "..." (მასივში ელემენტის „დამატებისას") ყოველ ჯერზე ხელახლა პარსავს მთელ შემცველობას — ეს ნელია, დიდ სიებზე. insertAdjacentHTML() პარსავს მხოლოდ ახალ ნაწილს, ოთხი ზუსტი პოზიციიდან ერთ-ერთში: 

const list = document.querySelector("#project-list");

list.insertAdjacentHTML("beforeend", `<li>ახალი პროექტი</li>`);
// "beforebegin" | "afterbegin" | "beforeend" | "afterend" — ოთხივე შესაძლო პოზიცია

DocumentFragment — ბევრი ელემენტის ეფექტური ჩასმა

როცა ერთდროულად ბევრი ელემენტის დამატება გვჭირდება (მაგ. მასივის თითოეული ელემენტისთვის ცალკე card), თითოეულის ცალ-ცალკე appendChild-ით დამატება ყოველ ჯერზე იწვევს ბრაუზერის „ხელახლა დათვლას" (reflow) — ნელია დიდ სიებზე. DocumentFragment არის „უხილავი კონტეინერი" — ყველა ელემენტს ჯერ მასში ვაგროვებთ, და ბოლოს, ერთი ოპერაციით ვამატებთ რეალურ DOM-ში: 

const container = document.querySelector("#project-list");
const fragment = document.createDocumentFragment(); // "უხილავი" კონტეინერი, ჯერ არ არის DOM-ში

for (const project of projects) {
  const li = document.createElement("li");
  li.textContent = project.title;
  fragment.appendChild(li); // ემატება "უხილავ" fragment-ს — DOM ჯერ არ იცვლება
}

container.appendChild(fragment); // ერთი ოპერაცია — ბრაუზერი მხოლოდ ერთხელ "ითვლის" ხელახლა

წესი: 1-2 ელემენტისთვის ეს განსხვავება შეუმჩნეველია — მაგრამ 10+, და განსაკუთრებით ასეულობით ელემენტისთვის, DocumentFragment-ის გამოყენება საგრძნობლად აჩქარებს გვერდის რენდერს.

5. საკონტროლო პროექტი — პორტფოლიო DOM-ზე, ბოლოს-და-ბოლოს!

მე-12 გაკვეთილიდან პროექტების მონაცემები მხოლოდ Console-ში იბეჭდებოდა, ხოლო card-ები index.html-ში ხელით, სტატიკურად იყო ჩაწერილი. ახლა, DOM-ის ცოდნით, ეს ორი ცალკეული ნაწილი საბოლოოდ „შევაერთოთ" — HTML-დან წავშალოთ ხელით ჩაწერილი card-ები, და JS-მა ისინი projects მასივიდან დინამიურად გამოსახოს.

ნაბიჯი 1 — HTML: სტატიკური card-ების ჩანაცვლება ერთი, ცარიელი კონტეინერით

<!-- ძველი: 4 card ხელით ჩაწერილი -->
<div class="project-grid">
  <article class="project-card">...</article>
  <article class="project-card">...</article>
  ... -->

<!-- ახალი: ერთი ცარიელი კონტეინერი, id-ით, რომ JS-მა იპოვოს -->
<div class="project-grid" id="project-grid"></div>

ნაბიჯი 2 — app.js: render ფუნქცია, DocumentFragment-ით

import { projects } from "./data.js";
import { getFeaturedProjects } from "./project-utils.js";

function createProjectCard(project) {
  const { title, year, tags, featured } = project; // destructuring, მე-14 გაკვეთილიდან

  const card = document.createElement("article");
  card.className = "project-card";
  if (featured) card.setAttribute("data-featured", "true");

  const tagsHTML = tags.map((tag) => `<span>${tag}</span>`).join("");
  const badgeHTML = featured ? `<span class="featured-badge">⭐ გამორჩეული</span>` : "";

  // insertAdjacentHTML — სწრაფი, ერთჯერადი ჩასმა ერთი card-ის შიგნით
  card.insertAdjacentHTML("beforeend", `
    <div class="project-top">
      <div>${badgeHTML}<h3>${title}</h3></div>
      <span class="project-year">${year}</span>
    </div>
    <div class="project-tags">${tagsHTML}</div>
  `);

  return card;
}

function renderProjects(projectList) {
  const container = document.querySelector("#project-grid");
  const fragment = document.createDocumentFragment(); // batch — ერთი reflow, ბევრი card-ის მაგივრად

  for (const project of projectList) {
    fragment.appendChild(createProjectCard(project));
  }

  container.innerHTML = ""; // ჯერ ვასუფთავებთ (თუ ძველი კონტენტი იყო)
  container.appendChild(fragment); // ერთი ოპერაცია — ყველა card ერთდროულად ემატება
}

renderProjects(projects); // საწყისად — ყველა პროექტი

შედეგი: გვერდზე ახლა რეალურად ჩანს 4 card, მონაცემებიდან გენერირებული — არა ხელით HTML-ში ჩაწერილი. თუ projects მასივს ახალ ობიექტს დავამატებთ (spread-ით, მე-14 გაკვეთილის addProject()-ის მსგავსად) და renderProjects()-ს ხელახლა გამოვიძახებთ — ახალი card ავტომატურად გამოჩნდება, ხელით HTML-ის შეხების გარეშე.

რჩება ერთადერთი „ხარვეზი": ღილაკებზე დაწკაპუნება (მაგ. „მხოლოდ გამორჩეულების ჩვენება" ფილტრი) ჯერ არაფერს არ აკეთებს — ეს არის ზუსტად ის, რასაც მომდევნო გაკვეთილში, Events-ის სწავლისას, დავამატებთ.

გაიმეორე — შეკითხვები

  1. რას ნიშნავს, რომ DOM არის „ხის" (tree) სტრუქტურა?
  2. რატომ არის defer უსაფრთხო არჩევანი DOM-თან მომუშავე სკრიპტისთვის?
  3. რას აკეთებს closest() და როდის დაგვჭირდება ის მომდევნო გაკვეთილში?
  4. რატომ არის insertAdjacentHTML() ხშირად უფრო სწრაფი, ვიდრე innerHTML += "..."?
  5. რას აკეთებს DocumentFragment და რატომ არის ის სასარგებლო, როცა ბევრი ელემენტის დამატება გვჭირდება ერთდროულად?
  6. რატომ წავშალეთ HTML-დან ხელით ჩაწერილი project card-ები საკონტროლო პროექტში?

პრაქტიკული დავალებები

  1. გამოიყენე querySelector ერთი ელემენტის მოსაძებნად და შეუცვალე textContent JS-დან.
  2. გამოიყენე querySelectorAll რამდენიმე ელემენტზე და forEach-ის გამოყენებით შეუცვალე ყველას ერთი და იმავე კლასი.
  3. შექმენი 3 ახალი <li> ელემენტი JS-დან (createElement) და ჩასვი არსებულ <ul>-ში.
  4. დაუმატე ერთ ელემენტს ატრიბუტი data-status="active" JS-დან და შემდეგ querySelector-ის გამოყენებით იპოვე ის ატრიბუტის მნიშვნელობის მიხედვით ([data-status="active"]).
  5. გადაწერე ერთი innerHTML += "..." მაგალითი insertAdjacentHTML("beforeend", ...)-ის გამოყენებით.
  6. შექმენი 20 <li> ელემენტი ციკლში — ჯერ ცალ-ცალკე appendChild-ით, შემდეგ DocumentFragment-ის გამოყენებით — შეადარე კოდის სტრუქტურა.
