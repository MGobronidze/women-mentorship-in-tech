შედარება, პირობები, ლუპები (for/while) და Type Coercion

პროგრამები არსებობს იმისთვის, რომ გადაწყვეტილებები მიიღონ და განმეორებადი მოქმედებები შეასრულონ. ამ გაკვეთილში ვსწავლობთ, როგორ ვადარებთ მნიშვნელობებს, როგორ ვმართავთ პროგრამის დინებას პირობების მიხედვით, და როგორ ვიმეორებთ მოქმედებას ციკლებით.

1. შედარების ოპერატორები

// უტოლობის/თანასწორობის ოპერატორები
5 > 3      // true — მეტია
5 < 3      // false — ნაკლებია
5 >= 5     // true — მეტი ან ტოლი
5 <= 4     // false — ნაკლები ან ტოლი

// თანასწორობა: == (loose) vs === (strict)
5 == "5"   // true  — ტიპს არ ამოწმებს, მხოლოდ მნიშვნელობას (coercion ხდება)
5 === "5"  // false — ამოწმებს ტიპსაც და მნიშვნელობასაც
5 !== "5"  // true  — strict "არ არის ტოლი"

მნიშვნელოვანი წესი: თანამედროვე JavaScript-ში თითქმის ყოველთვის ვიყენებთ === და !==-ს, ==/!=-ის ნაცვლად — ეს გვიცავს მოულოდნელი, „ჩუმად" მომხდარი ტიპის კონვერტაციისგან.

Object.is() — როცა === არ არის საკმარისად ზუსტი

===-საც ჰყავს ორი ცნობილი „უცნაური" შემთხვევა: NaN === NaN არის false (თუმცა ინტუიციურად უნდა იყოს true), ხოლო -0 === 0 არის true (თუმცა ტექნიკურად განსხვავებული მნიშვნელობებია). ES6-ის Object.is() ამ ორ გამონაკლისს ასწორებს: 

NaN === NaN        // false — მოულოდნელი!
Object.is(NaN, NaN) // true — Object.is უფრო "მათემატიკურად ზუსტია"

-0 === 0            // true
Object.is(-0, 0)     // false

პრაქტიკაში Object.is() იშვიათად გჭირდება — ჩვეულებრივი შედარებისთვის === სავსებით საკმარისია. მაგრამ ღირს იცოდე, რომ ის არსებობს, თუ როდისმე NaN-ის ან -0-ის ზუსტი შემოწმება დაგჭირდება.

2. if / else — პირობითი ოპერატორი

let age = 20;

if (age >= 18) {
  console.log("სრულწლოვანია");
} else if (age >= 13) {
  console.log("მოზარდია");
} else {
  console.log("ბავშვია");
}

if-ის ფრჩხილებში მოთავსებული გამოსახულება ყოველთვის გარდაიქმნება true/false-ად (ე.წ. truthy/falsy შემოწმება). Falsy მნიშვნელობებია: false, 0, "" (ცარიელი სტრიქონი), null, undefined, NaN. ყველა დანარჩენი — truthy-ია.

Nullish Coalescing (??) — თანამედროვე ალტერნატივა ||-ისთვის

ძველად, ნაგულისხმევი მნიშვნელობის მისაცემად ხშირად ||-ს იყენებდნენ — მაგრამ მას ჰქონდა პრობლემა: 0, "" და false ყველა falsy-ია, ამიტომ || მათაც „ცვლიდა" ნაგულისხმევით, თუნდაც ისინი ვალიდური, განზრახ მითითებული მნიშვნელობები ყოფილიყო: 

let discount = 0; // მომხმარებელმა შეგნებულად აირჩია 0% ფასდაკლება

// ძველი გზა — || — შეცდომას იძლევა
let finalDiscount1 = discount || 10; // 10 — ❌ არასწორია! 0 იყო "ვალიდური" მნიშვნელობა

// თანამედროვე გზა — ?? — მხოლოდ null/undefined-ს ცვლის
let finalDiscount2 = discount ?? 10; // 0 — ✅ სწორია, discount ხომ განსაზღვრულია

let username;
let displayName = username ?? "სტუმარი"; // "სტუმარი" — username მართლაც undefined-ია

წესი: გამოიყენე ??, როცა გინდა ნაგულისხმევი მხოლოდ null/undefined-ის შემთხვევაში (ანუ „მნიშვნელობა საერთოდ არ არსებობს"), და || — მხოლოდ მაშინ, როცა შეგნებულად გინდა ყველა falsy მნიშვნელობის ჩანაცვლება.

Optional Chaining (?.) — უსაფრთხო წვდომა ჩადგმულ ობიექტებში

როცა ობიექტის ღრმად ჩადგმულ თვისებას ვკითხულობთ, ერთ-ერთი შუალედური საფეხური შეიძლება არ არსებობდეს — ჩვეულებრივი dot notation ამ დროს Error-ს გამოიწვევს. ?. „ჩუმად" წყვეტს ჯაჭვს და აბრუნებს undefined-ს, Error-ის ნაცვლად: 

const user = { name: "ანა" }; // user.address საერთოდ არ არსებობს

console.log(user.address.city);   // ❌ TypeError: Cannot read properties of undefined
console.log(user.address?.city);  // ✅ undefined — უსაფრთხოდ "ჩერდება" და აბრუნებს undefined-ს

// ხშირად ერთად გამოიყენება ?? -სთან, სრული "უსაფრთხო წვდომა + ნაგულისხმევის" პატერნისთვის
const city = user.address?.city ?? "მითითებული არ არის";

3. switch case

როცა ერთი ცვლადის ბევრ კონკრეტულ მნიშვნელობასთან გვჭირდება შედარება, switch ხშირად წაკითხვადია if/else if ჯაჭვზე მეტად: 

let day = "სამშაბათი";

switch (day) {
  case "ორშაბათი":
    console.log("კვირის დასაწყისი");
    break;
  case "სამშაბათი":
  case "ოთხშაბათი":
    console.log("კვირის შუა");
    break;
  default:
    console.log("სხვა დღე");
}

break აუცილებელია — მისი გამოტოვება იწვევს „fall-through"-ს (შესრულება გრძელდება შემდეგ case-შიც). ორი case-ის ერთად ჩაწერა (ისე, როგორც ზემოთ) გამოსადეგია, როცა რამდენიმე მნიშვნელობას ერთი და იგივე შედეგი უნდა.

4. Ternary ოპერატორი

Ternary არის მოკლე ჩანაწერი მარტივი if/else-ისთვის — ერთ ხაზზე, გამოსახულების სახით (ანუ, მას შეიძლება პირდაპირ მივანიჭოთ ცვლადს): 

// condition ? ჭეშმარიტ_შემთხვევაში : მცდარ_შემთხვევაში
let age = 20;
let status = age >= 18 ? "სრულწლოვანი" : "არასრულწლოვანი";
console.log(status); // "სრულწლოვანი"

წაკითხვადობის წესი: ternary კარგია ერთი, მარტივი პირობისთვის. ჩადგმული ternary-ები (a ? b : c ? d : e) სწრაფად ხდება ძნელად წასაკითხავი — ასეთ შემთხვევაში, ჩვეულებრივი if/else if ან switch სჯობს.

5. ლუპები — for და while

ციკლი (loop) საშუალებას გვაძლევს, ერთი და იგივე კოდის ბლოკი მრავალჯერ შევასრულოთ, ხელით გამეორების გარეშე. JavaScript-ს აქვს რამდენიმე ტიპის ციკლი — დავიწყოთ ორი ყველაზე ფუნდამენტურით.

for — როცა წინასწარ ვიცით გამეორებების რაოდენობა

for ციკლი შედგება სამი ნაწილისგან, წერტილ-მძიმეებით გამოყოფილი: საწყისი მნიშვნელობა, პირობა (სანამ ეს true-ა, ციკლი გრძელდება) და ნაბიჯი (რა ხდება ყოველი გამეორების ბოლოს): 

for (let i = 0; i < 5; i++) {
  console.log(i); // 0, 1, 2, 3, 4
}
// i = 0        — საწყისი მნიშვნელობა (სრულდება მხოლოდ ერთხელ)
// i < 5        — პირობა (მოწმდება ყოველი გამეორების დაწყებამდე)
// i++          — ნაბიჯი (სრულდება ყოველი გამეორების ბოლოს)

for საუკეთესოა, როცა წინასწარ ვიცით, რამდენჯერ გვინდა გამეორება — მაგ. მასივის ინდექსებზე გავლა (i < array.length), ან კონკრეტული რაოდენობის გამეორება.

while — როცა გამეორებების რაოდენობა წინასწარ უცნობია

while ციკლი განმეორდება მანამ, სანამ პირობა true-ა — გამოსადეგია, როცა ზუსტად არ ვიცით, რამდენჯერ დაგვჭირდება გამეორება (მაგ. სანამ მომხმარებელი სწორ პასუხს არ შემოიტანს): 

let countdown = 3;

while (countdown > 0) {
  console.log(countdown);
  countdown--; // აუცილებელია! წინააღმდეგ შემთხვევაში — უსასრულო ციკლი
}
console.log("Გაშვება!");

საშიშროება: თუ დაგავიწყდა პირობის „შემცირება" (ან პირობა არასდროს ხდება false), ციკლი არასდროს გაჩერდება და ბრაუზერი „გაიყინება" — ეს ერთ-ერთი ყველაზე ხშირი დამწყები დეველოპერის შეცდომაა.

do...while — ციკლი, რომელიც სულ ცოტა ერთხელ სრულდება

do...while ჯერ ასრულებს კოდის ბლოკს, და შემდეგ ამოწმებს პირობას — ეს ნიშნავს, რომ ბლოკი ყოველთვის სულ ცოტა ერთხელ სრულდება, თუნდაც პირობა თავიდანვე false იყოს: 

let attempts = 0;

do {
  console.log("მცდელობა #" + (attempts + 1));
  attempts++;
} while (attempts < 3);
// გამოსცემს: "მცდელობა #1", "მცდელობა #2", "მცდელობა #3"

break და continue

// break — მთლიანად წყვეტს ციკლს
for (let i = 0; i < 10; i++) {
  if (i === 5) break; // ციკლი ჩერდება, როცა i === 5
  console.log(i); // 0, 1, 2, 3, 4
}

// continue — გამოტოვებს მიმდინარე გამეორებას, აგრძელებს შემდეგით
for (let i = 0; i < 5; i++) {
  if (i === 2) continue; // 2-ს გამოტოვებს
  console.log(i); // 0, 1, 3, 4
}

საუკეთესო პრაქტიკა — როდის for/while, როდის — array მეთოდები

მომდევნო გაკვეთილში ვისწავლით map(), filter() და სხვა მასივის მეთოდებს, რომლებიც ხშირად უფრო წაკითხვადია, ვიდრე ხელით დაწერილი for ციკლი. თანამედროვე JavaScript-ში ზოგადი წესია:

  • მასივის გარდაქმნისთვის (ახალი მასივის შესაქმნელად) — სჯობს map()/filter().
  • ადრეული გამოსვლისთვის (მაგ. მოძებნა და დაუყოვნებლივ გაჩერება), წარმადობაზე კრიტიკულ კოდში, ან როცა გამეორებების რაოდენობა წინასწარ უცნობია — for/while სულ ისევ საუკეთესო არჩევანია.
  • while განსაკუთრებით გამოსადეგია non-array სცენარებში — მაგ. „სანამ API-დან შემდეგი გვერდი მოდის" ან „სანამ მომხმარებელი ვალიდურ input-ს არ შემოიტანს".

6. Type Coercion

Coercion არის ავტომატური ტიპის კონვერტაცია, რომელსაც JavaScript ატარებს „ჩუმად", როცა სხვადასხვა ტიპის მნიშვნელობებს ერთმანეთს ვადარებთ ან ვაერთიანებთ ოპერატორებით. 

// String coercion — + ოპერატორი string-თან ერთად აქცევს ყველაფერს string-ად
"5" + 3      // "53" (string) — 3 გარდაიქმნა "3"-ად
"ასაკი: " + 25  // "ასაკი: 25"

// Numeric coercion — სხვა არითმეტიკული ოპერატორები (-, *, /) string-ს რიცხვად აქცევს
"5" - 3      // 2 (number)
"10" * "2"   // 20 (number)
"abc" - 1    // NaN — "abc" ვერ გარდაიქმნა რიცხვად

// Boolean coercion — if/&&/||-ში ავტომატურად
if ("გამარჯობა") { console.log("truthy!"); }  // შესრულდება — არაცარიელი სტრიქონი truthy-ია
if (0) { console.log("არ შესრულდება"); }     // 0 — falsy
Boolean("")   // false
Boolean("0")  // true — ეს არის სტრიქონი "0", არა რიცხვი 0!

საუკეთესო პრაქტიკა: Coercion-ის გაგება მნიშვნელოვანია შეცდომების ამოსაცნობად, მაგრამ საკუთარ კოდში აჯობებს მისი შეგნებული, აშკარა გამოყენება (მაგ. Number(str), String(num)) — არა იმედის მინდობა „ჩუმ" კონვერტაციაზე.

პრაქტიკული დავალებები

  1. დაწერე if/else if/else ბლოკი, რომელიც შეაფასებს გამოცდის ქულას (0-100) და დაბეჭდავს ასოით შეფასებას (A/B/C/D/F).
  2. იგივე ლოგიკა გადაწერე switch-ის გამოყენებით (მაგ. ქულის დიაპაზონების ნაცვლად — კვირის დღეების მაგალითზე).
  3. დაწერე ternary ოპერატორი, რომელიც ცვლადს ანიჭებს "ლუწი" ან "კენტი" — რიცხვის მიხედვით.
  4. დაწერე ობიექტი (მაგ. user), რომელსაც არ აქვს ერთ-ერთი ჩადგმული თვისება, და ?.-ისა და ??-ის კომბინაციით უსაფრთხოდ წაიკითხე ის, ნაგულისხმევი მნიშვნელობით.
  5. for ციკლის გამოყენებით დაბეჭდე რიცხვები 1-დან 10-მდე, continue-ის გამოყენებით ლუწი რიცხვების გამოტოვებით.
  6. დაწერე while ციკლი, რომელიც აგროვებს შემთხვევით რიცხვებს (Math.random()), სანამ ჯამი 50-ს არ გადააჭარბებს — გამოიყენე break საჭიროების შემთხვევაში.
  7. დაწერე do...while ციკლი, რომელიც სულ ცოტა ერთხელ ითხოვს „პაროლს" (თუნდაც ჰარდქოდირებულ ცვლადში) და იმეორებს, სანამ სწორი არ იქნება.
  8. Console-ში გამოსცადე 5 სხვადასხვა coercion მაგალითი ("5" + 5, "5" - 5 და სხვ.) და დანიშნე, რომელი შედეგი გაგაკვირვა.
  9. (რთული) დაწერე კოდი, რომელიც discount = 0-ისთვის შედარებას აკეთებს ||-ითა და ??-ით — დაბეჭდე ორივე შედეგი და ახსენი, რატომ განსხვავდება ისინი.
