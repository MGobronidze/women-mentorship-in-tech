CSS · 04/24

CSS სინტაქსი, სტრუქტურული ტეგები, Class/ID, Normalize, Box Model

HTML-მა მოგვცა სტრუქტურა. ახლა ვიწყებთ CSS მოდულს — ჯერ გავეცნობით გვერდის „კონტეინერ" ტეგებს (div/section/header/main/footer), შემდეგ ვისწავლით, როგორ ვხატავთ ამ სტრუქტურას Class/ID სელექტორებით, როგორ ვამყარებთ ერთნაირ საწყის წერტილს ყველა ბრაუზერში (Reset/Normalize), და როგორ „ითვლის" ბრაუზერი თითოეული ელემენტის ზომებს.

1. CSS-ის სინტაქსი

CSS კოდი შედგება სელექტორისგან (რომელ ელემენტს ვირჩევთ) და ბლოკისგან ფიგურულ ფრჩხილებში, სადაც ჩამწერია ერთი ან მეტი თვისება: მნიშვნელობა; წყვილი. 

selector {
  property: value;
  property: value;
}

/* მაგალითი */
p {
  color: #171F1B;
  font-size: 16px;
}

CSS-ის დაკავშირების 3 გზა

  • გარეგანი (External) — <link> ტეგით <head>-ში. საუკეთესო პრაქტიკა.
  • შიდა (Internal) — <style> ტეგში, <head>-ში.
  • ჩანაწერი (Inline) — პირდაპირ ელემენტის style ატრიბუტში. იშვიათად გამოიყენება.
<!-- External — რეკომენდებული -->
<link rel="stylesheet" href="style.css">

<!-- Inline -->
<p style="color: red;">ტექსტი</p>

HTML-ის მსგავსად, CSS-შიც შესაძლებელია კომენტარების ჩაწერა — ისინი ჩაწერილია /* ... */ შორის და გავლენას არ ახდენენ სტილზე: 

/* ეს არის კომენტარი — გამოსადეგია კოდის ორგანიზებისთვის */
.btn {
  padding: 10px 16px; /* ღილაკის შიდა მანძილები */
}

2. სტრუქტურული HTML ტეგები: div, section, header, main, footer

სანამ სელექტორებით ელემენტების სტილიზებას განვაგრძობთ, გავეცნოთ იმ „კონტეინერ" ტეგებს, რომლებიც ქმნიან გვერდის ჩონჩხს, რომელსაც შემდეგ Class/ID სელექტორებით ვსტილავთ.

  • <div> — ზოგადი, „უსახური" კონტეინერი, საკუთარი სემანტიკური მნიშვნელობის გარეშე. გამოიყენება მხოლოდ მაშინ, როცა ელემენტების დაჯგუფება/სტილიზება გვინდა, და არცერთი სემანტიკური ტეგი შინაარსობრივად არ ესადაგება.
  • <header> — შესავალი/სათაურის ბლოკი. შესაძლოა იყოს ერთხელ, მთელი გვერდისთვის (ლოგო, ნავიგაცია), ან განმეორდეს ცალკეულ <article>/<section>-ში (მაგ. სტატიის სათაური და თარიღი).
  • <main> — გვერდის მთავარი, უნიკალური შემცველობა. ერთი გვერდზე მხოლოდ ერთხელ გამოიყენება — screen reader-ს საშუალებას აძლევს, პირდაპირ „გადახტეს" მთავარ კონტენტზე, ნავიგაციის გვერდის ავლის გარეშე.
  • <section> — თემატურად დაჯგუფებული შემცველობა, ჩვეულებრივ საკუთარი სათაურით (<h2>/<h3>). თუ ბლოკს არ აქვს ცალკე თემა/სათაური — <div> უფრო სწორი არჩევანია.
  • <footer> — დამხურავი ინფორმაცია (საავტორო უფლებები, კონტაქტი, ბმულები). ისევე, როგორც <header>, შესაძლოა იყოს გვერდის დონეზეც და ცალკეულ სექციაშიც.

ეს არის ზუსტად ის სტრუქტურა, რომელსაც ეს კურსის საიტი იყენებს ყველა გვერდზე:

<body>
  <header class="site-header">      <!-- ერთხელ, მთელი გვერდისთვის -->
    <nav>...</nav>
  </header>

  <main>                        <!-- ერთადერთი main გვერდზე -->
    <section class="hero">         <!-- თემატური ბლოკი, სათაურით -->
      <h1>სათაური</h1>
    </section>

    <div class="card-grid">     <!-- უბრალო კონტეინერი, ლეიაუტისთვის -->
      <div class="card">...</div>
    </div>
  </main>

  <footer class="site-footer">      <!-- ერთხელ, მთელი გვერდისთვის -->
    <p>© 2026</p>
  </footer>
</body>

წესი „section vs div"-ის ამოსაცნობად: თუ დაწერდი ბლოკს ცალკე სათაურს (და ის აზრიანად „იკითხება" დოკუმენტის სქემაში/outline-ში) — <section>. თუ საჭიროა მხოლოდ ვიზუალური დაჯგუფება (მაგ. grid-ის კონტეინერი, wrapper padding-ისთვის) — <div>.

3. სელექტორების ტიპები

სელექტორი განსაზღვრავს, რომელ ელემენტ(ებ)ს მიესადაგება სტილი:

/* Element — ეხება ყველა <p>-ს */
p { line-height: 1.6; }

/* Class — ეხება class="card" მქონე ყველა ელემენტს */
.card { border-radius: 12px; }

/* ID — ეხება ერთადერთ, უნიკალურ ელემენტს */
#main-nav { position: sticky; }

/* Universal — ეხება ყველა ელემენტს */
* { box-sizing: border-box; }

/* Descendant — ეხება .card-ის შიგნით ჩადგმულ <p>-ებს */
.card p { color: gray; }

Class გამოსადეგია განმეორებადი სტილებისთვის, ID — ერთადერთი, უნიკალური ელემენტისთვის. ჩვეულებრივ სტილიზაციისთვის Class-ს ვირჩევთ, რადგან ის მრავალჯერ გამოსაყენებელია.

კლასი

ერთ ელემენტს შესაძლებელია ერთდროულად ბევრი Class ჰქონდეს (space-ით გამოყოფილი) — ეს არის ყველაზე ხშირი, მოქნილი გზა სტილების „კომბინირებისთვის": 

<div class="card featured">...</div>

/* .card — ეხება ყველა card-ს */
.card { border-radius: 12px; padding: 20px; }

/* .featured — ეხება ყველა featured ელემენტს (card-იც შეიძლება იყოს, სხვაც) */
.featured { border: 2px solid gold; }

/* .card.featured (space-ის გარეშე!) — ეხება მხოლოდ იმ ელემენტს, სადაც ორივე კლასია ერთად */
.card.featured { box-shadow: 0 4px 12px rgba(0,0,0,.15); }

ID, როდის ვირჩევთ ID-ს

ID სამი ძირითადი დანიშნულებით გამოიყენება, CSS სტილიზების გარდაც:

  • JavaScript-იდან პოვნა — document.getElementById("id") ან querySelector("#id") (მე-15 გაკვეთილში ვისწავლით დეტალურად).
  • Fragment ბმულები — გვერდის კონკრეტულ ნაწილზე პირდაპირი გადასვლა, მაგ. index.html#syllabus (ზუსტად ისე, როგორც ამ საიტის ნავიგაციაშია გამოყენებული).
  • Form label-ის დაკავშირება — <label for="email"> უწყვილდება <input id="email">-ს (მე-3 გაკვეთილიდან ნაცნობი).
<section id="syllabus">...</section>

<!-- ბმული, რომელიც პირდაპირ ამ სექციაზე ჩაასქროლავს გვერდს -->
<a href="#syllabus">სილაბუსზე გადასვლა</a>

წესი: ID უნდა იყოს უნიკალური მთელ გვერდზე — ერთი და იგივე ID-ს ორ ელემენტზე გამოყენება არასწორია და ბრაუზერის ქცევასაც არაპროგნოზირებადს ხდის (მაგ. getElementById ყოველთვის მხოლოდ პირველ ნაპოვნ შედეგს აბრუნებს).

ვინ „იმარჯვებს" კონფლიქტისას

თუ ერთსა და იმავე ელემენტს ორი სხვადასხვა წესი ეხება ერთი და იმავე თვისებისთვის, ბრაუზერი ირჩევს იმ წესს, რომელსაც მაღალი specificity (სპეციფიკურობა) აქვს: 

/* დაბალი → მაღალი specificity: */
p            { color: black; }   /* Element — ყველაზე დაბალი */
.text        { color: blue; }    /* Class — საშუალო */
#main-text   { color: green; }   /* ID — მაღალი */
/* inline style="color: red" — ყველაზე მაღალი (თავად HTML ელემენტზე) */

/* შედეგად, თუ ყველა ეს წესი ერთ <p>-ს ეხება — ტექსტი იქნება წითელი (ინლაინ სიესეს იმარჯვებს) 
თუ ინლაინ არ არის გამოყენებული მაშინ გაიმარჯვებს ID და ტექსტი იქნება მწვანე და ა.შ. */

სწორედ ამის გამო ID-ს CSS სტილიზებისთვის ხშირად თავს ვარიდებთ — მისი მაღალი specificity მოგვიანებით ართულებს სტილის „გადაფარვას". საუკეთესო პრაქტიკა: გამოიყენე Class სტილიზებისთვის, ID კი — JS/fragment-ბმულების/label-ისთვის.

დასახელების კონვენციები

Class-ის სახელები იწერება kebab-case-ით (card-title, არა cardTitle) — ეს არის CSS-ის სტანდარტი. დიდ პროექტებში ხშირად გამოიყენება BEM მეთოდოლოგია (Block__Element--Modifier), რომელსაც უფრო დეტალურად React მოდულში შევხვდებით: 

/* BEM: block__element--modifier */
.card { }                 /* Block */
.card__title { }          /* Element — card-ის ნაწილი */
.card--featured { }       /* Modifier — card-ის ვარიაცია */

4. Browser Reset და Normalize

სხვადასხვა ბრაუზერს აქვს განსხვავებული ნაგულისხმევი სტილები (ე.წ. User Agent Stylesheet) — Chrome, Firefox და Safari ოდნავ განსხვავებულად „ხედავენ" ერთსა და იმავე HTML-ს, სანამ საკუთარ CSS-ს დავამატებთ. ამის მოსაგვარებლად ორი ძირითადი მიდგომა არსებობს: Reset და Normalize. 

/* მინიმალური, თანამედროვე reset (ეს საიტიც ამ მიდგომას იყენებს) */
*, *::before, *::after {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

img {
  max-width: 100%;
  display: block;
}

Reset აქრობს ყველა ნაგულისხმევ სტილს (margin, padding, font-size სხვადასხვაობა სათაურებზე და ა.შ.) — შედეგად, ყველაფერი თავიდან თავად უნდა დაწერო. ეს არის „სუფთა ფურცელი" მიდგომა.

რა არის Normalize.css და რატომ განსხვავდება Reset-ისგან

Normalize.css არის პატარა, open source CSS ბიბლიოთეკა (ავტორი: Nicolas Gallagher), რომელიც არ „აქრობს" ნაგულისხმევ სტილებს, არამედ ასწორებს კონკრეტულ უთანხმოებებს ბრაუზერებს შორის — ინარჩუნებს იმას, რაც სასარგებლოა, და ასწორებს მხოლოდ იმას, რაც ბრაუზერებში სხვადასხვანაირად მუშაობს. მაგალითად, Normalize.css:

  • ასწორებს <h1>-ის ზომას, როცა ის ჩადგმულია <section>/<article>-ში (ზოგ ბრაუზერში ეს სხვანაირად გამოისახება).
  • უზრუნველყოფს, რომ HTML5-ის სემანტიკური ტეგები (<main>, <details> და სხვ.) სწორად გამოისახოს ძველ ბრაუზერებში, რომლებმაც ეს ტეგები არ იციან.
  • აყალიბებს ფორმის ელემენტების (button, input, select) ფონტს ერთნაირად — ნაგულისხმევად ეს ბრაუზერებში ხშირად სხვადასხვაა.
  • ასწორებს <button>-ის „ფარულ" შიდა padding-ს Firefox-ში, რომელიც სხვა ბრაუზერებში არ არსებობს.
  • აყალიბებს line-height-ს ერთნაირად ყველა ბრაუზერისთვის.

მოკლედ განსხვავება: Reset ამბობს „არაფერი არ მინდა ნაგულისხმევად, ყველაფერს თავად ვწერ". Normalize ამბობს „მინდა გონივრული, ერთნაირი საწყისი წერტილი ყველა ბრაუზერში — შემდეგ მხოლოდ საჭირო ცვლილებებს დავამატებ".

როგორ გამოვიყენოთ Normalize.css

სამი გავრცელებული გზა არსებობს პროექტში Normalize.css-ის დასამატებლად:

<!-- 1. CDN-ით, <head>-ში, საკუთარი style.css-ის წინ -->
<link rel="stylesheet"
      href="https://cdnjs.cloudflare.com/ajax/libs/normalize/8.0.1/normalize.min.css">
<link rel="stylesheet" href="style.css">
# 2. NPM-ით (თუ პროექტს აქვს build-სისტემა, მაგ. Vite — React მოდულში ვნახავთ)
npm install normalize.css
/* 3. style.css-ის თავში, @import-ით (ან პირდაპირ ჩასმული ფაილის შემცველობა) */
@import "normalize.css";

/* ამის შემდეგ იწყება შენი საკუთარი სტილები */
body { font-family: sans-serif; }

თანმიმდევრობა კრიტიკულია: Normalize.css ყოველთვის უნდა ჩაიტვირთოს შენი საკუთარი სტილების წინ — წინააღმდეგ შემთხვევაში მან შეიძლება გადაფაროს შენი განზრახ დაწერილი წესები.

როდის ვირჩევთ რომელს: პატარა, პერსონალურ პროექტში (ან სასწავლო კურსში, ამ საიტის მსგავსად) ხშირად საკმარისია მინიმალური, ხელით დაწერილი reset — სრული კონტროლისთვის. დიდ პროექტში, რომლებიც ბევრ ბრაუზერზე უნდა მუშაობდეს ერთნაირად და დროის დაზოგვა გვჭირდება დეტალების ხელახლა დაწერაზე — Normalize.css ხშირად პრაქტიკულია.

5. CSS Box Model

ყოველი HTML ელემენტი ბრაუზერისთვის არის მართკუთხა „ყუთი" (box), რომელიც შედგება ოთხი ფენისგან, შიგნიდან გარეთ:

  • Content — ტექსტი ან სხვა შემცველობა.
  • Padding — შიდა მანძილი content-სა და ჩარჩოს შორის.
  • Border — ელემენტის ჩარჩო.
  • Margin — გარე მანძილი, სხვა ელემენტებამდე.
.box {
  width: 300px;
  padding: 20px;
  border: 2px solid #146B5C;
  margin: 16px;
}

box-sizing: content-box vs border-box

ნაგულისხმევად (content-box), width/height ეხება მხოლოდ content-ს — padding და border ემატება ჯამურ ზომას. ეს ხშირად დაუგეგმავ განლაგებას იწვევს. ამიტომ თანამედროვე პროექტებში თითქმის ყოველთვის ვიყენებთ border-box-ს, სადაც width უკვე მოიცავს padding-ისა და border-ის ზომას: 

/* border-box — ყუთის ჯამური სიგანე ყოველთვის 300px-ია */
* {
  box-sizing: border-box;
}

.box {
  width: 300px;
  padding: 20px;
  border: 2px solid black;
  /* content-ის ნამდვილი სიგანე გამოითვლება ავტომატურად */
}

გაიმეორე — შეკითხვები

  1. რა განსხვავებაა <div>-სა და <section>-ს შორის — რომელ კითხვას დაუსვამდი საკუთარ თავს, რომ ერთ-ერთი აირჩიო?
  2. რატომ შეიძლება <main> გვერდზე მხოლოდ ერთხელ გამოჩნდეს?
  3. რა შემთხვევაში აირჩევდი Class-ს და რა შემთხვევაში — ID-ს?
  4. რომელი გაიმარჯვებს, თუ ერთსა და იმავე ელემენტს .title და #main-title ორივე ანიჭებს ფერს? რატომ?
  5. რა განსხვავებაა Reset-სა და Normalize.css-ს შორის — რომელი „შლის" და რომელი „ასწორებს"?
  6. რატომ არის მნიშვნელოვანი, რომ Normalize.css საკუთარ style.css-ზე ადრე ჩაიტვირთოს?

პრაქტიკული დავალებები

  1. დაუკავშირე გარეგანი style.css ერთ HTML გვერდს <link> ტეგით.
  2. ააწყვე გვერდის საბაზისო ჩონჩხი <header>, <main> (ერთი <section>-ით შიგნით) და <footer>-ის გამოყენებით.
  3. დაამატე ერთ ბლოკს ორი Class ერთდროულად (მაგ. class="card featured") და დაწერე სამი CSS წესი — ერთი თითოეული class-ისთვის ცალკე, და ერთი — ორივესთვის ერთად (.card.featured).
  4. დაწერე Element, Class და ID სელექტორები ერთსა და იმავე გვერდზე — თითოეული განსხვავებულ ელემენტს ასტილებდეს — და ერთ ელემენტზე შეგნებულად შექმენი specificity კონფლიქტი (class და id ერთსა და იმავე თვისებაზე), დააკვირდი DevTools-ის Elements → Styles ტაბში, რომელი წესია გადახაზული.
  5. დაამატე მინიმალური reset ბლოკი შენს პროექტში და DevTools-ის Elements ტაბში დააკვირდი, რა შეიცვალა.
  6. დაუკავშირე Normalize.css CDN-ით (საკუთარი style.css-ის წინ) და შეადარე გვერდის გარეგნობა — რა შეიცვალა სათაურებში, ღილაკებში, ფორმის ველებში?
  7. შექმენი ყუთი განსაზღვრული width, padding, border და margin-ით.
  8. (რთული) ერთი და იმავე ელემენტისთვის შეადარე ზომა content-box-სა და border-box-ს შორის — გაზომე DevTools-ის Elements → Computed ტაბში.
