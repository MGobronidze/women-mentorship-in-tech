1. რა არის React და SPA კონცეფცია

React — რა არის და რატომ არსებობს

React არის JavaScript ბიბლიოთეკა (შექმნილია Meta-ში, 2013 წელს გამოქვეყნდა open source-ად) მომხმარებლის ინტერფეისის (UI) ასაგებად. მისი მთავარი იდეა: ინტერფეისი აიწყოს პატარა, ხელახლა გამოსაყენებელი „ბლოკებისგან“ — კომპონენტებისგან, რომლებიც საკუთარ მდგომარეობას (state) მართავენ.

ჩვენ აქამდე ვიყენებდით იმპერატიულ მიდგომას: JavaScript-ში ბრძანებებით ვეუბნებოდით ბრაუზერს, როგორ შეეცვალა DOM (querySelector, createElement, textContent = ...). React-ში გამოიყენება დეკლარაციული მიდგომა: აღვწერთ, როგორ უნდა გამოიყურებოდეს UI მოცემული მონაცემებისთვის, დანარჩენს (რა უნდა შეიცვალოს DOM-ში) React თვითონ გაარკვევს.

იმპერატიული (Vanilla JS)დეკლარაციული (React)
„იპოვე ელემენტი, შეცვალე ტექსტი, დაამატე კლასი, წაშალე შვილობილი...“ „თუ count არის 5, UI ასე გამოიყურება“
DOM-ს ხელით ვმართავთ, ადვილია სინქრონიზაციის შეცდომები UI ყოველთვის არის მონაცემების ფუნქცია: UI = f(state)

React-ის ძირითადი პრინციპები

  • კომპონენტებზე დაფუძნებულობა — გვერდი იყოფა დამოუკიდებელ ნაწილებად (Header, Card, Button...), რომლებიც ერთმანეთში ჩაიდგმება.
  • ცალმხრივი მონაცემთა ნაკადი — მონაცემები მშობელი კომპონენტიდან შვილისკენ მიედინება props-ების საშუალებით (შემდეგ გაკვეთილებზე დეტალურად).
  • Virtual DOM და reconciliation — React ინახავს UI-ის მსუბუქ აღწერას მეხსიერებაში, ცვლილებისას ადარებს ძველ და ახალ აღწერას და რეალურ DOM-ში მხოლოდ საჭირო ნაწილს ცვლის.
  • „Learn once, write anywhere“ — იგივე მიდგომა მუშაობს ვებზე (React DOM), მობილურზე (React Native) და სერვერზეც (Server Components).

SPA — Single Page Application

SPA (Single Page Application) არის აპლიკაცია, რომელიც ერთხელ იტვირთება ერთ HTML ფაილად, ხოლო შემდეგი „გვერდები“ და ცვლილებები JavaScript-ით, სრული გვერდის ხელახლა ჩატვირთვის გარეშე ჩნდება. განსხვავებით ჩვენი, „მრავალგვერდიანი“ (MPA, Multi-Page Application) საიტისგან, სადაც ყოველი lessonX.html ცალკე ფაილია და ბმულზე დაჭერა ბრაუზერს ახალ გვერდს ატვირთვინებს.

MPA (ჩვენი კურსის საიტი)SPA (React + Vite)
ნავიგაციაყოველი ბმული — სრული გვერდის ჩატვირთვაბრაუზერი არ იტვირთება; JS ცვლის შიგთავსს
შეგრძნებაკლასიკური ვებ-საიტიახლოს არის დესკტოპ/მობილურ აპლიკაციასთან
პირველი ჩატვირთვასწრაფია — HTML უკვე მზადააშეიძლება ნელი იყოს — ჯერ JS უნდა ჩაიტვირთოს და შეასრულოს
SEOმარტივია — შიგთავსი HTML-შიაუფრო რთულია — საწყისი HTML თითქმის ცარიელია
საუკეთესოაბლოგი, საინფორმაციო საიტი, მარტივი ვიტრინადაფები (dashboard), ადმინ-პანელი, ჩატი, task-manager, რედაქტორი

კლიენტ-მხარის რუტინგი

SPA-ში URL-ის შეცვლა ხდება JavaScript-ით (History API), ხოლო „რომელი გვერდი ვაჩვენოთ“ — რუტერი წყვეტს. პრაქტიკაში ამისთვის იყენებენ ბიბლიოთეკას (მაგ. React Router) — ამას ბოლო მოდულის შემდეგ გაკვეთილებზე შევხვდებით.

მნიშვნელოვანი კონტექსტი: SPA არ არის ერთადერთი გზა

2025 წლის თებერვალში React-ის გუნდმა ოფიციალურად გააუქმა Create React App (CRA) ახალი პროექტებისთვის (ის დიდი ხანია აღარ არის აქტიურად მხარდაჭერილი). თუ ძველ ტუტორიალში ნახავთ npx create-react-app — ეს მოძველებული გზაა. React-ის გუნდის რეკომენდაცია: რეალური, production აპლიკაციებისთვის გამოიყენეთ ფრეიმვორქი (მაგ. Next.js, React Router framework mode, Expo მობილურისთვის), რომელიც რუტინგს, მონაცემთა მიღებას, კოდის დაყოფას და SEO-ს უკვე ამოხსნილს გაძლევთ. მაგრამ სწავლისთვის და მცირე პროექტებისთვის Vite + React — პირდაპირი, გამჭვირვალე და უმარტივესი გზაა, რადგან ხედავთ, როგორ მუშაობს ყველაფერი „კედლის უკან“. სწორედ ამიტომ ვიწყებთ მისით.

2. React გარემოს შექმნა Vite-ის გამოყენებით

Vite (ფრანგ. „სწრაფი“, წარმოითქმის „ვით“) არის თანამედროვე build tool და development სერვერი. ის ორ რამეს აკეთებს: (1) development-ის დროს მყისიერად უშვებს პროექტს და ცვლილებებს ბრაუზერში ავტომატურად აჩვენებს (HMR — Hot Module Replacement, გვერდის სრული გადატვირთვის გარეშე); (2) production-ისთვის აგებს ოპტიმიზებულ, შეკუმშულ ფაილებს (build).

წინაპირობები

  • Node.js 20.19+ ან 22.12+ (Vite 8-ის მოთხოვნა; ძველი Node 18 აღარ ეყოფა). შეამოწმე: node -v
  • npm (Node-თან ერთად დგება): npm -v. ალტერნატივები: pnpm, yarn, bun.
  • კოდის რედაქტორი (VS Code) და ბრაუზერი.

პროექტის შექმნა და გაშვება

# ახალი React + Vite პროექტის შექმნა (JavaScript)
npm create vite@latest my-react-app -- --template react

# ან TypeScript-ით (რეკომენდებულია კურსის შემდეგ ეტაპზე)
npm create vite@latest my-react-app -- --template react-ts

# პროექტში შესვლა და დამოკიდებულებების დაყენება
cd my-react-app
npm install

# development სერვერის გაშვება (ჩვეულებრივ http://localhost:5173)
npm run dev

-- ორმაგი ტირე აუცილებელია: ის --template react-ს Vite-ის დამგენერირებელ ხელსაწყომდე აწვდის (npm 7+). შეგიძლია ბრძანება უპარამეტროდაც გაუშვა — npm create vite@latest — და ინტერაქტიულად აირჩიო ფრეიმვორქი (React) და ვარიანტი (JavaScript / TypeScript). ახალი ვერსიები შეიძლება დამატებით გკითხონ, გინდა თუ არა რომელიმე ექსპერიმენტული ოპცია (მაგ. rolldown-vite), ან დაუყოვნებლივ გაუშვან npm install

3. JSX — HTML-ის მსგავსი სინტაქსი JavaScript-ში

JSX (JavaScript XML) საშუალებას გვაძლევს, HTML-ის მსგავსი სინტაქსი პირდაპირ JavaScript ფაილში დავწეროთ. ის არ არის არც სტრიქონი, არც HTML — ეს არის JavaScript-ის სინტაქსური გაფართოება, რომელიც build-ის დროს ჩვეულებრივ JS-ად გარდაიქმნება. 

// JSX მაგალითი
const element = <h1 className="title">გამარჯობა, React!</h1>;

ეს არ არის ნამდვილი HTML — ბრაუზერი მას პირდაპირ ვერ გაიგებს. build-ის ეტაპზე (Oxc ან Babel) JSX გარდაიქმნება ჩვეულებრივ JavaScript ფუნქციის გამოძახებად.

react.createElement — რაშიც JSX „კულისებში“ გარდაიქმნება

// JSX (რასაც ვწერთ)
const element = <h1 className="title">გამარჯობა, React!</h1>;

// React.createElement — ხელით დაწერილი ექვივალენტი
const element = React.createElement(
  "h1",                       // 1. ტიპი: HTML ტეგის სახელი, ან კომპონენტი
  { className: "title" },     // 2. props (ატრიბუტები), ან null
  "გამარჯობა, React!"          // 3+. შვილები (children)
);

createElement ქმნის ჩვეულებრივ JavaScript ობიექტს — React element-ს, რომელიც UI-ის „აღწერილობაა“ (არ არის ნამდვილი DOM ელემენტი!). გამარტივებით ასე გამოიყურება: 

// console.log(element) დაახლოებით ამას დაგანახებს:
{
  type: "h1",
  props: { className: "title", children: "გამარჯობა, React!" },
  key: null,
  // ... React-ის შიდა ველები
}

React ამ ობიექტების ხეს აგროვებს, ადარებს წინა ხეს და მხოლოდ საჭირო ცვლილებებს ახორციელებს რეალურ DOM-ში. ჩადგმული ელემენტების შემთხვევაში createElement ბუდობრივად იწერება: 

// JSX
<div className="card">
  <h2>ლანა</h2>
  <p>Front-end სტუდენტი</p>
</div>

// იგივე createElement-ით — ხედავ, რატომ ვწერთ JSX-ს
React.createElement(
  "div",
  { className: "card" },
  React.createElement("h2", null, "ლანა"),
  React.createElement("p", null, "Front-end სტუდენტი")
);

JSX-ის წესები და შესაძლებლობები

  • ერთი root ელემენტი. კომპონენტმა უნდა დააბრუნოს ერთი ძირითადი ელემენტი, ან fragment: <>...</> (არ ამატებს ზედმეტ <div>-ს DOM-ში).
  • ყველა ტეგი უნდა დაიხუროს. HTML-ში <img> ან <br> ისედაც მუშაობს, JSX-ში აუცილებელია <img />, <br />, <input />.
  • camelCase ატრიბუტები. class → className (რადგან class JS-ის დაცული სიტყვაა), for → htmlFor, onclick → onClick, tabindex → tabIndex.
  • JS გამოსახულება ფიგურული ფრჩხილებით: {studentName}, {2 + 2}, {user.name.toUpperCase()}. ფრჩხილებში გამოსახულება (expression) დაიშვება, ოპერატორი (if, for) — არა.
  • ატრიბუტში JS ან სტრიქონი: src="a.png" (სტრიქონი), src={imageUrl} (ცვლადი). ორივე ერთდროულად არ შეიძლება: src="{x}" გამოვა სიტყვასიტყვითი ტექსტი.
  • inline style — ობიექტია: style={{ backgroundColor: "teal", fontSize: 18 }} (გარე ფრჩხილები — JSX-ის, შიდა — JS ობიექტის; თვისებები camelCase).
  • კომენტარი JSX-ში: {/* ასე */}.
  • უსაფრთხოება: JSX-ში ჩასმული მნიშვნელობები ავტომატურად ექრანირდება, ამიტომ მომხმარებლის ტექსტი თავისით ვერ გადაიქცევა HTML/სკრიპტად (დაცვა XSS-ისგან). ზუსტად ამ დაცვას ეუბნებიან მიზანმიმართულად გამორთვას, როცა იყენებენ ისეთ API-ს, რომლის სახელშიც სიტყვა „dangerously“ წერია.

4. ფუნქციური კომპონენტები

დღეს React-ის კომპონენტები თითქმის ყოველთვის იწერება ჩვეულებრივ JavaScript ფუნქციად, რომელიც აბრუნებს JSX-ს. (ძველი კლასზე დაფუძნებული კომპონენტები ჯერ კიდევ მუშაობს და ძველ კოდში შეგხვდება, მაგრამ ახალ კოდში მათ აღარ ვწერთ.) 

function Welcome() {
  const studentName = "ლანა";

  return (
    <div className="welcome">
      <h1>გამარჯობა, {studentName}!</h1>    {/* {} ჩასვამს JS ცვლადს JSX-ში */}
      <p>კეთილი იყოს შენი დაბრუნება React-ის სამყაროში.</p>
    </div>
  );
}

export default Welcome;

კომპონენტის სახელი ყოველთვის იწყება დიდი ასოთი (Welcome, არა welcome) — ეს არის React-ის წესი, რომლითაც ის ცნობს, კომპონენტს იყენებ თუ ჩვეულებრივ HTML ტეგს: <div> → ჩაშენებული ტეგი, <Welcome /> → შენი კომპონენტი.

Props — კომპონენტის „პარამეტრები“

კომპონენტი ერთი და იგივე რჩება, მაგრამ სხვადასხვა მონაცემით შეგვიძლია გამოვიძახოთ. მონაცემები გადაეცემა props-ით (properties) — ატრიბუტების სახით; ფუნქცია კი მათ პირველ არგუმენტად იღებს ობიექტის სახით. ყველაზე ხშირად ობიექტს დაუყოვნებლივ ვშლით (destructuring): 

// Greeting.jsx
function Greeting({ name, role = "სტუდენტი" }) {   // role-ს აქვს ნაგულისხმევი მნიშვნელობა
  return <p>გამარჯობა, {name}! შენ ხარ {role}.</p>;
}

// გამოყენება:
<Greeting name="ლანა" />
<Greeting name="ნათია" role="მენტორი" />
  • props-ები მხოლოდ წასაკითხია — კომპონენტი საკუთარ props-ს არ ცვლის.
  • სტრიქონი გადაეცემა ბრჭყალებით (name="ლანა"), სხვა ყველაფერი — ფიგურული ფრჩხილებით (age={25}, skills={["HTML","CSS"]}, onClick={handle}).

პირობითი რენდერი და სიების გამოტანა

JSX-ში if ბლოკს პირდაპირ ვერ ჩავსვამთ, ამიტომ გამოიყენება JS გამოსახულებები: სამადგილიანი ოპერატორი (? :), && და .map(): 

function Profile() {
  const isOnline = true;
  const skills = ["HTML", "CSS", "JavaScript", "React"];

  return (
    <section>
      <p>{isOnline ? "🟢 ონლაინ" : "⚪ ოფლაინ"}</p>

      {isOnline && <button>message</button>}

      <ul>
        {skills.map((skill) => (
          <li key={skill}>{skill}</li>
        ))}
      </ul>
    </section>
  );
}

key — აუცილებელი ატრიბუტი სიებში

სიის თითოეულ ელემენტს უნდა ჰქონდეს უნიკალური და სტაბილური key (იდეალურად — მონაცემის id). ის React-ს ეხმარება გაიგოს, რომელი ელემენტი დაემატა, წაიშალა ან გადაადგილდა. მასივის ინდექსის გამოყენება key-დ მხოლოდ იმ შემთხვევაშია დასაშვები, თუ სია არასოდეს ცვლის რიგს და არ იშლება/ემატება. &&-ის გამოყენებისას გაუფრთხილდი რიცხვებს: {0 && ...} ეკრანზე „0“-ს გამოსახავს.

კომპონენტის „სისუფთავე“ (pure components)

კარგი React კომპონენტი ისევე იქცევა, როგორც წმინდა ფუნქცია: ერთი და იგივე შესატანისთვის (props, state) ყოველთვის ერთსა და იმავე JSX-ს აბრუნებს და რენდერის დროს გარეთ არაფერს ცვლის (არ ცვლის გლობალურ ცვლადებს, არ აგზავნის მოთხოვნას, არ ცვლის DOM-ს ხელით). გვერდითი ეფექტებისთვის არსებობს event handler-ები და useEffect — ამას შემდეგ გაკვეთილებზე გავივლით.

ფაილების ორგანიზება

  • ერთი კომპონენტი — ერთი ფაილი, ფაილის სახელი = კომპონენტის სახელი (ProjectCard.jsx).
  • export default — ერთი მთავარი ექსპორტი; import ProjectCard from "./ProjectCard".
  • Vite-ში JSX შემცველი ფაილის გაფართოება .jsx (ან .tsx) უნდა იყოს, არა .js.
  • React 19-ში კომპონენტის სახელი და გაფართოება — აუცილებლად დიდი ასოთი და .jsx, ხოლო მონაცემთა ფაილები (მაგ. data.js) JSX-ს არ შეიცავს.

5. კომპონენტების მენეჯმენტი და რენდერი

კომპონენტები „ერთვის“ ერთმანეთს, ისევე როგორც ჩვეულებრივი HTML ტეგები — ერთი კომპონენტი შეიძლება მეორეს „შიგნით“ გამოვიძახოთ. შედეგად ვიღებთ კომპონენტების ხეს, სადაც ზედა კომპონენტი (App) მშობელია, ქვედები — შვილები. 

// App.jsx
import Welcome from "./Welcome";

function App() {
  return (
    <div className="app">
      <Welcome />                    {/* კომპონენტის გამოძახება, tag-ის სახით */}
      <p>სხვა შემცველობა...</p>
    </div>
  );
}

export default App;
// main.jsx — "root"-ის შექმნა და მთელი აპლიკაციის რენდერი DOM-ში
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App";
import "./index.css";

const root = createRoot(document.getElementById("root"));
root.render(
  <StrictMode>
    <App />
  </StrictMode>
);

createRoot + render არის ის „ხიდი“, სადაც React პირველად ეხება ნამდვილ DOM-ს — index.html ფაილში აუცილებელია ერთი ცარიელი <div id="root"></div>, სადაც React-ი მთელ აპლიკაციას ჩააშენებს.

რა არის <StrictMode>

StrictMode მხოლოდ development-ში მუშაობს და დამატებით შემოწმებებს ამატებს: კომპონენტს ორჯერ არენდერებს და ეფექტებს ორჯერ უშვებს, რომ გამოაჩინოს "ხარვეზიანი" კოდი და ამოუხსნელი შეცდომები. თუ console.log-ს ორჯერ ხედავ — ეს ნორმალურია და production-ში აღარ მოხდება. ნუ ამოიღებ StrictMode-ს ამ მიზეზით.

როგორ „ფიქრობს“ React: ტრიგერი → რენდერი → commit

  1. ტრიგერი — პირველადი რენდერი (root.render) ან state-ის ცვლილება.
  2. რენდერი — React ეძახის შენს კომპონენტებს (ფუნქციებს) და იღებს ახალ React element-ების ხეს.
  3. Commit — React ადარებს ახალ და ძველ ხეს და რეალურ DOM-ს მხოლოდ იმ ადგილებში ცვლის, სადაც სხვაობაა.

React DevTools

დააინსტალირე ბრაუზერის გაფართოება React Developer Tools (Chrome / Firefox / Edge). გამოჩნდება ორი ახალი ჩანართი: Components (კომპონენტების ხე, props და state რეალურ დროში) და Profiler (რენდერის ანალიზი). ეს არის ძირითადი ხელსაწყო დებაგისთვის.

6. ყველაზე ხშირი შეცდომები დამწყებებისთვის

შეცდომასიმპტომიგამოსწორება
კომპონენტის სახელი პატარა ასოთი (function welcome()) React მას HTML ტეგად მიიჩნევს; <welcome /> არაფერს აჩვენებს ყოველთვის დიდი ასო: Welcome
class="..." className-ის ნაცვლად კონსოლში გაფრთხილება, სტილი შეიძლება არ გამოჩნდეს className, htmlFor, onClick
ორი ძირეული ელემენტი დაბრუნებულია შეცდომა: „Adjacent JSX elements must be wrapped“ გარშემო <div> ან <>...</>
ტეგი არ არის დახურული (<img>, <input>) კომპილაციის შეცდომა <img />, <input />
სიაში key-ის გარეშე გაფრთხილება „Each child in a list should have a unique key“ key={item.id}
JSX ფაილი .js გაფართოებით Vite-ის შეცდომა JSX სინტაქსზე გადაარქვი .jsx
ობიექტის პირდაპირ ჩასმა {user}-ში „Objects are not valid as a React child“ გამოიტანე კონკრეტული ველი: {user.name}
კომპონენტის გამოძახება ფუნქციად: {Welcome()} ბაგები მოგვიანებით, როცა კომპონენტი სარგებლობს hooks-ით JSX-ით: <Welcome />

7. რეალური პროექტი: პორტფოლიოს გვერდი React-ში

ახლა ყველაფერს გავაერთიანებთ ერთ პრაქტიკულ პროექტში: ავაწყობთ პირად პორტფოლიოს გვერდს კომპონენტებისგან. პროექტი ზუსტად ამ გაკვეთილის თემებს ეყრდნობა — Vite, JSX, ფუნქციური კომპონენტები, props, children, სიები .map()-ით და createRoot — და საჭირო არაა state ან hooks. ბოლოს დასრულებულ პროექტს გამოაქვეყნებ GitHub Pages-ზე.

8. თვითშემოწმება

1. რით განსხვავდება SPA MPA-სგან?

SPA ერთხელ იტვირთება ერთ HTML ფაილად, შემდეგ JavaScript დინამიურად ცვლის შიგთავსს გვერდის სრული გადატვირთვის გარეშე. MPA-ში ყოველი ბმული ახალ HTML გვერდს ტვირთავს.

2. რატომ არ გამოიყენება ახალ პროექტებში Create React App?

2025 წლის თებერვალში React-ის გუნდმა ის ახალი პროექტებისთვის გააუქმა — მას აქტიური მომვლელები აღარ ჰყავდა. ალტერნატივები: ფრეიმვორქი (Next.js, React Router და სხვ.) ან build tool, მაგალითად Vite.

3. რა მინიმალური ვერსიის Node.js გჭირდება Vite 8-ისთვის?

Node.js 20.19+ ან 22.12+.

4. რა ხდება JSX-თან build-ის დროს და ვინ აკეთებს ამას Vite 8-ში?

JSX გარდაიქმნება ჩვეულებრივ JavaScript-ად (jsx() გამოძახებად react/jsx-runtime-იდან ან ძველ სტილში — React.createElement-ად). Vite 8-ში ამას ასრულებს Oxc, არა Babel; Babel საჭიროა მხოლოდ დამატებით პლაგინებისთვის (მაგ. React Compiler).

5. რატომ არის className და არა class?

class JavaScript-ის დაცული სიტყვაა, JSX კი JavaScript-ში იწერება.

6. რას აკეთებს createRoot(...).render(<App />)?

ქმნის React root-ს index.html-ის #root ელემენტზე და იქ ამონტაჟებს მთელ აპლიკაციას — ეს არის წერტილი, სადაც React პირველად ეხება რეალურ DOM-ს.

7. რატომ იწყება კომპონენტის სახელი დიდი ასოთი?

ასე React არჩევს, რომ <Welcome /> არის კომპონენტი, ხოლო <div> — ჩვეულებრივი HTML ტეგი.

8. რისთვის არის key სიებში?

ეხმარება React-ს ზუსტად გაიგოს, რომელი ელემენტი დაემატა, წაიშალა ან გადაადგილდა; უნდა იყოს უნიკალური და სტაბილური (ჩვეულებრივ id).

  3. შექმენი ახალი ფაილი Greeting.jsx ერთი მარტივი ფუნქციური კომპონენტით და import-ის გამოყენებით ჩასვი ის App.jsx-ში. გამოიძახე ის სამჯერ, სხვადასხვა name prop-ით.
  4. დაწერე JSX ელემენტი, რომელშიც ჩასმულია JS ცვლადი ({}-ის გამოყენებით) და JS გამოსახულება (მაგ. {2 + 2}).
