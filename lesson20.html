OOP, Prototype, Classes, Storage & Cookies

ობიექტზე ორიენტირებული პროგრამირების საფუძვლები, ბრაუზერში მონაცემების შენახვის გზები და საბოლოოდ — რეალური To-Do აპლიკაცია, რომელშიც 1–20 გაკვეთილის ცოდნა ერთიანდება.

1. Constructor Function

Constructor function არის „ქარხანა", საიდანაც ერთი „ფორმის" ბევრი ობიექტის შექმნა შეიძლება. Convention: სახელი იწყება დიდი ასოთი, გამოიძახება new-ით. 

function Student(name, age) {
  this.name = name;
  this.age = age;
}

const student1 = new Student("ნატა", 22);
const student2 = new Student("გიორგი", 24);
console.log(student1.name); // "ნატა"

რას აკეთებს new სინამდვილეში?

  1. ქმნის ცარიელ ობიექტს {};
  2. აკავშირებს მას Student.prototype-თან (ობიექტის შიდა [[Prototype]]);
  3. ასრულებს ფუნქციას, სადაც this = ახალი ობიექტი;
  4. აბრუნებს ამ ობიექტს (გარდა იმ შემთხვევისა, როცა constructor თავად აბრუნებს სხვა ობიექტს).
ხშირი შეცდომა: new-ის დავიწყება. ჩვეულებრივი ფუნქციის რეჟიმში this ან undefined იქნება (strict mode), ან — გლობალური ობიექტი. თავის დასაცავად: 
function Student(name) {
  if (!new.target) {                     // new.target === undefined, თუ new-ის გარეშე გამოიძახეს
    throw new TypeError("გამოიყენე new Student(...)");
  }
  this.name = name;
}

// ინსტანციიდან მისი "ქარხნის" გასაგებად:
console.log(student1.constructor === Student); // true
ისტორია: ჩაშენებული ტიპებიც იგივე მექანიზმია — new Date(), new Map(), new Error(). იგივე ლოგიკა გამოიყენება class-შიც.

2. Prototype და მემკვიდრეობითობა

ყველა ობიექტს აქვს „ფარული" კავშირი სხვა ობიექტთან — prototype-თან. როცა თვისებას ვეძებთ და ობიექტში ვერ ვპოულობთ, JS მიყვება ამ კავშირს ზევით, სანამ null-ს არ მიაღწევს — ამას ჰქვია prototype chain. 

student1  ──►  Student.prototype  ──►  Object.prototype  ──►  null
 (name, age)     (introduce)           (toString, hasOwnProperty...)

საერთო მეთოდები prototype-ზე დადე (და არა constructor-ში): ასე ყველა instance ერთ ფუნქციას იზიარებს და მეხსიერება არ იხარჯება თითოეულ ობიექტზე ცალ-ცალკე ასლისთვის. 

Student.prototype.introduce = function () {
  return `გამარჯობა, მე ვარ ${this.name}`;
};

console.log(student1.introduce());                         // "გამარჯობა, მე ვარ მატა"
console.log(student1.introduce === student2.introduce);    // true — იგივე ფუნქცია

prototype-ის შესამოწმებელი ხელსაწყოები

Object.getPrototypeOf(student1) === Student.prototype; // true (სწორი, თანამედროვე გზა)
student1.__proto__ === Student.prototype;              // true, მაგრამ __proto__ მხოლოდ დებაგისთვის

Object.hasOwn(student1, "name");        // true  — საკუთარი თვისება
Object.hasOwn(student1, "introduce");   // false — მემკვიდრეობით მიღებული
"introduce" in student1;                // true  — ჯაჭვშიც ეძებს

student1.name = "ნინო";                 // shadowing: ჩაწერა ყოველთვის ობიექტზეა და არა prototype-ზე
for...in gotcha: for (const k in student1) გამოიტანს prototype-ზე ხელით მიმატებულ (enumerable) მეთოდებსაც. ამიტომ გამოიყენე Object.keys(obj) / Object.entries(obj) — ისინი მხოლოდ საკუთარ თვისებებს აბრუნებენ.

მემკვიდრეობა prototype-ით (როგორ ხდებოდა class-მდე)

function GraduateStudent(name, age, thesis) {
  Student.call(this, name, age);          // მშობლის constructor — call (გაკვეთილი 17)
  this.thesis = thesis;
}
GraduateStudent.prototype = Object.create(Student.prototype);
GraduateStudent.prototype.constructor = GraduateStudent;

// Object.create — ობიექტი პირდაპირ კონკრეტული prototype-ით:
const animal = { speak() { return `${this.name} გამოსცემს ხმას`; } };
const dog = Object.create(animal, { name: { value: "ბობი", enumerable: true } });
dog.speak();

// სუფთა "ლექსიკონი" prototype-ის გარეშე:
const dict = Object.create(null);       // არ აქვს toString, hasOwnProperty და ა.შ.
უსაფრთხოება (Prototype Pollution): თუ უცხო ობიექტებს (მაგ. JSON-იდან) ბრმად აერთიანებ საკუთარ ობიექტში, გასაღებმა "__proto__" შეიძლება Object.prototype შეცვალოს. არასდროს დააკოპირო user-ის ობიექტი key-ების შემოწმების გარეშე; ლექსიკონად გამოიყენე Map ან Object.create(null).

3. Class-ები — თანამედროვე სინტაქსი

ES6-ის class იგივე prototype-მექანიზმია, უფრო წასაკითხავი ფორმით („syntactic sugar"), მაგრამ რამდენიმე დამატებითი წესით:

  • class-ის გამოძახება new-ის გარეშე — TypeError;
  • class-ის სხეული ყოველთვის strict mode-ში მუშაობს;
  • class ცვლადივით იმალება TDZ-ში (let-ის მსგავსად) — გამოაცხადე გამოყენებამდე;
  • class-ის მეთოდები non-enumerable-ია — for...in მათ არ აჩვენებს.
class Student {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  introduce() {                            // prototype-ზე ჩავარდება
    return `გამარჯობა, მე ვარ ${this.name}`;
  }
}

Class fields და private (#) თვისებები

თვისებები შეიძლება პირდაპირ class-ის სხეულში გამოვაცხადოთ. #-ით დაწყებული თვისება ნამდვილად private-ია: მის წაკითხვას class-ის გარეთ ენა თავად კრძალავს (ეს „_" კონვენციისგან განსხვავდება, რომელიც მხოლოდ შეთანხმებაა). 

class BankAccount {
  #balance = 0;                            // private field
  owner;                                   // public field

  constructor(owner, initial = 0) {
    this.owner = owner;
    this.#deposit(initial);
  }

  #deposit(sum) {                          // private მეთოდი
    if (sum < 0) throw new RangeError("თანხა უარყოფითი ვერ იქნება");
    this.#balance += sum;
  }

  add(sum) { this.#deposit(sum); return this; }   // return this → chaining
  get balance() { return this.#balance; }

  static isAccount(obj) { return #balance in obj; }  // brand check (ES2022)
}

const acc = new BankAccount("ნატა", 100).add(50);
console.log(acc.balance);                  // 150
// console.log(acc.#balance);              // ❌ SyntaxError — გარედან მიუწვდომელია
გაითვალისწინე: ქვეკლასი მშობლის #ველს ვერ წაიკითხავს (SyntaxError) — მშობლის public getter-ს უნდა გამოიყენოს. კერძო ველები და public class fields თანამედროვე ბრაუზერებში „Baseline"-ია, ამიტომ უპრობლემოდ გამოიყენება.
ხაფანგი: JSON.stringify არ ხედავს კერძო ველებს. იგი მხოლოდ საკუთარ public თვისებებს აგროვებს: #balance და prototype-ზე მდგომარე getter JSON-ში არ მოხვდება — localStorage-ში შენახვისას მონაცემი უჩუმრად დაიკარგებოდა. გამოსავალი — toJSON() მეთოდი (იხ. პროექტი, Task კლასი).

4. Setters & Getters

Getter/setter გვაძლევს კონტროლს, როგორ იკითხება/იწერება თვისება: ვალიდაცია, გამოთვლადი მნიშვნელობა, read-only თვისება. გარედან ჩვეულებრივი თვისებასავით გამოიყურება (ფრჩხილების გარეშე). 

class Student {
  #age;

  constructor(name, age) {
    this.name = name;
    this.age = age;                        // საწყისი მნიშვნელობაც setter-ით გაივლის ვალიდაციას
  }

  get age() { return this.#age; }

  set age(value) {
    if (!Number.isFinite(value) || value < 0) {
      throw new RangeError("ასაკი უნდა იყოს არაუარყოფითი რიცხვი");
    }
    this.#age = value;
  }

  get isAdult() { return this.#age >= 18; }   // მხოლოდ getter → read-only
}

const s = new Student("ნატა", 22);
console.log(s.age);        // 22 — getter
s.age = 23;                // setter
console.log(s.isAdult);    // true
s.age = -5;                // ❌ RangeError
დაუშვებელია: set age(v) { this.age = v; } — უსასრულო რეკურსია, რადგან this.age = ... ისევ setter-ს იძახებს. ამიტომ ვიყენებთ სხვა სახელს (_age) ან private #age-ს.

5. instanceof ოპერატორი

ამოწმებს, არის თუ არა Constructor.prototype ობიექტის prototype chain-ში:

// 1. ვქმნით მშობელ კლასს
class Student {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
}

// 2. ვქმნით შვილობილ კლასს, რომელიც მემკვიდრეობით იღებს Student-ს
class GraduateStudent extends Student {
  constructor(name, age, thesisTopic) {
    super(name, age); // აუცილებლად ვუძახებთ მშობლის კონსტრუქტორს
    this.thesisTopic = thesisTopic;
  }
}

const grad = new GraduateStudent("ჯონი", 27, "Front-end განათლება");

console.log(grad instanceof GraduateStudent); // true (რადგან ამ კლასის ინსტანციაა)
console.log(grad instanceof Student);         // true (მემკვიდრეობის გამო — GraduateStudent extends Student)
console.log(grad instanceof Object);          // true (JavaScript-ში ყველა ობიექტი და კლასი Object-ის შვილია)
console.log(grad instanceof Array);           // false (არანაირი კავშირი არ აქვს მასივთან)

6. მონაცემების შენახვა ბრაუზერში

Web Storage: localStorage და sessionStorage

  • ინახავს მხოლოდ სტრიქონებს (key → string);
  • ლიმიტი დაახლოებით 5 MiB ორიგინზე (origin = პროტოკოლი + დომენი + პორტი);
  • მონაცემი არ იგზავნება სერვერზე;
  • localStorage რჩება ბრაუზერის დახურვის შემდეგაც; sessionStorage — მხოლოდ ერთი ტაბის სიცოცხლით;
  • API სინქრონულია: დიდი მონაცემი მთავარ thread-ს ბლოკავს.

    • (რა საფრთხეა: თუ შენ შეეცდები localStorage-ში დიდი მოცულობის ტექსტის (მაგ. 4-5 მეგაბაიტიანი ფაილის) ჩაწერას, მყარ დისკზე ჩაწერის პროცესის დასრულებამდე ბრაუზერი „გაიყინება“ (Main Thread დაიბლოკება). ამ დროს ვებსაიტი დროებით შეწყვეტს რეაგირებას კლიკებზე, ღილაკები არ იმოძრავებს და ანიმაციები შეჩერდება.

    რჩევა: ამიტომ localStorage-ში ინახავენ მხოლოდ პატარა ზომის მონაცემებს (ტოკენები, პარამეტრები, მომხმარებლის სახელი), ხოლო დიდი მონაცემებისთვის იყენებენ ბრაუზერის სხვა, ასინქრონულ ბაზებს (მაგალითად, IndexedDB-ს).)

ბრაუზერის Storage-ის გამოყენებისას გახსოვდეს

  • სენსიტიური მონაცემი (პაროლი, ტოკენი) localStorage-ში არ შეინახო — ნებისმიერ XSS-ს შეუძლია წაიკითხოს.
  • Private/Incognito რეჟიმში localStorage sessionStorage-ივით იქცევა: ფანჯრის დახურვისას იშლება.
  • Safari-ს თვალთვალისგან დაცვის პოლიტიკით, თუ მომხმარებელი დიდხანს (დაახლ. 7 დღე) არ ურთიერთობს საიტთან, script-ით ჩაწერილი მონაცემი შეიძლება წაიშალოს. დასკვნა: ბრაუზერის საცავი არის კომფორტი და ქეში, არა ერთადერთი „ჭეშმარიტების წყარო" — მნიშვნელოვანი მონაცემი სერვერზეც უნდა ინახებოდეს.
  • შენახული მონაცემი „არასანდოა": მომხმარებელს DevTools-ში ნებისმიერი ჩანაწერის შეცვლა შეუძლია — წაკითხვისას ყოველთვის გადაამოწმე ფორმატი .
  • DevTools → Application → Local storage / Session storage / Cookies: ჩანაწერებს ცხრილად ნახავ, ორმაგი დაწკაპუნებით შეცვლი ან წაშლი, „Clear site data"-თი ყველაფერს გაასუფთავებ. ეს შენი მთავარი დებაგ-ხელსაწყოა ამ თემისთვის.

Cookies

Cookie ბრაუზერისა და სერვერის საერთო მექანიზმია:

ბრაუზერიდან სერვერზე: როდესაც შენი საიტი სერვერზე აგზავნის რაიმე მოთხოვნას (მაგალითად, ღილაკს აჭერ ან გვერდს ტვირთავ), ბრაუზერი ავტომატურად აყოლებს იმ დომენისთვის შენახულ ქუქიებს HTTP Header-ში (Cookie: username=nata). სერვერი ამას კითხულობს და ხვდება, ვინ აკეთებს მოთხოვნას (მაგალითად, რომელი მომხმარებელია ავტორიზებული).

სერვერიდან ბრაუზერში: როდესაც სერვერს პასუხის დაბრუნება სურს, ის პასუხში აყოლებს სათაურს Set-Cookie: username=nata, ბრაუზერი კი ამას იმახსოვრებს

მოცულობა: ერთი ქუქი არის ძალიან პატარა — მაქსიმუმ 4 კილობაიტი (KB). ამიტომ მასში დიდ მონაცემებს (როგორც localStorage-ში) ვერ შეინახავ. ის ძირითადად გამოიყენება ტოკენებისთვის, იდენტიფიკატორებისთვის ან პატარა პარამეტრებისთვის.

document.cookie ერთ cookie-ს ამატებს/ანახლებს (დანარჩენებს არ „გადააწერს"), წაკითხვისას კი ყველას ერთ სტრიქონად აბრუნებს, ატრიბუტების გარეშე. ხელით პარსინგი არასაიმედოა, ამიტომ სამი დამხმარე ფუნქცია: 

function setCookie(name, value, { days = 365, path = "/", sameSite = "Lax" } = {}) {
  const maxAge = days * 24 * 60 * 60;
  document.cookie = `${encodeURIComponent(name)}=${encodeURIComponent(value)}; max-age=${maxAge}; path=${path}; SameSite=${sameSite}`;
}

function getCookie(name) {
  const prefix = `${encodeURIComponent(name)}=`;
  const found = document.cookie.split("; ").find(row => row.startsWith(prefix));
  return found ? decodeURIComponent(found.slice(prefix.length)) : null;
}

function deleteCookie(name, path = "/") {
  document.cookie = `${encodeURIComponent(name)}=; max-age=0; path=${path}`;  // path იგივე უნდა იყოს, რაც ჩაწერისას!
}

ძებნა Debounce-ით

input event ყოველ სიმბოლოზე ირთვება — ყოველ კლავიშზე ფილტრაცია/რენდერი (ან API მოთხოვნა) ზედმეტი სამუშაოა. Debounce ფუნქციას „აყოვნებს": შესრულდება მხოლოდ მაშინ, როცა ბოლო გამოძახებიდან delay ხანი გავიდა. აქ ერთად მუშაობს closure (timerId-ს „ახსოვს", გაკვეთილი 13), Higher-Order Function (ფუნქციას აბრუნებს, 17) და setTimeout (18): 

function debounce(fn, delay = 300) {
  let timerId;                              // closure-ში ცოცხალი
  return (...args) => {
    clearTimeout(timerId);                  // წინა "ჩანიშნული" გამოძახება გაუქმდეს
    timerId = setTimeout(() => fn(...args), delay);
  };
}

const searchEl = document.querySelector("#search");

  query = e.target.value.trim().toLowerCase();
  render();                                 // ჩვენი render ფილტრსაც ითვალისწინებს და ძებნასაც
}, 300));
