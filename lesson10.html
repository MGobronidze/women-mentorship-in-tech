JS სინტაქსი, NPM/pnpm/Bun, ცვლადები, მონაცემთა ტიპები

აქამდე ვქმნიდით სტატიკურ გვერდებს, სადაც ინფორმაცია უბრალოდ განთავსებული იყო და მომხმარბელს არ შეეძლოთ რაიმე ქმედების გახორციელება. დღეს დავიწყებთ JavaScript-ის შესწავლას, იგი პროგრამირების ენაა, რომელიც, სწორედ დინამიურიობის შესამატებლად გვჭირდება. დავიწყოთ ენის ბაზისური სინტაქსით, თანამედროვე პაკეტების მენეჯერების ლანდშაფტით და მონაცემების შენახვის ხერხებით.

1. JavaScript-ის სინტაქსი — პირველი ნაბიჯები

JavaScript-ის კოდი შეიძლება ჩავსვათ HTML-ში <script> ტეგით, ან — უკეთესი პრაქტიკაა — ცალკე .js ფაილში, რომელსაც HTML-დან ვუკავშირდებით: 

<script src="script.js"></script>

ბრძანებები (statements) მთავრდება წერტილ-მძიმით (;) — ეს არ არის აბსოლუტურად სავალდებულო (JS-ს აქვს ავტომატური „Automatic Semicolon Insertion"), მაგრამ კარგი პრაქტიკაა მისი ხელით ჩაწერა, გაუთვალისწინებელი შეცდომების თავიდან ასაცილებლად.

თუ ახალ ხაზს იწყებთ კვადრატული [ ან მრგვალი ( ფრჩხილით, JS მას არ აღიქვამს ახალ ბრძანებად — მას ჰგონია, რომ წინა ხაზზე არსებულ ფუნქციას იძახებთ ან მასივს მიმართავთ. 


const a = 1 
      
[1, 2, 3].forEach(n => console.log(n))  
    
// ერთხაზიანი კომენტარი
console.log("გამარჯობა, JavaScript!"); // გამოაქვს ტექსტი DevTools Console-ში

/* მრავალხაზიანი
   კომენტარი */

Strict Mode — "use strict"

"use strict" ფაილის/ფუნქციის თავში ჩართავს JavaScript-ის „მკაცრ" რეჟიმს — ის კრძალავს რამდენიმე ძველ, საშიშ პატერნს (მაგ. ცვლადის შემთხვევით გლობალურად გამოცხადებას, var-ის გამოცხადების გარეშე გამოყენებას) და აჩენს შეცდომებს იქ, სადაც ძველად JS „ჩუმად" აგრძელებდა მუშაობას: 

"use strict";

age = 25; // ❌ ReferenceError strict mode-ში (age არასდროს გამოცხადებულა let/const/var-ით)

კარგი ამბავი: ES6 მოდულებში (<script type="module">, გავეცნობით მე-14 გაკვეთილიდან) და class-ის შიგნით (მე-20 გაკვეთილი) strict mode ავტომატურად ჩართულია — ხელით წერა აღარ სჭირდება. თანამედროვე პროექტების უმეტესობა (React-ის ჩათვლით) სწორედ მოდულების საშუალებით მუშაობს, ამიტომ ეს პრაქტიკულად „უფასოდ" გვაქვს.

JavaScript — ცოცხალი, ყოველწლიურად განახლებადი ენა

JavaScript-ის ოფიციალური სპეციფიკაცია (ECMAScript, შემოკლებით ES) TC39 კომიტეტის მიერ ყოველწლიურად განახლდება. მაგალითად, ES2024-მა დაამატა Object.groupBy() (მასივის ელემენტების დაჯგუფება), ხოლო ES2025-მა — Iterator Helpers და Set-ის მათემატიკური ოპერაციები (union, intersection). ამ კურსში თანდათან შევხვდებით ბევრ მათგანს — ჯერჯერობით მთავარია დავიმახსოვროთ, რომ JS არ არის „გაყინული" ენა, და ახალი ფუნქციები ყოველწლიურად ემატება.

2. პაკეტების მენეჯერები — npm, pnpm, Bun, Yarn (2026 წლის ლანდშაფტი)

NPM (Node Package Manager) არის ყველაზე გავრცელებული ინსტრუმენტი, რომელიც საშუალებას გვაძლევს დავამატოთ ჩვენს პროექტში სხვების მიერ დაწერილი, მრავალჯერ გამოსაცდელი კოდის პაკეტები (მაგ. React, Axios). NPM მოჰყვება Node.js-ს და ნებისმიერ დროს მუშაობს — ამიტომ კურსში მას ვიყენებთ ნაგულისხმევად. 

# პროექტის ინიციალიზაცია — ქმნის package.json ფაილს
npm init -y

# პაკეტის დაყენება (მაგ. axios)
npm install axios

# პაკეტის დაყენება მხოლოდ დეველოპმენტისთვის (მაგ. ტესტირების ინსტრუმენტი)
npm install --save-dev vitest

# პაკეტის ერთჯერადი გაშვება, დაყენების გარეშე
npx create-vite@latest

package.json ფაილი აღრიცხავს პროექტის ყველა დამოკიდებულებას (dependency) — როდესაც პროექტს სხვას უზიარებთ ან GitHub-ზე ტვირთავთ, არ არის საჭირო ათასობით ფაილისგან შემდგარი node_modules საქაღალდის (გადმოწერილი პაკეტების) გაგზავნა. სხვას შეუძლია ერთი ბრძანებით (npm install) დააყენოს ისინი.

package-lock.json — ზუსტი ვერსიების „ფოტოსურათი"

npm install-ის შემდეგ ავტომატურად იქმნება package-lock.json — ის აფიქსირებს ყოველი დამოკიდებულების (და მისი დამოკიდებულებების) ზუსტ ვერსიას იმ მომენტისთვის. ეს ფაილი ყოველთვის უნდა მოხვდეს Git-ში (არა .gitignore-ში) — ის უზრუნველყოფს, რომ გუნდის ყველა წევრს, და production სერვერსაც, ზუსტად იგივე ვერსიები დაუყენდეს, შემთხვევითი „ჩემთან მუშაობს, შენთან — არა" სიტუაციების თავიდან ასაცილებლად.

Semantic Versioning (semver) — ^ და ~ რას ნიშნავს

package.json-ში ვერსიები იწერება MAJOR.MINOR.PATCH ფორმატით (მაგ. 4.18.2) — თითოეული რიცხვის ცვლილებას განსხვავებული მნიშვნელობა აქვს:

ნაწილი იზრდება, როცა...
MAJOR (4.x.x)დანერგილია incompatible ცვლილება (breaking change)
MINOR (x.18.x)დამატებულია ახალი ფუნქციონალი, უკუთავსებადობის დარღვევის გარეშე
PATCH (x.x.2)გასწორებულია bug, API უცვლელია
 
// package.json-ში ხშირად ნახავ ასეთ სიმბოლოებს ვერსიის წინ:
"axios": "^1.7.2"   // ^ — დაშვებულია MINOR/PATCH განახლება (1.x.x, არა 2.0.0)
"lodash": "~4.17.21" // ~ — დაშვებულია მხოლოდ PATCH განახლება (4.17.x)
"react": "18.2.0"    // ზუსტი — არანაირი ავტომატური განახლება

2026 წლის პაკეტების მენეჯერების ლანდშაფტი

NPM-ის გარდა, დღეს აქტიურად გამოიყენება კიდევ სამი ალტერნატივა — თითოეულს თავისი უპირატესობა აქვს:

ინსტრუმენტი მთავარი უპირატესობა როდის ვირჩევთ
npm ყველგან მუშაობს, Node.js-თან ჩაშენებული უსაფრთხო ნაგულისხმევი არჩევანი, სასწავლო პროექტები
pnpm დისკის ეკონომია, მკაცრი დამოკიდებულებების იზოლაცია ("phantom dependency"-ების პრევენცია) გუნდური/დიდი პროექტები, monorepo-ები — 2026-ში ხშირად ნაგულისხმევი არჩევანია ახალი პროექტებისთვის
Bun ყველაზე სწრაფი ინსტალაცია; ასევე სრული runtime (შეუძლია Node.js-ის ჩანაცვლება) ინდივიდუალური პროექტები, სადაც სისწრაფე პრიორიტეტულია
Yarn (Berry/PnP) დახვეწილი workspace-ების მართვა, "Plug'n'Play" (node_modules-ის გარეშე) გუნდები, რომლებიც უკვე Yarn-ის ეკოსისტემაზეა აწყობილი

ამ კურსისთვის: ვიყენებთ npm-ს, რადგან ის ყოველთვის, ყველგან მუშაობს დამატებითი ინსტალაციის გარეშე — მაგრამ მნიშვნელოვანია იცოდე, რომ სხვა ვარიანტებიც არსებობს, და პროფესიულ პროექტში, სავარაუდოდ, ამათგან ერთს შეხვდები.

npm audit — უსაფრთხოების შემოწმება

2025-2026 წლებში გახშირდა „supply chain" შეტევები (მავნე კოდის ჩანერგვა პოპულარულ NPM პაკეტებში). კარგი პრაქტიკაა პერიოდულად გაუშვა: 

npm audit          # ცნობილი დაუცველობების სკანირება დამოკიდებულებებში
npm audit fix       # ავტომატური გასწორება (სადაც შესაძლებელია)

3. ცვლადები: let, const, var

ცვლადი არის „კონტეინერი" მონაცემისთვის. JavaScript-ს აქვს სამი გზა ცვლადის გამოსაცხადებლად: 

let age = 25;        // მნიშვნელობის შეცვლა შესაძლებელია
age = 26;             // მუშაობს

const name = "ანა";   // მნიშვნელობა უცვლელია, ხელახლა მინიჭება არ შეიძლება
name = "მარი";         // Error: Assignment to constant variable

var city = "თბილისი"; // ძველი სინტაქსი (ES5-მდე), დღეს იშვიათად გამოიყენება
  • const — ნაგულისხმევი არჩევანი. გამოიყენე, თუ ცვლადი მუდმივია და მნიშვნელობის შეცვლა არასოდეს დაგჭირდება.
  • let — გამოიყენე, თუ იცი, რომ მნიშვნელობა შეიცვლება (მაგ. მთვლელი ციკლში).
  • var — მოძველებულია; მისი „scope" ქცევა (function-level, არა block-level) ხშირად შეცდომების წყაროა. თანამედროვე კოდში პრაქტიკულად აღარ გამოიყენება.

მნიშვნელოვანია: const კრძალავს ცვლადის ხელახლა მინიჭებას, მაგრამ არა ობიექტის/მასივის შიდა შემცველობის შეცვლას — ამას მომდევნო გაკვეთილებში დავინახავთ.

4. მონაცემთა ტიპები (Data Types)

JavaScript-ს აქვს 7 primitive ტიპი და ერთი კომპლექსური (reference) კატეგორია — Object (რომელშიც შედის მასივიც და ფუნქციაც): 

// ხუთი ყველაზე ხშირად ხმარებული primitive ტიპი
let studentAge = 22;              // Number
let studentName = "გიორგი";       // String
let isEnrolled = true;            // Boolean
let middleName = undefined;      // Undefined — ცვლადს ჯერ არ აქვს მნიშვნელობა
let noValue = null;               // Null — შეგნებულად „ცარიელი" მნიშვნელობა

// Reference ტიპები (მომდევნო გაკვეთილებში ჩავუღრმავდებით)
let hobbies = ["კითხვა", "ცურვა"]; // Object (Array)
let student = { name: "გიორგი" };  // Object

// typeof ოპერატორი ამოწმებს ტიპს
console.log(typeof studentAge);   // "number"
console.log(typeof isEnrolled);   // "boolean"
console.log(typeof hobbies);      // "object" (მასივიც ობიექტია!)

undefined vs null ხშირად აბნევს დამწყებებს: undefined ავტომატურად ენიჭება ცვლადს, რომლისთვისაც ჯერ მნიშვნელობა არ მიუციათ, ხოლო null დეველოპერი შეგნებულად წერს, რომ აღნიშნოს „აქ განზრახ არაფერია".

ორი ნაკლებად ცნობილი primitive: BigInt და Symbol

// BigInt — ძალიან დიდი მთელი რიცხვებისთვის (Number-ის ზღვარს იქით)
const hugeNumber = 9007199254740993n; // "n" სუფიქსი ამცნობს BigInt-ს
console.log(typeof hugeNumber); // "bigint"

// Symbol — ყოველთვის უნიკალური მნიშვნელობა (იშვიათად გამოიყენება, ძირითადად ბიბლიოთეკებში)
const uniqueKey = Symbol("description");
console.log(typeof uniqueKey); // "symbol"

Number-ის „ხაფანგი": JavaScript-ის რიცხვები float-ის სახით ინახება, რაც ხანდახან მოულოდნელ შედეგს იძლევა — ეს ცნობილი, ხშირად ციტირებული მაგალითია: 

console.log(0.1 + 0.2); // 0.30000000000000004 — არა ზუსტად 0.3!
console.log(0.1 + 0.2 === 0.3); // false

// ეს ხდება ყველა ენაში, სადაც IEEE 754 float-ი გამოიყენება — არა მხოლოდ JS-ში.

  1. რას აკეთებს "use strict" და სად ჩაირთვება ის ავტომატურად, ხელით წერის გარეშე?
  2. რას აღრიცხავს package-lock.json და რატომ უნდა მოხვდეს ის Git-ში?
  3. რას ნიშნავს ^1.7.2 და რით განსხვავდება ის ~1.7.2-გან?
  4. რა უპირატესობა აქვს pnpm-ს npm-თან შედარებით — რას ნიშნავს "phantom dependency"?
  5. რა განსხვავებაა undefined-სა და null-ს შორის?
  6. რატომ იძლევა 0.1 + 0.2 JavaScript-ში 0.30000000000000004-ს, ზუსტად 0.3-ის ნაცვლად?

პრაქტიკული დავალებები

  1. შექმენი script.js ფაილი, დაუკავშირე HTML გვერდს და გამოიყენე console.log() DevTools Console-ში შესამოწმებლად.
  2. გამოაცხადე 5 ცვლადი — თითოეული სხვადასხვა primitive ტიპით (number, string, boolean, undefined, null) — და დაბეჭდე თითოეულის typeof Console-ში.
  3. სცადე const-ით გამოცხადებული ცვლადის ხელახლა მინიჭება და დააკვირდი Console-ში გამოსულ შეცდომას.
  4. დააინსტალირე Node.js (თუ ჯერ არ გაქვს), გაუშვი npm init -y ცარიელ საქაღალდეში და შეისწავლე შედეგად მიღებული package.json.
  5. დააინსტალირე ერთი პაკეტი (მაგ. npm install axios) და შეადარე package.json-სა და package-lock.json-ის შემცველობა — იპოვე, სად ჩანს ზუსტი ვერსია.
  6. Console-ში გაუშვი console.log(0.1 + 0.2) და console.log(0.1 + 0.2 === 0.3) — დაწერე, რატომ ხდება ეს.
  7. (რთული) დაწერე პატარა სკრიპტი, რომელიც აცხადებს სტუდენტის ინფორმაციას (სახელი, ასაკი, ჩარიცხულია თუ არა) ცალკეულ ცვლადებში და კონსოლში ბეჭდავს წინადადებას ამ ცვლადების გამოყენებით (template literal-ის — `${}` — გამოყენებით).
