Fetch, AJAX, JSON, DevTools — სლაიდერი და ვალიდაცია

წინა გაკვეთილში ვისწავლეთ, როგორ ვმართავთ ასინქრონულობას. ახლა გამოვიყენოთ ეს ცოდნა რეალურ სცენარში — მონაცემების წამოსაღებად სერვერიდან — და ავაწყოთ ორი პრაქტიკული UI.

1. AJAX — კონცეფცია

AJAX (Asynchronous JavaScript and XML) არის ტექნიკის საერთო სახელი, რომელიც JavaScript-ს საშუალებას აძლევს, სერვერს მოსთხოვოს მონაცემები გვერდის ხელახლა ჩატვირთვის გარეშე. სახელწოდებაში „XML" ისტორიულია — დღეს თითქმის ყოველთვის JSON-ს ვიყენებთ, XML-ის ნაცვლად.

2. XMLHttpRequest — ისტორიული საფუძველი

XMLHttpRequest (XHR) იყო პირველი API ბრაუზერის AJAX მოთხოვნებისთვის. დღეს იშვიათად იწერება ხელით (Fetch უფრო მარტივია), მაგრამ მნიშვნელოვანია ვიცოდეთ, რომ ის არსებობს — ბევრ ძველ კოდში ჯერ კიდევ გვხვდება: 

const xhr = new XMLHttpRequest();
xhr.open("GET", "https://api.example.com/users");
xhr.onload = function() {
  if (xhr.status === 200) {
    console.log(JSON.parse(xhr.responseText));
  }
};
xhr.send();

3. Fetch API — თანამედროვე სტანდარტი

fetch() არის Promise-ზე დაფუძნებული, ბევრად მარტივი API HTTP მოთხოვნების გასაგზავნად. დღეს ეს არის სტანდარტული არჩევანი. 

// GET მოთხოვნა — async/await-ით
async function loadUsers() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/users");

    if (!response.ok) {
      throw new Error(`HTTP შეცდომა: ${response.status}`);
    }

    const users = await response.json(); // პასუხის ტექსტის JSON-ად გარდაქმნა
    console.log(users);
  } catch (error) {
    console.error("მონაცემების წამოღება ვერ მოხერხდა:", error.message);
  }
}
// POST მოთხოვნა — მონაცემების გაგზავნა
async function createUser(userData) {
  const response = await fetch("https://api.example.com/users", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(userData), // JS ობიექტი → JSON სტრიქონი
  });
  return await response.json();
}

4. JSON — ობიექტი და მეთოდები

JSON (JavaScript Object Notation) არის ტექსტური ფორმატი მონაცემების გადასაცემად — ის ჰგავს JS ობიექტს, მაგრამ არის მკაცრად ტექსტური (string). 

const user = { name: "ანა", age: 22, active: true };

// JS ობიექტი → JSON სტრიქონი (გასაგზავნად)
const jsonString = JSON.stringify(user);
console.log(jsonString); // '{"name":"ანა","age":22,"active":true}'

// JSON სტრიქონი → JS ობიექტი (მიღებული პასუხის დასამუშავებლად)
const parsedUser = JSON.parse(jsonString);
console.log(parsedUser.name); // "ანა"

response.json(), რომელსაც Fetch-თან ერთად ვიყენებთ, სინამდვილეში JSON.parse()-ის „მოხერხებული" ვერსიაა, უშუალოდ HTTP პასუხისთვის.

5. DevTools — Network ტაბი

Network ტაბი (გავეცანით მე-1 გაკვეთილში ზოგადად) ახლა კონკრეტულად გამოსადეგია fetch მოთხოვნების სადებაგოდ:

  • ხედავ ყველა გაგზავნილ მოთხოვნას, მათ სტატუს კოდს და დროს.
  • ერთ მოთხოვნაზე დაწკაპუნებით ხედავ Headers-ს (რა გაგზავნე), Response-ს (რა მიიღე) და Preview-ს (გაფორმებული ხედი).
  • ფილტრით Fetch/XHR შეგიძლია დანარჩენი (სურათები, ფონტები) დამალო და მხოლოდ API მოთხოვნებზე ფოკუსირდე.

6. პრაქტიკა: სლაიდერი და ფორმის ვალიდაცია

ორი პატარა, დამოუკიდებელი UI კომპონენტი, რომლებიც აერთიანებს ამ და წინა გაკვეთილების ცოდნას — DOM, events, state ცვლადებში. 

// მარტივი სურათების სლაიდერი
const slides = document.querySelectorAll(".slide");
let currentIndex = 0;

function showSlide(index) {
  slides.forEach((slide, i) => {
    slide.style.display = i === index ? "block" : "none";
  });
}

document.querySelector(".next-btn").addEventListener("click", () => {
  currentIndex = (currentIndex + 1) % slides.length; // წრიულად უბრუნდება დასაწყისს
  showSlide(currentIndex);
});

showSlide(currentIndex); // საწყისი მდგომარეობა
// ფორმის ვალიდაცია, submit-ის დროს
const form = document.querySelector("#signup-form");

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const email = document.querySelector("#email").value.trim();
  const errorEl = document.querySelector("#email-error");

  if (!email.includes("@")) {
    errorEl.textContent = "გთხოვთ, მიუთითოთ ვალიდური ელფოსტა";
    return;
  }

  errorEl.textContent = "";
  console.log("ფორმა ვალიდურია, იგზავნება:", email);
});
