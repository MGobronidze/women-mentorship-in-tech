1. HTTP, REST, CORS — ბაზისი

სანამ კოდზე გადავალთ, გავიხსენოთ, რას ველაპარაკებით. API (Application Programming Interface) აქ ნიშნავს სერვერზე არსებულ მისამართებს (endpoint-ებს), რომლებიც მონაცემებს, ჩვეულებრივ JSON ფორმატში, გვიბრუნებს ან იღებს. ყველაზე გავრცელებული სტილია REST.

CORS — ყველაზე ხშირი „უცნაური“ შეცდომა

როცა შენი აპლიკაცია (მაგ. http://localhost:5173) სხვა წარმოშობის (origin) სერვერს (მაგ. https://api.example.com) ეკონტაქტება, ბრაუზერი ამოწმებს, ნებას რთავს თუ არა სერვერი ამას (Access-Control-Allow-Origin header). თუ არ რთავს, კონსოლში ჩნდება „blocked by CORS policy“. ეს სერვერის კონფიგურაციის საკითხია, React-ის ან Axios-ის კოდის შეცდომა არ არის. development-ში გავრცელებული გამოსავალია Vite-ის proxy: 

// vite.config.js
export default defineConfig({
  plugins: [react()],
  server: {
    proxy: {
      // /api/... მოთხოვნები გადაიგზავნება backend-ზე — ბრაუზერისთვის ის იგივე origin-ია
      "/api": { target: "http://localhost:3000", changeOrigin: true },
    },
  },
})

2. მონაცემების წამოღება: async/await + useEffect

React-ში API მოთხოვნები ჩვეულებრივ ხდება useEffect-ის შიგნით (მე-22 გაკვეთილიდან ნაცნობი), async ფუნქციის დახმარებით (useEffect-ის callback თავად არ შეიძლება იყოს async): 

function ProductList() {
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    async function loadProducts() {
      try {
        const response = await fetch("/api/products");
        if (!response.ok) throw new Error("წამოღება ვერ მოხერხდა");
        const data = await response.json();
        setProducts(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false); // ან წარმატებით, ან შეცდომით — loading მთავრდება
      }
    }
    loadProducts();
  }, []);

  if (loading) return <p>იტვირთება...</p>;
  if (error) return <p>შეცდომა: {error}</p>;
  return <ul>{products.map(p => <li key={p.id}>{p.name}</li>)}</ul>;
}

loading და error state ცვლადები — ეს არის სტანდარტული პატერნი ნებისმიერ React აპლიკაციაში, სადაც მონაცემები სერვერიდან მოდის. ამ კოდს ორი მნიშვნელოვანი ნაკლი აქვს, რომელსაც ქვემოთ გამოვასწორებთ: ძველი მოთხოვნა არ უქმდება (race condition) და მონაცემი ბევრ ადგილას მეორდება.

ძალიან მნიშვნელოვანი: fetch არ „ვარდება“ HTTP შეცდომაზე

fetch-ის Promise მხოლოდ ქსელის შეცდომაზე (კავშირი არ არის, CORS, DNS) უარყოფილია (reject). თუ სერვერმა 404 ან 500 დააბრუნა, fetch ჩვეულებრივად „წარმატებულად“ სრულდება — ამიტომ აუცილებლად შეამოწმე response.ok (ეს true არის 200–299 სტატუსებზე) ან response.status. ეს ერთ-ერთი ყველაზე ხშირი ბაგია დამწყებებისთვის.

სრული „მზა“ ვერსია: გაუქმება, პარალელური მოთხოვნები და სხვა მეთოდები

useEffect(() => {
  const controller = new AbortController();   // მოთხოვნის გაუქმების საშუალება

  async function load() {
    try {
      setLoading(true);
      setError(null);

      const res = await fetch(`${API_URL}/products?category=${category}`, {
        signal: controller.signal,
      });
      if (!res.ok) throw new Error("HTTP " + res.status);

      setProducts(await res.json());
    } catch (err) {
      if (err.name !== "AbortError") setError(err.message); // გაუქმება შეცდომა არ არის
    } finally {
      if (!controller.signal.aborted) setLoading(false);
    }
  }

  load();
  return () => controller.abort();   // cleanup: category-ის შეცვლისას ძველი მოთხოვნა უქმდება
}, [category]);
// POST — ახალი ჩანაწერის გაგზავნა
async function createUser(user) {
  const res = await fetch(`${API_URL}/users`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(user),       // ობიექტი → JSON სტრიქონი
  });
  if (!res.ok) throw new Error("შექმნა ვერ მოხერხდა");
  return res.json();
}

// DELETE
await fetch(`${API_URL}/users/${id}`, { method: "DELETE" });

// რამდენიმე დამოუკიდებელი მოთხოვნა ერთდროულად (უფრო სწრაფია, ვიდრე ზედიზედ await)
const [users, posts] = await Promise.all([
  fetch(`${API_URL}/users`).then((r) => r.json()),
  fetch(`${API_URL}/posts`).then((r) => r.json()),
]);

UI-ს მდგომარეობები: loading / error / empty / success

კარგი აპლიკაცია მომხმარებელს ოთხივე მდგომარეობაში ეხმარება: იტვირთება (spinner ან skeleton), შეცდომა (გასაგები ტექსტი და „სცადე ხელახლა“ ღილაკი), ცარიელია (მონაცემი წარმატებით მოვიდა, მაგრამ სია ცარიელია) და წარმატება. ხშირი შეცდომაა მხოლოდ „წარმატების“ დაწერა. 

if (loading) return <p role="status">იტვირთება...</p>;
if (error) return (
  <div role="alert">
    <p>შეცდომა: {error}</p>
    <button onClick={reload}>სცადე ხელახლა</button>
  </div>
);
if (products.length === 0) return <p>პროდუქტები ვერ მოიძებნა.</p>;
return <ul>...</ul>;

რეალურ პროექტებში: server state-ის ბიბლიოთეკები

useEffect + fetch მშვენიერია სასწავლად და პატარა პროექტებისთვის, მაგრამ რეალურ აპლიკაციებში მონაცემების წამოღებას (ქეშირება, ავტომატური განმეორება, გადაფრენა, ფონური განახლება, mutation-ები) ხშირად TanStack Query (@tanstack/react-query, v5) ან SWR ხსნის: 

import { useQuery } from "@tanstack/react-query";

function Users() {
  const { data, isPending, isError, error } = useQuery({
    queryKey: ["users"],
    queryFn: async () => {
      const res = await fetch("https://jsonplaceholder.typicode.com/users");
      if (!res.ok) throw new Error("HTTP " + res.status);
      return res.json();
    },
  });

  if (isPending) return <p>იტვირთება...</p>;
  if (isError) return <p>შეცდომა: {error.message}</p>;
  return <ul>{data.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;
}

(ამ ბიბლიოთეკას მთლიანი აპლიკაცია <QueryClientProvider>-ით უნდა შეეფუთოს.) ახლა მთავარი მიზანი ისაა, რომ გესმოდეს, რას აკეთებენ ისინი „კედლის უკან“ — სწორედ ამას ვსწავლობთ ამ გაკვეთილზე.

3. Axios — ალტერნატივა Fetch-ისთვის

Axios არის პოპულარული NPM ბიბლიოთეკა HTTP მოთხოვნებისთვის — Fetch-თან შედარებით გვთავაზობს ავტომატურ JSON პარსინგს, უფრო მარტივ error handling-ს და request/response ინტერცეპტორებს. 

# ინსტალაცია
npm install axios
import axios from "axios";

async function loadProducts() {
  try {
    const response = await axios.get("/api/products"); // ავტომატურად JSON-ად პარსავს
    setProducts(response.data); // მონაცემი პირდაპირ .data-შია, .json() აღარ სჭირდება
  } catch (err) {
    setError(err.message);
  }
}

უსაფრთხოება: 2026 წლის მარტის Axios ინციდენტი

2026 წლის 31 მარტს თავდამსხმელმა Axios-ის მომვლელის npm ანგარიში გატეხა და გამოაქვეყნა ორი მავნე ვერსია — axios@1.14.1 და axios@0.30.4 (ისინი ზიანის მომტან დამოკიდებულებას მოიცავდა). npm-მა ორივე რამდენიმე საათში წაშალა, მაგრამ იმ პერიოდში npm install axios ლოკ-ფაილის გარეშე შეიძლებოდა მავნე ვერსიაზე „მოსულიყო“. ეს გაკვეთილი მნიშვნელოვანია არა იმიტომ, რომ Axios „ცუდია“ — პრობლემა ნებისმიერ პოპულარულ npm პაკეტს შეიძლება შეეხოს. პრაქტიკული წესები:

  • lock ფაილი (package-lock.json) აუცილებლად Git-ში ჩაამატე და CI-ში/დეპლოიში გამოიყენე npm ci, არა npm install.
  • ახალი პაკეტის დამატებამდე შეამოწმე: რამდენი ჩამოტვირთვა აქვს, ვინ მართავს, ბოლოს როდის განახლდა.
  • ახალი ვერსიის გამოშვებისთანავე ავტომატურად ნუ განაახლებ — დაელოდე რამდენიმე დღე (არსებობს ინსტრუმენტები, რომლებიც ახალ გამოშვებებს „დაყოვნებას“ უწესებენ).
  • პერიოდულად გაუშვი npm audit; რეალურ პროექტებში გამოიყენე dependency-სკანერი (Dependabot, Socket და ა.შ.).
  • თუ 2026 წლის 31 მარტს შენს მანქანაზე ვინმემ Axios დააინსტალირა ლოკ-ფაილის გარეშე და შეიძლება მავნე ვერსია ჩამოტვირთულიყო, ეს უსაფრთხოების ინციდენტია: გადაამოწმე ვერსიები და გამოიყენე უსაფრთხოების კომპანიების გზამკვლევები (ბმულები ქვემოთ).

დღეს უახლესი Axios ვერსია სანდო წყაროდან (npm view axios version) გადაამოწმე; ქვედა ვერსიები, რომლებიც 2026 წლის აპრილის უსაფრთხოების ხარვეზებს შეიცავს, არ გამოიყენო (დაფიქსირდა 1.15.x განახლებით).

Axios instance — ერთხელ დაყენებული კონფიგურაცია

Axios ასევე იძლევა საშუალებას, ერთხელ დავაყენოთ „ბაზური" კონფიგურაცია (base URL, default headers) — გამოსადეგია, როცა ბევრი endpoint-თან ვმუშაობთ: 

// src/api/client.js
import axios from "axios";

export const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL,   // მაგ. https://api.example.com
  timeout: 10000,                          // 10 წმ-ის შემდეგ მოთხოვნა შეცდომით სრულდება
  headers: { "Content-Type": "application/json" },
});

4. Custom Hook

Custom Hook არის ჩვეულებრივი JavaScript ფუნქცია, რომლის სახელი იწყება use-ით და რომელიც სხვა Hook-ებს (useState, useEffect) იყენებს — ეს საშუალებას გვაძლევს, გავიტანოთ განმეორებადი ლოგიკა ცალკე, ხელახლა გამოსაყენებელ ერთეულში. მნიშვნელოვანია: Custom Hook-ი ლოგიკას იზიარებს და არა state-ს — ერთსა და იმავე Hook-ს ორ კომპონენტში თითოეული თავის დამოუკიდებელ state-ს მიიღებს. 

// useFetch.js — Custom Hook, რომელიც "ფარავს" loading/error/data ლოგიკას
import { useState, useEffect } from "react";
import axios from "axios";

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    setLoading(true);
    axios.get(url)
      .then(res => setData(res.data))
      .catch(err => setError(err.message))
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading, error };
}

export default useFetch;
// ProductList.jsx — ერთი ხაზი, ნაცვლად 15-ის!

  return <ul>{products.map(p => <li key={p.id}>{p.name}</li>)}</ul>;
}

ზემოთ მოცემულ ვერსიას სამი ნაკლი აქვს: (1) URL სწრაფად რომ შეიცვალოს, ძველმა ნელმა პასუხმა შეიძლება ახალი გადააწეროს (race condition); (2) შეცდომა არ ნულდება ახალი მოთხოვნისას; (3) „ხელახლა სცადე“ ფუნქცია არ არსებობს. გამართული ვერსია (სუფთა fetch-ზე, დამოკიდებულების გარეშე): 

// src/hooks/useFetch.js
import { useState, useEffect, useCallback } from "react";

export function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(Boolean(url));
  const [error, setError] = useState(null);
  const [reloadCount, setReloadCount] = useState(0);

  const reload = useCallback(() => setReloadCount((c) => c + 1), []);

  useEffect(() => {
    if (!url) return;                         // URL ჯერ არ არის (მაგ. ველოდებით ID-ს)

    const controller = new AbortController();
    setLoading(true);
    setError(null);

    fetch(url, { signal: controller.signal })
      .then((res) => {
        if (!res.ok) throw new Error("HTTP " + res.status);
        return res.json();
      })
      .then((json) => setData(json))
      .catch((err) => {
        if (err.name !== "AbortError") setError(err.message);
      })
      .finally(() => {
        if (!controller.signal.aborted) setLoading(false);
      });

    return () => controller.abort();          // cleanup
  }, [url, reloadCount]);

  return { data, loading, error, reload };
}

Axios-ის ვერსიაში ცვლილება მხოლოდ მოთხოვნის ხაზშია: axios.get(url, { signal: controller.signal }) და შეცდომაში axios.isCancel(err)-ის შემოწმება. სახელობითი ექსპორტი (export function useFetch) და ნაგულისხმევი (export default) ორივე მისაღებია — მთავარია პროექტში ერთი სტილი გამოიყენო.

Hook-ის გამოყენებისას — ობიექტი dependency-ში

useFetch(url)-ში url სტრიქონია — პრიმიტივი, ამიტომ dependency სწორად მუშაობს. თუ Hook-ში ობიექტს (მაგ. options) გადასცემ, რომელიც რენდერისას ყოველ ჯერზე ახლიდან იქმნება, ეფექტი ყოველ რენდერზე გაეშვება და მიიღებ უსასრულო ციკლს (სავარაუდოდ „მოთხოვნების ქარიშხალს“). მოთხოვნის პარამეტრები ან URL-ში ჩააწერე (`/items?page=${page}`) ან გამოიყენე პრიმიტივები.

// useDebounce — 400 მწ-ით დაგვიანებული მნიშვნელობა
import { useState, useEffect } from "react";

export function useDebounce(value, delay = 400) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);            // ახალი ასოს აკრეფისას ძველი ტაიმერი უქმდება
  }, [value, delay]);

  return debounced;
}

6. Virtual DOM — რატომ არის React სწრაფი

React ინახავს „ვირტუალურ" ასლს DOM-ისა მეხსიერებაში (Virtual DOM). state-ის შეცვლისას, React ჯერ ადარებს ახალ ვირტუალურ DOM-ს ძველთან (diffing) და შემდეგ ნამდვილ ბრაუზერის DOM-ში ცვლის მხოლოდ იმას, რაც რეალურად შეიცვალა — ეს ბევრად უფრო სწრაფია, ვიდრე მთელი გვერდის ხელახლა აგება.

როგორ მუშაობს ეს ნაბიჯ-ნაბიჯ

  1. ტრიგერი — state იცვლება (setCount) ან მშობელი ახალ props-ს გადასცემს.
  2. რენდერი — React იძახებს შენს კომპონენტებს და იღებს ახალ React element-ების ხეს (JavaScript ობიექტებს — „ვირტუალურ DOM“-ს; ის, რაც ქვევით ვნახეთ createElement-ის შედეგად).
  3. შედარება (reconciliation) — React ადარებს ახალ ხეს წინასთან. ეს რთული ალგორითმია, მაგრამ ორ მარტივ ევრისტიკას ეყრდნობა:
    • თუ ელემენტის ტიპი შეიცვალა (<div> → <span> ან <A /> → <B />), React ძველ ქვეხეს მთლიანად აგდებს და ახალს აშენებს (state-ის დაკარგვითაც);
    • თუ ტიპი იგივეა, React მხოლოდ შეცვლილ ატრიბუტებს/ტექსტს ანახლებს; სიებში ელემენტებს key-ით ცნობს.
  4. Commit — React რეალურ DOM-ს მხოლოდ ზუსტად იმ ადგილებში ცვლის, სადაც სხვაობა იპოვა.

დაზუსტება: „Virtual DOM სწრაფია“ — რას ნიშნავს ეს?

Virtual DOM ყოველთვის უფრო სწრაფი არ არის, ვიდრე ხელით, ზუსტად გაწერილი DOM-ის განახლება — ის დამატებით შედარების სამუშაოს აკეთებს. მისი ძირითადი მნიშვნელობა სხვაა: ის გვაძლევს დეკლარაციულ პროგრამირებას (ვწერთ, როგორ გამოიყურება UI მონაცემებისთვის, არა როგორ შევცვალოთ DOM ბრძანებებით) და ამავდროულად საკმარისად სწრაფ განახლებებს, რომ ეს მიდგომა მასშტაბურად იმუშაოს. არსებობს ფრეიმვორქები (Svelte, Solid), რომლებიც ვირტუალურ DOM-ს საერთოდ არ იყენებენ და სხვა მეთოდით აღწევენ სიჩქარეს — „რომელი სჯობს“ კამათი არ არის ამ გაკვეთილის საკითხი.

React Fiber და კონკურენტული რენდერი

ამჟამინდელი React-ის შიგნით მუშაობს Fiber არქიტექტურა: რენდერის სამუშაო პატარა ნაწილებად იყოფა და შეიძლება შეჩერდეს ან გადაიდოს, რომ მომხმარებლის ქმედებები (კლავიატურაზე წერა, დაწკაპუნება) არ „გაიყინოს“. ამას ეყრდნობა useTransition, Suspense და 19.3-ში stable <ViewTransition>. შენთვის პრაქტიკული დასკვნა: რენდერის დროს კომპონენტი „სუფთა“ უნდა იყოს (გვერდითი ეფექტების გარეშე) — რადგან React მას შეიძლება რამდენჯერმე გამოიძახოს, ან გააუქმოს.

პრაქტიკული რჩევები ეფექტურობისთვის

  • ყოველთვის უნიკალური, სტაბილური key სიებში.
  • state შეინახე იმ კომპონენტთან, რომელსაც ის სჭირდება — რაც უფრო მაღლაა state, მით მეტი კომპონენტი ხელახლა იხატება.
  • ჯერ გაზომე, მერე ოპტიმიზაცია: React DevTools Profiler-ით. ნუ დაწერ useMemo-ს და useCallback-ს „ყოველი შემთხვევისთვის“ — React Compiler ბევრ ასეთ შემთხვევას ავტომატურად ხსნის.
  • დიდი სიებისთვის (ათასობით ელემენტი) გამოიყენე ვირტუალიზაცია (მაგ. @tanstack/react-virtual) — ეს სხვა „ვირტუალური“ ცნებაა: მხოლოდ ეკრანზე ჩანაცვლებული ელემენტები იხატება.

მნიშვნელოვანი განახლება: პაკეტი react-router-ია, არა react-router-dom

Data რეჟიმი (მოკლედ): createBrowserRouter და loader

„Data“ რეჟიმში მარშრუტები ობიექტების მასივად აღიწერება და მონაცემებს გვერდის გამოჩენამდე loader-ი ტვირთავს (არა useEffect-ი კომპონენტის შიგნით). ეს თანამედროვე და ძალიან გავრცელებული მიდგომაა; აქ მხოლოდ გაგებისთვის ვაჩვენებთ: 

import { createBrowserRouter, useLoaderData } from "react-router";
import { RouterProvider } from "react-router/dom";      // v8-ში ბრაუზერისთვის ეს იმპორტია რეკომენდებული

const router = createBrowserRouter([
  {
    path: "/",
    Component: Layout,
    children: [
      { index: true, Component: Home },
      {
        path: "users/:userId",
        loader: async ({ params }) => {
          const res = await fetch(`https://jsonplaceholder.typicode.com/users/${params.userId}`);
          if (!res.ok) throw new Response("მომხმარებელი ვერ მოიძებნა", { status: res.status });
          return res.json();
        },
        Component: UserDetails,          // შიგნით:  const user = useLoaderData();
        ErrorBoundary: UserError,        // შეცდომის გვერდი ამ მარშრუტისთვის
      },
    ],
  },
]);

createRoot(document.getElementById("root")).render(<RouterProvider router={router} />);

  • Vite dev სერვერი, npm run preview, Netlify, Vercel, Cloudflare Pages — ეს, როგორც წესი, ავტომატურად ან მცირე კონფიგურაციით (Netlify-ში public/_redirects ფაილი: /* /index.html 200) მუშაობს.
  • GitHub Pages — არ აქვს fallback; გამოსავალი: HashRouter (/#/users/5), ან 404.html ხრიკი. ამასთან vite.config.js-ში base: "/რეპოზიტორია/" და <BrowserRouter basename="/რეპოზიტორია"> უნდა დააყენო.

// src/pages/UsersPage.jsx
import { Link, useSearchParams } from "react-router";
import { useFetch } from "../hooks/useFetch";

const API = "https://jsonplaceholder.typicode.com";

function UsersPage() {
  const { data: users, loading, error, reload } = useFetch(`${API}/users`);
  const [searchParams, setSearchParams] = useSearchParams();
  const search = searchParams.get("search") ?? "";

  if (loading) return <p role="status">იტვირთება...</p>;
  if (error) return (
    <div role="alert">
      <p>შეცდომა: {error}</p>
      <button onClick={reload}>სცადე ხელახლა</button>
    </div>
  );

  // გაფილტვრა რენდერისას — ცალკე state არ გვჭირდება
  const visible = users.filter((u) =>
    u.name.toLowerCase().includes(search.toLowerCase())
  );

  return (
    <section>
      <h1>მომხმარებლები</h1>

      <input
        value={search}
        onChange={(e) => setSearchParams(e.target.value ? { search: e.target.value } : {})}
        placeholder="ძებნა სახელით..."
        aria-label="ძებნა"
      />

      {visible.length === 0 ? (
        <p>ვერაფერი მოიძებნა.</p>
      ) : (
        <ul>
          {visible.map((u) => (
            <li key={u.id}>
              <Link to={`/users/${u.id}`}>{u.name}</Link> — {u.email}
            </li>
          ))}
        </ul>
      )}
    </section>
  );
}

export default UsersPage;

10. თვითშემოწმება

1. რატომ არ შეიძლება useEffect-ის callback იყოს async?

async ფუნქცია Promise-ს აბრუნებს, React კი ეფექტისგან ელოდება ან არაფერს, ან cleanup ფუნქციას. async ფუნქცია ეფექტის შიგნით განვსაზღვროთ და იქვე გამოვიძახოთ.

2. რა განსხვავებაა HTTP შეცდომების დამუშავებაში fetch-სა და Axios-ს შორის?

fetch Promise-ს მხოლოდ ქსელის შეცდომაზე აუქმებს; 404/500-ზე „წარმატებით“ სრულდება და res.ok უნდა შევამოწმოთ. Axios ნებისმიერ არა-2xx სტატუსზე გადადის catch-ში, ხოლო err.response-ში სერვერის პასუხია.

3. რას ნიშნავს loading/error/empty მდგომარეობების დამუშავება და რატომ არის ის მნიშვნელოვანი?

კარგი UI მომხმარებელს ყველა სიტუაციაში ეუბნება, რა ხდება: იტვირთება, შეცდომაა (და როგორ გავასწოროთ), მონაცემი არ არის, ან წარმატებაა. მხოლოდ „წარმატების“ დაწერა თეთრ ეკრანს ან უსასრულო spinner-ს იძლევა.

4. რას წყვეტს AbortController მონაცემების წამოღებისას?

ძველი ან აღარაქტუალური მოთხოვნის გაუქმებას (კომპონენტის მოხსნისას ან dependency-ს შეცვლისას), რათა ნელმა ძველმა პასუხმა ახალი მონაცემი არ გადააწეროს (race condition).

5. რა არის Custom Hook და რას იზიარებს ის სხვადასხვა კომპონენტებს შორის?

ეს არის use-ით დაწყებული ფუნქცია, რომელიც სხვა Hooks-ს იყენებს. ის იზიარებს ლოგიკას და არა state-ს: ყოველი კომპონენტი თავის დამოუკიდებელ state-ს იღებს.

6. რატომ არ ინახება API-ის საიდუმლო გასაღები VITE_ ცვლადში?

VITE_ ცვლადები build-ისას JavaScript-ში ჩაიწერება და ბრაუზერში ყველასთვის ხილულია. საიდუმლო მონაცემები backend-ზე უნდა ინახებოდეს.

7. რა დასკვნა გამოვიტანოთ Axios-ის 2026 წლის მარტის ინციდენტიდან?

ნებისმიერი პოპულარული npm პაკეტი შეიძლება კომპრომეტირებული გახდეს. გამოიყენე lock ფაილი და npm ci, გააკონტროლე ახალი ვერსიები და დამოკიდებულებები, გაუშვი npm audit.

8. როგორ მუშაობს Virtual DOM და რას აკეთებს key?

React ინახავს UI-ის აღწერას მეხსიერებაში, ადარებს ახალ და ძველ ხეს და რეალურ DOM-ში მხოლოდ სხვაობას ცვლის. key ეხმარება სიებში ელემენტების ამოცნობაში.

9. რით განსხვავდება <Link> <a>-სგან?

<Link> ნავიგაციას React Router-ის მეშვეობით აკეთებს, გვერდის სრული გადატვირთვის გარეშე (state რჩება). <a href> ბრაუზერს ახალი გვერდის ჩატვირთვას აიძულებს.

10. რა პაკეტიდან ვიმპორტებთ Routes, Link, useParams-ს დღეს და რატომ?

react-router-იდან. v7-ში react-router-dom გაერთიანდა react-router-ში, ხოლო v8-ში react-router-dom ამოიღეს; RouterProvider ბრაუზერისთვის react-router/dom-იდან იმპორტირდება.
