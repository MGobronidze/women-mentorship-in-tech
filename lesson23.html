API მუშაობა, Axios, Custom Hook, Router

React აპლიკაცია იშვიათად არსებობს იზოლირებულად — თითქმის ყოველთვის მას სჭირდება სერვერთან კომუნიკაცია და რამდენიმე „გვერდი". ეს გაკვეთილი სწორედ ამას ეთმობა.

1. მონაცემების წამოღება: async/await + useEffect

React-ში API მოთხოვნები ჩვეულებრივ ხდება useEffect-ის შიგნით (მე-22 გაკვეთილიდან ნაცნობი), async ფუნქციის დახმარებით (useEffect-ის callback თავად არ შეიძლება იყოს async): 

function ProductList() {
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    async function loadProducts() {
      try {
        const response = await fetch("/api/products");
        if (!response.ok) throw new Error("წამოღება ვერ მოხერხდა");
        const data = await response.json();
        setProducts(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false); // ან წარმატებით, ან შეცდომით — loading მთავრდება
      }
    }
    loadProducts();
  }, []);

  if (loading) return <p>იტვირთება...</p>;
  if (error) return <p>შეცდომა: {error}</p>;
  return <ul>{products.map(p => <li key={p.id}>{p.name}</li>)}</ul>;
}

loading და error state ცვლადები — ეს არის სტანდარტული პატერნი ნებისმიერ React აპლიკაციაში, სადაც მონაცემები სერვერიდან მოდის.

2. Axios — ალტერნატივა Fetch-ისთვის

Axios არის პოპულარული NPM ბიბლიოთეკა HTTP მოთხოვნებისთვის — Fetch-თან შედარებით გვთავაზობს ავტომატურ JSON პარსინგს, უფრო მარტივ error handling-ს და request/response ინტერცეპტორებს. 

# ინსტალაცია
npm install axios
import axios from "axios";

async function loadProducts() {
  try {
    const response = await axios.get("/api/products"); // ავტომატურად JSON-ად პარსავს
    setProducts(response.data); // მონაცემი პირდაპირ .data-შია, .json() აღარ სჭირდება
  } catch (err) {
    setError(err.message);
  }
}

Axios ასევე იძლევა საშუალებას, ერთხელ დავაყენოთ „ბაზური" კონფიგურაცია (base URL, default headers) — გამოსადეგია, როცა ბევრი endpoint-თან ვმუშაობთ: 

const api = axios.create({
  baseURL: "https://api.example.com",
  headers: { Authorization: "Bearer TOKEN" },
});

const response = await api.get("/products"); // baseURL ავტომატურად ერწყმის

3. Custom Hook

Custom Hook არის ჩვეულებრივი JavaScript ფუნქცია, რომლის სახელი იწყება use-ით და რომელიც სხვა Hook-ებს (useState, useEffect) იყენებს — ეს საშუალებას გვაძლევს, გავიტანოთ განმეორებადი ლოგიკა ცალკე, ხელახლა გამოსაყენებელ ერთეულში. 

// useFetch.js — Custom Hook, რომელიც "ფარავს" loading/error/data ლოგიკას
import { useState, useEffect } from "react";

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    setLoading(true);
    axios.get(url)
      .then(res => setData(res.data))
      .catch(err => setError(err.message))
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading, error };
}

export default useFetch;
// ProductList.jsx — ერთი ხაზი, ნაცვლად 15-ის!
function ProductList() {
  const { data: products, loading, error } = useFetch("/api/products");

  if (loading) return <p>იტვირთება...</p>;
  if (error) return <p>{error}</p>;
  return <ul>{products.map(p => <li key={p.id}>{p.name}</li>)}</ul>;
}

4. Styled Components და Material UI

Styled Components არის ბიბლიოთეკა, რომელიც საშუალებას გვაძლევს, CSS პირდაპირ JS ფაილში დავწეროთ, კომპონენტთან „მიმაგრებული": 

import styled from "styled-components";

const Button = styled.button`
  background: #146B5C;
  color: white;
  padding: 10px 16px;
  border-radius: 8px;
  border: none;

  &:hover {
    background: #1B8A75;
  }
`;

// გამოყენება ჩვეულებრივი კომპონენტივით
<Button>დაწკაპუნება</Button>

Material UI (MUI) კი, Bootstrap-ის React ვერსიის მსგავსად, გვთავაზობს მზა, სრულად აწყობილ React კომპონენტებს (ღილაკები, ფორმები, ცხრილები), Google-ის Material Design-ის სტილში: 

import Button from "@mui/material/Button";

<Button variant="contained" color="primary">
  შენახვა
</Button>

5. Virtual DOM — რატომ არის React სწრაფი

React ინახავს „ვირტუალურ" ასლს DOM-ისა მეხსიერებაში (Virtual DOM). state-ის შეცვლისას, React ჯერ ადარებს ახალ ვირტუალურ DOM-ს ძველთან (diffing) და შემდეგ ნამდვილ ბრაუზერის DOM-ში ცვლის მხოლოდ იმას, რაც რეალურად შეიცვალა — ეს ბევრად უფრო სწრაფია, ვიდრე მთელი გვერდის ხელახლა აგება.

6. React Router — მრავალგვერდიანი ნავიგაცია

SPA-ში „გვერდები" სინამდვილეში ცალკე HTML ფაილები არ არის (როგორც ჩვენს lessonX.html სისტემაში) — React Router მართავს URL-ს და აჩვენებს შესაბამის კომპონენტს, გვერდის ხელახლა ჩატვირთვის გარეშე: 

# ინსტალაცია
npm install react-router-dom
import { BrowserRouter, Routes, Route, Link } from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">მთავარი</Link>
        <Link to="/products">პროდუქტები</Link>
      </nav>

      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/products" element={<ProductList />} />
      </Routes>
    </BrowserRouter>
  );
}

<Link> გამოიყენება <a>-ის ნაცვლად — ის React Router-ს ატყობინებს ნავიგაციაზე, სრული გვერდის გადატვირთვის თავიდან ასაცილებლად.
