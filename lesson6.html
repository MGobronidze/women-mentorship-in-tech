CSS · 06/24

Flexbox, Typography Units, პოზიციონირება

მიმდინარე შეხვედრაზე განვიხილავთ — Flexbox-ს, ტიპოგრაფიის ერთეულებს (px/rem/em/%/vw/clamp), ელემენტების პოზიციონირებას. ბოლოს განხილული იქნება პრაქტიკული სავარჯიშო რეალური Figma დიზაინის მიხედვით.

1. Flexbox — საბაზისო კონცეფცია

Flexbox არის ერთგანზომილებიანი (ერთი განზომილების მიმართულებით — ჰორიზონტალურად ან ვერტიკალურად) განლაგების სისტემა. ის შედგება ორი ძირითადი მახასიათებლისაგან: container (მშობელი ელემენტი, რომელსაც ვუწერთ display: flex) და items (მისი პირდაპირი შვილები). 

.container {
  display: flex;
}

როგორც კი მშობელს დავუწერთ display: flex-ს, ყველა მისი პირდაპირი შვილი ავტომატურად დალაგდება ერთ ხაზზე, გვერდიგვერდ. inline-flex იგივეს აკეთებს, მაგრამ თავად container-ს აქცევს inline ელემენტად (მე-5 გაკვეთილის display-ის მსგავსად).

2. Main Axis და Cross Axis — ღერძების კონცეფცია

Flexbox-ის სიღმისეულად გასააზრებლად, მნიშვნელოვანია გვესმოდეს როგორ მუშაობს — ორი ღერძის (axis) ცნება. ყველა container-ის, მშობლის, თვისება „მუშაობს" ერთ-ერთი ამ ღერძის მიმართ:

  • Main Axis (მთავარი ღერძი) — მიმართულება, რომლითაც items-ი „მისდევს" ერთმანეთს. მას განსაზღვრავს flex-direction. justify-content მუშაობს მთავარი ღერძის მიმართ.
  • Cross Axis (განივი ღერძი) — Main Axis-ის პერპენდიკულარული მიმართულება. align-items და align-content მუშაობს განივი ღერძის მიმართ.
/* flex-direction: row (ნაგულისხმევი) */
/* Main Axis:  →  (მარცხნიდან მარჯვნივ)   */
/* Cross Axis: ↓  (ზემოდან ქვემოთ)        */

.container { display: flex; flex-direction: row; }
/* justify-content აქ ჰორიზონტალურად ალაგებს items-ს */
/* align-items    აქ ვერტიკალურად ალაგებს items-ს    */
/* flex-direction: column — ღერძები 90°-ით "ბრუნდება"! */
/* Main Axis:  ↓  (ზემოდან ქვემოთ)        */
/* Cross Axis: →  (მარცხნიდან მარჯვნივ)   */

.container { display: flex; flex-direction: column; }
/* justify-content ახლა ვერტიკალურად ალაგებს items-ს */
/* align-items    ახლა ჰორიზონტალურად ალაგებს items-ს */

შენიშნა: justify-content ყოველთვის Main Axis-ზეა პასუხისმგებელი, align-items/align-content — ყოველთვის Cross Axis-ზე. როცა flex-direction იცვლება row-დან column-ზე, ეს ორი ღერძი ერთმანეთს „ენაცვლება".

3. Flex Container-ის თვისებები — სრული ჩამონათვალი

flex-direction და flex-wrap

.container {
  display: flex;
  flex-direction: row;            /* row | row-reverse | column | column-reverse */
  flex-wrap: nowrap;              /* nowrap | wrap | wrap-reverse */

  /* flex-flow — shorthand ორივესთვის ერთად */
  flex-flow: row wrap;            /* flex-direction flex-wrap */
}
  • row-reverse/column-reverse — იგივე მიმართულება, მაგრამ საპირისპირო თანმიმდევრობით (ვიზუალურად, HTML-ის შეცვლის გარეშე).
  • wrap — items გადადის ახალ ხაზზე, თუ container-ში ადგილი აღარ ჰყოფნის; wrap-reverse — იგივე, მაგრამ ხაზები საპირისპირო მიმართულებით ლაგდება.

justify-content — Main Axis-ის განლაგება

.container {
  justify-content: flex-start;    /* ნაგულისხმევი — items იწყება Main Axis-ის დასაწყისიდან */
  justify-content: flex-end;      /* items იკრიბება ბოლოში */
  justify-content: center;        /* items ცენტრირებულია */
  justify-content: space-between; /* პირველი/ბოლო — კიდეებზე, დანარჩენი — თანაბრად შორის */
  justify-content: space-around;  /* თანაბარი სივრცე ყოველი item-ის გარშემო */
  justify-content: space-evenly;  /* ზუსტად თანაბარი სივრცე ყველგან, კიდეების ჩათვლითაც */
}

align-items — Cross Axis-ის განლაგება (ერთი ხაზის შიგნით)

.container {
  align-items: stretch;     /* ნაგულისხმევი — items "იჭიმება" container-ის სრულ სიმაღლეზე */
  align-items: flex-start;  /* items იწყება Cross Axis-ის დასაწყისიდან */
  align-items: flex-end;    /* items იკრიბება ბოლოში */
  align-items: center;      /* items ცენტრირებულია განივად */
  align-items: baseline;    /* items ლაგდება ტექსტის baseline-ის მიხედვით (განსხვავებული font-size-ების დროსაც თანაბრად) */
}

align-content — Cross Axis-ის განლაგება (ხაზებს შორის)

ხშირი გაუგებრობა: align-content მუშაობს მხოლოდ მაშინ, როცა container-ს აქვს flex-wrap: wrap და items რამდენიმე ხაზზეა გადანაწილებული, და Cross Axis-ზე დამატებითი, გამოუყენებელი სივრცე რჩება. align-items ალაგებს items-ს ერთი ხაზის შიგნით, ხოლო align-content — თავად ხაზებს ერთმანეთის მიმართ. 

.container {
  flex-wrap: wrap;
  align-content: space-between; /* flex-start | flex-end | center | space-between | space-around | space-evenly | stretch */
}

gap, row-gap, column-gap

.container {
  gap: 16px;              /* მანძილი items-ს შორის ორივე ღერძზე — margin-ის გარეშე! */
  row-gap: 20px;           /* მანძილი მხოლოდ ხაზებს შორის (wrap-ის დროს) */
  column-gap: 12px;        /* მანძილი მხოლოდ სვეტებს შორის */

  /* shorthand: gap: row-gap column-gap; */
  gap: 20px 12px;
}

4. Flex Items-ის თვისებები — სრული ჩამონათვალი

ეს თვისებები ეწერება ცალკეულ item-ს, არა container-ს:

order და align-self

.item {
  order: 2;              /* ცვლის ვიზუალურ თანმიმდევრობას (ნაგულისხმევი ყველასთვის: 0) */
  align-self: flex-end;  /* ერთი კონკრეტული item-ის align-items-ის "გადაფარვა" */
}

flex-grow, flex-shrink, flex-basis

ეს სამი თვისება განსაზღვრავს, როგორ გაინაწილებენ ელემენტები ერთმანეთს შორის container-ის ხელმისაწვდომ სივრცეს: 

.item {
  flex-basis: 200px;  /* item-ის საწყისი ზომა, "growing/shrinking"-მდე */
  flex-grow: 1;        /* რამდენად "იზრდება" item, თუ container-ში ზედმეტი სივრცეა (თანაფარდობა) */
  flex-shrink: 1;      /* რამდენად "იკუმშება" item, თუ container-ში სივრცე არ ჰყოფნის (თანაფარდობა) */
}

flex-grow და flex-shrink არის თანაფარდობები, არა აბსოლუტური მნიშვნელობები. მაგალითად, თუ სამ item-ს აქვს flex-grow: 1, 2, 1 — დამატებითი სივრცე გადანაწილდება პროპორციით 1:2:1 (მეორეს ორჯერ მეტი დამატებითი სივრცე ერგება): 

<div class="row">
  <div class="a">A</div>
  <div class="b">B</div>
  <div class="c">C</div>
</div>

/* CSS */
.row { display: flex; gap: 8px; }
.a { flex-grow: 1; }  /* იღებს 1 ნაწილს დამატებითი სივრციდან */
.b { flex-grow: 2; }  /* იღებს 2-ჯერ მეტს, ვიდრე A ან C */
.c { flex-grow: 1; }  /* იღებს 1 ნაწილს */

flex — shorthand (რეკომენდებული ფორმა)

პრაქტიკაში, სამივე თვისებას ჩვეულებრივ ერთად, flex shorthand-ით ვწერთ: flex: [grow] [shrink] [basis]. 

.item { flex: 1 1 200px; }  /* გაიზრდება, შემცირდება, საწყისი ზომა 200px */

.item { flex: 1; }          /* shorthand "flex: 1 1 0%" — ტოლი გაყოფა, საწყისი ზომის იგნორირებით */
.item { flex: auto; }       /* shorthand "flex: 1 1 auto" — იზრდება/იკუმშება, საწყისი ზომა content-ის მიხედვით */
.item { flex: none; }       /* shorthand "flex: 0 0 auto" — არც იზრდება, არც იკუმშება — ფიქსირებული ზომა */
Shorthand grow shrink basis გამოყენების შემთხვევა
flex: 1 1 1 0% თანაბრად გაყოფილი სვეტები/ბარათები
flex: auto 1 1 auto content-ის ზომიდან იზრდება/იკუმშება
flex: none 0 0 auto ფიქსირებული ზომის sidebar/icon

5. პრაქტიკული მაგალითები

5.1 — ნავიგაციის ზოლი

<nav class="navbar">
  <div class="logo">front-end-course</div>
  <ul class="links">
    <li><a href="#">მთავარი</a></li>
    <li><a href="#">სილაბუსი</a></li>
  </ul>
</nav>

/* CSS */
.navbar {
  display: flex;
  justify-content: space-between; /* ლოგო მარცხნივ, ბმულები მარჯვნივ */
  align-items: center;
}
.links {
  display: flex;
  gap: 24px; /* მანძილი ელემენტებს შორის, margin-ის გარეშე */
}

5.2 — რესპონსიული ბარათების რიგი (flex-grow/shrink/basis)

3 ბარათი, რომლებიც თანაბრად იზიარებენ სივრცეს, მაგრამ არასდროს იკუმშება 220px-ზე ნაკლებზე — ამის ნაცვლად, ახალ ხაზზე გადადის (flex-wrap-თან ერთად): 

.card-row {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}
.card {
  flex: 1 1 220px; /* გაიზრდება, შემცირდება, მაგრამ საწყისი/მინიმალური ~220px */
}

6. Positioned Elements

position თვისება განსაზღვრავს, როგორ „გაერევა" ელემენტი ჩვეულებრივ დინებაში (document flow) და გამოიყენება top/right/bottom/left-თან ერთად:

  • staticეს არის CSS-ის სტანდარტული მდგომარეობა. ელემენტი განთავსებულია ზუსტად იმ ადგილას, სადაც HTML-ის იერარქიაში წერია. top/left. (შენიშვნა: top/right/bottom/left/z-index: ამ თვისებებს არანაირი ეფექტი არ აქვს static ელემენტზე.)
  • relative — ელემენტი „გადაინაცვლებს" საკუთარი, ნაგულისხმევი პოზიციიდან, მაგრამ ისევ იკავებს ორიგინალურ ადგილს დინებაში (სხვები „ხედავენ" მას, თითქოს არსად წასულა).
  • absolute — ელემენტი მთლიანად ამოვარდება დინებიდან და პოზიციონირდება უახლოესი relative (ან absolute/fixed/sticky) წინაპრის მიმართ. (თუ ასეთი წინაპარი არ არსებობს: მდებარეობას აიღებს უშუალოდ HTML დოკუმენტის პირველადი კონტეინერის ( / Viewport) მიმართ.)
  • fixed — პოზიციონირდება ბრაუზერის ფანჯრის მიმართ და „მიმაგრებულია" — არ მოძრაობს სქროლვისას.
  • sticky — ჰიბრიდი: იქცევა როგორც relative, სანამ არ მიაღწევს განსაზღვრულ ზღვარს (მაგ. top: 0), შემდეგ იქცევა როგორც fixed.
/* sticky ჰედერი — ზუსტად ისე, როგორც ამ საიტის ნავიგაციაშია გამოყენებული */
.site-header {
  position: sticky;
  top: 0;
  z-index: 50;
}

/* badge, რომელიც card-ის კუთხეში „ეკვრის" */
.card { position: relative; }
.badge {
  position: absolute;
  top: 8px;
  right: 8px;
}

7. Typography Units — px, rem, em, %, vw/vh, clamp()

ტექსტის (და ხშირად სხვა თვისებების) ზომების ერთეულის სწორად არჩევა პირდაპირ გავლენას ახდენს საიტის ხელმისაწვდომობასა (accessibility) და რესპონსიულობაზე.

px — აბსოლუტური ერთეული

px ყოველთვის ერთი და იგივე, ფიქსირებული ზომაა — არ იცვლება არაფრის მიხედვით. 

p { font-size: 16px; } /* ყოველთვის ზუსტად 16px, ყველგან */

რატომ არ არის რეკომენდებული ტექსტისთვის: ბრაუზერებს აქვთ პარამეტრი (Accessibility Settings), რომლითაც მომხმარებელს შეუძლია გაზარდოს ნაგულისხმევი ფონტის ზომა (მაგ. მხედველობის დაქვეითების გამო). px-ით ჩაწერილი ტექსტი ამ პარამეტრს არ ემორჩილება — რჩება ფიქსირებული, მიუხედავად მომხმარებლის პარამეტრებისა. rem-ით ჩაწერილი კი — მასშტაბირდება.

rem — Root-ის მიმართ (Root EM)

rem ყოველთვის ითვლება <html> (root) ელემენტის font-size-ის მიმართ — ნაგულისხმევად ეს არის 16px თითქმის ყველა ბრაუზერში: 

html { font-size: 16px; } /* ეს ჩვეულებრივ ნაგულისხმევია, ხელით არ სჭირდება წერა */

h1 { font-size: 2rem; }    /* 2 × 16px = 32px */
p  { font-size: 1rem; }    /* 1 × 16px = 16px */
small { font-size: 0.875rem; } /* 0.875 × 16px = 14px */

რატომ არის ინდუსტრიის სტანდარტი: rem ყოველთვის ერთსა და იმავე „წყაროს" (root) მიემართება, დაბუდვის (nesting) სიღრმის მიუხედავად — ამიტომ პროგნოზირებადია. ამავე დროს, px-ისგან განსხვავებით, რეაგირებს მომხმარებლის ბრაუზერის accessibility-პარამეტრებზე, თუ მან root-ის font-size შეცვალა.

em — მშობლის მიმართ

em ითვლება უშუალო მშობელი ელემენტის font-size-ის მიმართ — არა root-ის, არამედ იმ კონკრეტული ელემენტისა, რომელშიც ის ჩადგმულია. 

.card { font-size: 18px; }
.card .title { font-size: 1.5em; } /* 1.5 × 18px = 27px (.card-ის მიმართ) */

Cascading პრობლემა — რატომ „მრავლდება" em

em-ის მთავარი „ხაფანგი" — ის აგრძელებს ერთმანეთზე გამრავლებას, თუ ჩადგმული ელემენტების ჯაჭვშია გამოყენებული: 

<div class="a">
  <div class="b">
    <div class="c">ტექსტი</div>
  </div>
</div>

/* CSS */
.a { font-size: 16px; }
.b { font-size: 1.5em; } /* 16 × 1.5 = 24px */
.c { font-size: 1.5em; } /* 24 × 1.5 = 36px — არა 16 × 1.5 = 24px, როგორც ერთი შეხედვით ჩანს! */

ყოველი ჩადგმის დონე ამრავლებს წინას — გაუთვალისწინებელი, „გაქცეული" ზომები რთულ, ღრმად ჩადგმულ კომპონენტებში. rem ამ პრობლემას მთლიანად გამორიცხავს, რადგან ყოველთვის root-ს მიემართება, ჩადგმის დონის მიუხედავად.

საუკეთესო გამოყენების შემთხვევა em-ისთვის: როცა შეგნებულად გინდა, რომ თვისება (ჩვეულებრივ padding/margin, არა font-size) პროპორციული იყოს კონკრეტული კომპონენტის ტექსტის ზომის მიმართ — მაგ. ღილაკის padding, რომ დიდი ტექსტის ღილაკს ავტომატურად ჰქონდეს დიდი padding-იც: 

.btn {
  font-size: 1rem;      /* rem — პროგნოზირებადი ტექსტის ზომა */
  padding: 0.75em 1.5em; /* em — padding "მისდევს" ღილაკის font-size-ს */
}
.btn.large { font-size: 1.25rem; } /* padding ავტომატურად პროპორციულად გაიზრდება, ხელახლა წერის გარეშე */

% და Viewport Units (vw, vh) და clamp()

% მუშაობს em-ის მსგავსად — მშობლის ზომის მიმართ (ჩვეულებრივ width/height-სთვის გამოიყენება, არა ტექსტისთვის). vw/vh კი ეთვლის ბრაუზერის ვიუპორტს (ხილულ ეკრანს): 1vw = ვიუპორტის სიგანის 1%, 1vh = სიმაღლის 1%. 

.hero-title {
  font-size: 5vw; /* ეკრანის სიგანის მიხედვით მასშტაბირდება — მაგრამ საშიშია მარტო! */
}
/* პრობლემა: ძალიან პატარა ეკრანზე — წაუკითხავად პატარა; ძალიან დიდზე — გადაჭარბებულად დიდი */

სწორედ ამის გადასაჭრელად არსებობს clamp() — თანამედროვე, რეკომენდებული ფუნქცია რესპონსიული ტიპოგრაფიისთვის: 

font-size: clamp(მინიმუმი, სასურველი (fluid), მაქსიმუმი);

/* პრაქტიკული მაგალითი */
h1 {
  font-size: clamp(1.75rem, 4vw + 1rem, 3rem);
  /* არასდროს იქნება 1.75rem-ზე ნაკლები */
  /* არასდროს იქნება 3rem-ზე მეტი           */
  /* შუალედში კი გლუვად "მიჰყვება" ეკრანის სიგანეს (4vw + 1rem) */
}

ეს ერთი ხაზი ანაცვლებს ბევრ @media query-ს, რომლებიც სხვადასხვა breakpoint-ზე სხვადასხვა ფიქსირებულ font-size-ს აწესებდა — clamp() გლუვად, უწყვეტად „მიჰყვება" ეკრანის ზომას, ორ ზღვარს შორის.

ერთეულების შედარების ცხრილი

ერთეული ითვლება გამოყენება
px აბსოლუტური, ფიქსირებული border-width, box-shadow — არა ტექსტი
rem Root (<html>)-ის მიმართ font-size — სტანდარტული არჩევანი
em უშუალო მშობლის მიმართ padding/margin, კომპონენტის font-size-ის პროპორციულად
% მშობლის ზომის მიმართ width/height — layout-ისთვის
vw/vh ვიუპორტის ზომის მიმართ fluid ზომები — ყოველთვის clamp()-თან ერთად
clamp() min/preferred/max კომბინაცია რესპონსიული ტიპოგრაფია — თანამედროვე სტანდარტი

px → rem კონვერტაცია — ფორმულა და ცხრილი

თუ root-ის font-size ნაგულისხმევი 16px-ია (როგორც თითქმის ყოველთვის), კონვერტაციის ფორმულა მარტივია:

პრაქტიკული რჩევა: Figma-ს დიზაინში ზომები თითქმის ყოველთვის px-შია მითითებული (Inspect პანელში, მე-5 გაკვეთილიდან ნაცნობი). კოდში გადატანისას, ტექსტის ზომებისთვის ეს px კონვერტირდება rem-ად ზემოთ მოცემული ფორმულით.

8. პრაქტიკული სავარჯიშო — Figma დიზაინის მიხედვით

ახლა დროა, ყველაფერი ერთად გამოვსცადოთ — რეალურ, მზა დიზაინზე. საილუსტრაციო პროექტი:

Figma Design — Responsive (გახსენი ახალ ტაბში)

  1. გახსენი ბმული და გადართე Dev Mode-ზე (Shift + D, ან იხ. მე-5 გაკვეთილის Figma სექცია).
  2. მონიშნე კონკრეტული ფრეიმი/კომპონენტი Layers პანელში — მარჯვნივ გამოჩნდება ზუსტი px-მნიშვნელობები (padding, gap, font-size).
  3. თითოეული ტექსტის font-size გადაიყვანე rem-ად ზემოთ მოცემული ფორმულით.
  4. დაადგინე, დიზაინი Flexbox-ის რომელ თვისებებს „ჰგავს" — მწკრივია თუ სვეტი? თანაბრადაა გადანაწილებული სივრცე (justify-content) თუ item-ებს შორის ფიქსირებული gap-ია?

გაიმეორე — შეკითხვები

  1. რა განსხვავებაა Main Axis-სა და Cross Axis-ს შორის, და რატომ „იცვლებიან" ისინი flex-direction: column-ზე გადასვლისას?
  2. რა განსხვავებაა align-items-სა და align-content-ს შორის?
  3. რას აკეთებს flex: 1 — რომელ სამ თვისებას შეესაბამება ეს shorthand?
  4. რატომ არ არის რეკომენდებული ტექსტის ზომების px-ით განსაზღვრა accessibility-ის თვალსაზრისით?
  5. რატომ „მრავლდება" em ჩადგმულ ელემენტებში, და როგორ გვიხსნის ამ პრობლემას rem?
  6. რას აკეთებს clamp() და რატომ სჯობს მას მარტო vw-ის გამოყენებას ტიპოგრაფიისთვის?

პრაქტიკული დავალებები

  1. შექმენი 3 ყუთი ერთ container-ში, დაუყენე display: flex და გამოსცადე justify-content-ის ყველა მნიშვნელობა (flex-start-დან space-evenly-მდე).
  2. იგივე container-ს დაუყენე flex-direction: column და დააკვირდი, რომელი თვისება (justify-content თუ align-items) აკონტროლებს ახლა რომელ მიმართულებას.
  3. შექმენი 4 item, სხვადასხვა flex-grow მნიშვნელობით (მაგ. 1, 2, 1, 3) და დააკვირდი, როგორ ნაწილდება დამატებითი სივრცე.
  4. ააწყვე ნავიგაციის ზოლი ლოგოთი მარცხნივ და ბმულებით მარჯვნივ, space-between-ის გამოყენებით.
  5. ააწყვე 3-ბარათიანი რიგი flex: 1 1 220px-ის გამოყენებით — შეამოწმე, რომ ვიწრო ეკრანზე ისინი ახალ ხაზზე გადადის.
  6. შექმენი card, რომელშიც ერთი „badge" ელემენტი position: absolute-ით მიმაგრებულია კუთხეში.
  7. დაწერე ერთი და იგივე სათაური სამივე ერთეულით — px, rem და clamp() — და ბრაუზერის Zoom/Font Size პარამეტრებში შეამოწმე, რომელი რეაგირებს ცვლილებაზე.
  8. (რთული) გახსენი Figma-ს დიზაინის ბმული, Dev Mode-ში ამოიღე ერთი კონკრეტული კომპონენტის ზუსტი px-მნიშვნელობები (padding, gap, font-size) და ააგე ის Flexbox-ითა და rem-ით — ამ გაკვეთილის „profile-card" მაგალითის პატერნის გამოყენებით.
