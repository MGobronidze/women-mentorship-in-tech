HTML · 03/24

HTML სიები, სურათები, ფორმები და მედია

HTML მოდულის ბოლო გაკვეთილში შევისწავლით როგორ ჩავაშენოთ სურათები, სიები, ვიდეოები და ფორმები პროექტში.

1. სიები — <ul> და <ol>

სიები გამოსადეგია ნებისმიერი ჩამონათვლის სემანტიკურად სწორად აღსანიშნად — ნავიგაციის ბმულებიდან რეცეპტის ინგრედიენტებამდე. HTML გვთავაზობს ორ ძირითად ტიპს:

  • <ul> (Unordered List) — არადალაგებული სია, ელემენტების თანმიმდევრობას მნიშვნელობა არ აქვს (მარკერებით/bullet points).
  • <ol> (Ordered List) — დალაგებული სია, სადაც თანმიმდევრობა მნიშვნელოვანია (ავტომატურად დანომრილი).
  • <li> (List Item) — ორივე ტიპის სიაში ცალკეული ელემენტისთვის, ერთადერთი დასაშვები პირდაპირი შვილი.
<!-- Unordered List — თანმიმდევრობას მნიშვნელობა არ აქვს -->
<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>

<!-- Ordered List — თანმიმდევრობა მნიშვნელოვანია -->
<ol>
  <li>დააინსტალირე VS Code</li>
  <li>შექმენი index.html</li>
  <li>გახსენი Live Server-ით</li>
</ol>

<ol>-ის დამატებითი ატრიბუტები

<!-- start — საიდან დაიწყოს ნუმერაცია -->
<ol start="5">
  <li>მეხუთე ნაბიჯი</li>
  <li>მეექვსე ნაბიჯი</li>
</ol>

<!-- reversed — კლებადი ნუმერაცია (მაგ. ტოპ-სიებისთვის) -->
<ol reversed>
  <li>მე-3 ადგილი</li>
  <li>მე-2 ადგილი</li>
  <li>1-ლი ადგილი</li>
</ol>

<!-- type — ნუმერაციის სტილი: 1 | A | a | I | i -->
<ol type="A">
  <li>ვარიანტი A</li>
  <li>ვარიანტი B</li>
</ol>

ჩადგმული (Nested) სიები

სია შეიძლება მოთავსდეს სხვა სიის <li>-ს შიგნით — ქმნის იერარქიულ სტრუქტურას:

<ul>
  <li>Front-end
    <ul>
      <li>HTML</li>
      <li>CSS</li>
    </ul>
  </li>
  <li>Back-end</li>
</ul>

სემანტიკური წესი (up-to-date პრაქტიკა): სია გამოიყენე მაშინ, როცა კონტენტი რეალურად ჩამონათვალია (screen reader ამბობს „სია, 3 ელემენტი" და ეხმარება ორიენტირებას) — არა მხოლოდ ვიზუალური დაშორების მისაღწევად. დაშორებისთვის CSS-ის gap/margin გამოიყენე, არა ცარიელი <li>-ები. ნავიგაციის ბმულების სია (<nav><ul>...</ul></nav>) — ზუსტად ეს პატერნია, რომელსაც ეს საიტიც იყენებს თავის ნავიგაციაში.

2. სურათები — <img> და თანამედროვე საუკეთესო პრაქტიკები

<img> უკვე მოკლედ ვახსენეთ წინა გაკვეთილში (სურათი, როგორც ბმული) — ახლა კი დეტალურად განვიხილოთ, მათ შორის თანამედროვე, პერფორმანსზე ორიენტირებული ატრიბუტები, რომლებსაც დღეს ყველა სერიოზული საიტი იყენებს. 

<img
  src="course-cover.jpg"
  alt="Front-end კურსის ყდის სურათი"
  width="1200"
  height="630">
  • src და alt — აუცილებელია ყოველთვის (alt — ხელმისაწვდომობისა და SEO-სთვის, იხ. მე-2 გაკვეთილი).
  • width/height — ყოველთვის მიუთითე, თუნდაც CSS-ით სხვა ზომას აყენებდე. ბრაუზერი წინასწარ ითვლის სურათის თანაფარდობას (aspect ratio) და ჯერ კიდევ ჩატვირთვამდე „იჯავშნის" სივრცეს — ეს ხელს უშლის Layout Shift-ს (გვერდის „ხტომას" სურათის ჩატვირთვისას).

loading — ზარმაცი ჩატვირთვა

loading="lazy" ეუბნება ბრაუზერს, არ ჩატვირთოს სურათი, სანამ მომხმარებელი მასთან ახლოს არ ჩამოსქროლავს — ეს აჩქარებს საწყისი გვერდის ჩატვირთვას: 

<img src="gallery-photo.jpg" alt="გალერეის ფოტო"
  width="800" height="600"
  loading="lazy">

წესი: გამოიყენე loading="lazy" მხოლოდ ეკრანს ქვემოთ მდებარე სურათებზე. პირველად ხილულ სურათებზე (განსაკუთრებით hero/ბანერზე) ის არ უნდა გამოიყენო — ეს შენელებდა ყველაზე მნიშვნელოვანი, პირველივე ხილული სურათის გამოჩენას.

fetchpriority — ჩატვირთვის პრიორიტეტი

fetchpriority (თანამედროვე, ფართოდ მხარდაჭერილი ატრიბუტი) ეუბნება ბრაუზერს, რომელი სურათი ჩატვირთოს უპირველესად — გამოსადეგია გვერდის ყველაზე მთავარი, თვალშისაცემი სურათისთვის (მაგ. hero ბანერი): 

<!-- ყველაზე მნიშვნელოვანი სურათი — მაღალი პრიორიტეტი, ზარმაცი ჩატვირთვის გარეშე -->
<img src="hero-banner.jpg" alt="მთავარი ბანერი"
  width="1600" height="600"
  fetchpriority="high">

<!-- ნაკლებად მნიშვნელოვანი სურათი — დაბალი პრიორიტეტი -->
<img src="sidebar-promo.jpg" alt="აქცია"
  width="300" height="200"
  fetchpriority="low">

წესი: fetchpriority="high" და loading="lazy" არასდროს არ გამოიყენება ერთად ერთსა და იმავე სურათზე — ეს ლოგიკურად ეწინააღმდეგება ერთმანეთს (ერთი ამბობს „მალე ჩატვირთე", მეორე — „დააგვიანე ჩატვირთვა"). გამოიყენე fetchpriority="high" მხოლოდ 1-2 ყველაზე მნიშვნელოვან სურათზე გვერდზე.

srcset და <picture> — რესპონსიული სურათები

სხვადასხვა ეკრანის ზომაზე/სიმკვრივეზე შესაძლებელია განსხვავებული ზომის სურათის მიწოდება — მობილურზე დიდი დესკტოპ-სურათის ჩატვირთვა ტყუილად ხარჯავს ტრაფიკს: 

<!-- srcset — ბრაუზერი თავად ირჩევს შესაბამის ზომას -->
<img
  src="photo-800.jpg"
  srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="პროდუქტის ფოტო"
  width="800" height="600">
<!-- <picture> — თანამედროვე ფორმატის მიწოდება, ძველი ბრაუზერისთვის fallback-ით -->
<picture>
  <source srcset="photo.avif" type="image/avif">
  <source srcset="photo.webp" type="image/webp">
  <img src="photo.jpg" alt="პროდუქტის ფოტო"
    width="800" height="600">
</picture>

AVIF და WebP არის თანამედროვე სურათის ფორმატები, რომლებიც JPEG/PNG-თან შედარებით ბევრად ნაკლებ ადგილს იკავებენ, იმავე ვიზუალური ხარისხით. ბრაუზერი <picture>-ში თავად ირჩევს პირველ ფორმატს, რომელსაც უჭერს მხარს — ხოლო ჩვეულებრივი <img> ბოლოში ყოველთვის რჩება, როგორც უნივერსალური fallback ყველა ბრაუზერისთვის.

3. ტეგი <form> და მისი ატრიბუტები

ფორმის ყველა ელემენტი ჩასმულია <form> ტეგში. ორი ატრიბუტი განსაზღვრავს, თუ სად და როგორ გაეგზავნება მონაცემები სერვერს:

  • action — მისამართი, სადაც გაეგზავნება ფორმის მონაცემები.
  • method — HTTP მეთოდი: GET (მონაცემები ჩანს URL-ში) ან POST (მონაცემები request body-ში, გამოსადეგია სენსიტიური მონაცემებისთვის).
<form action="/submit" method="POST">
  <!-- ფორმის ველები აქ განთავსდება -->
</form>

4. <label> — ველების „წარმდგენი"

<label> უწყვილდება input-ს for ატრიბუტით (რომელიც უტოლდება input-ის id-ს). ეს accessibility-სთვისაც აუცილებელია — screen reader ხმამაღლა წარმოთქვამს ველის დანიშნულებას. 

<label for="email">ელფოსტა</label>
<input type="email" id="email" name="email">

name ატრიბუტი კი „გასაღებია", რომლის ქვეშაც მონაცემი ჩაეწერება, როცა ფორმა სერვერს გაეგზავნება.

5. <input>-ის ტიპები

type ატრიბუტი განსაზღვრავს ველის სახეს. ბრაუზერი ავტომატურად ამოწმებს ფორმატს ზოგიერთი ტიპისთვის (მაგ. email): 

<label for="name">სახელი</label>
<input type="text" id="name" name="name" placeholder="შენი სახელი" required>

<label for="age">ასაკი</label>
<input type="number" id="age" name="age" min="1" max="120">

<label for="agree">ვეთანხმები წესებს</label>
<input type="checkbox" id="agree" name="agree">

ყველაზე ხშირად გამოსაყენებელი ტიპებია:

  • text, email, password, number, tel
  • checkbox (რამდენიმეს არჩევა), radio (ერთი ვარიანტი ჯგუფიდან — ყველა ერთი ჯგუფის input-ს ერთი name უნდა ჰქონდეს)
  • date, file, submit (ღილაკი ფორმის გასაგზავნად)

დამატებითი ატრიბუტები: placeholder (მინიშნება), required (სავალდებულო ველი), value (წინასწარ შევსებული მნიშვნელობა).

6. სავარჯიშო: მარტივი კონტაქტის ფორმა

<form action="/contact" method="POST">
  <label for="fullname">სრული სახელი</label>
  <input type="text" id="fullname" name="fullname" required>

  <label for="email">ელფოსტა</label>
  <input type="email" id="email" name="email" required>

  <button type="submit">გაგზავნა</button>
</form>

7. HTML მედია: <audio> და <video>

HTML5-მა შემოგვთავაზა ჩაშენებული ტეგები მედია კონტენტისთვის — დამატებითი პლაგინების გარეშე. 

<video width="640" controls>
  <source src="lesson-intro.mp4" type="video/mp4">
  ბრაუზერი არ უჭერს მხარს ვიდეო ტეგს.
</video>

<audio controls>
  <source src="podcast-episode.mp3" type="audio/mpeg">
  ბრაუზერი არ უჭერს მხარს audio ტეგს.
</audio>

ატრიბუტი controls უჩენს მოთამაშეს სტანდარტულ პულტს. <source>-ის შემდეგ ჩაწერილი ტექსტი (fallback) ჩანს მხოლოდ იმ ბრაუზერებში, რომლებმაც ტეგი ვერ ამოიცნეს.

გაიმეორე — შეკითხვები

  1. რა განსხვავებაა <ul>-სა და <ol>-ს შორის — როდის ავირჩევდი თითოეულს?
  2. რატომ არ არის კარგი პრაქტიკა სიის გამოყენება მხოლოდ ვიზუალური დაშორებისთვის?
  3. რატომ არის მნიშვნელოვანი <img>-ზე width/height-ის მითითება, თუნდაც CSS-ით სხვა ზომას აყენებდე?
  4. რომელ სურათზე გამოიყენებდი loading="lazy"-ს და რომელზე — არასდროს? რატომ?
  5. რას აკეთებს srcset ატრიბუტი და რატომ სჯობს მას ერთი დიდი სურათის ყველგან გამოყენებას?

პრაქტიკული დავალებები

  1. შექმენი <ul> სია შენი 5 საყვარელი ტექნოლოგიით, და <ol> სია 3-ნაბიჯიანი ინსტრუქციით (მაგ. „როგორ გავხსნა Live Server").
  2. გამოსცადე <ol>-ის start, reversed და type="A" ატრიბუტები ცალ-ცალკე სიაზე და დააკვირდი განსხვავებას.
  3. ააწყვე ჩადგმული სია — მინიმუმ 2 დონით (მაგ. კურსის მოდულები, თითოეულს ქვეშ — გაკვეთილების სია).
  4. ჩასმენე სურათი სწორი alt, width და height ატრიბუტებით, და დაუმატე loading="lazy".
  5. შექმენი ფორმა ორი ველით — სახელი და ელფოსტა — თითოეულს დაუყოლე <label>.
  6. დაამატე password ველი და required ატრიბუტი სავალდებულო ველებზე.
  7. შექმენი radio ჯგუფი 3 ვარიანტით (ერთი საერთო name-ით) და checkbox ერთი დამატებითი პირობით.
  8. ჩასმენე ვიდეო ან audio ელემენტი controls ატრიბუტით და fallback ტექსტით.
  9. (რთული) ააწყვე მარტივი „პროდუქტის ბარათი" — <picture>-ის გამოყენებით (AVIF/WebP + JPEG fallback), <ul> სიით მახასიათებლებისთვის, და რეგისტრაციის ფორმა 5+ input-ის ტიპით (მათ შორის date და file).
