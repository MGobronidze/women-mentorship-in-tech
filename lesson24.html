React · 24/24 — საბოლოო გაკვეთილი

React Forms, ავტორიზაცია, E-commerce საბოლოო პროექტი

კურსის ბოლო გაკვეთილი აერთიანებს ყველაფერს — HTML-იდან React-მდე — ერთ პრაქტიკულ, რეალისტურ პროექტში: მარტივ E-commerce აპლიკაციაში.

1. React Form და ვალიდაცია

React-ში ფორმის ველები ჩვეულებრივ არის controlled — მათი მნიშვნელობა ინახება state-ში, არა თავად DOM-ში (განსხვავებით ჩვეულებრივი HTML ფორმებისგან): 

function ContactForm() {
  const [email, setEmail] = useState("");
  const [error, setError] = useState("");

  function handleSubmit(event) {
    event.preventDefault(); // ისევე, როგორც vanilla JS-ში (მე-16 გაკვეთილი)

    if (!email.includes("@")) {
      setError("გთხოვთ, მიუთითოთ ვალიდური ელფოსტა");
      return;
    }
    setError("");
    console.log("იგზავნება:", email);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />
      {error && <p className="error">{error}</p>}
      <button type="submit">გაგზავნა</button>
    </form>
  );
}

value={email} + onChange წყვილი — ეს არის „controlled input"-ის ფორმულა: React state ყოველთვის „წყაროა ჭეშმარიტებისა" (source of truth) input-ის მიმდინარე მნიშვნელობისთვის.

2. საბაზისო ავტორიზაციის ლოგიკა

რეალურ პროექტში ავტორიზაცია მოიცავს სერვერს, ტოკენებს და უსაფრთხოების ბევრ დეტალს — მაგრამ საბაზისო, front-end მხარეს, პატერნი ასე გამოიყურება (მე-20 გაკვეთილის storage-ცოდნაზე დაფუძნებული): 

function LoginForm({ onLogin }) {
  const [username, setUsername] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    // რეალურ აპლიკაციაში აქ იქნებოდა API მოთხოვნა (axios.post("/login", ...))
    sessionStorage.setItem("user", JSON.stringify({ username }));
    onLogin(username); // მშობელი კომპონენტისთვის ცნობა, რომ ავტორიზაცია მოხდა
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={username} onChange={(e) => setUsername(e.target.value)} />
      <button type="submit">შესვლა</button>
    </form>
  );
}

„დაცული" (protected) გვერდები React Router-ში ჩვეულებრივ სტატუსს ამოწმებენ და საჭიროების შემთხვევაში ავტომატურად გადამისამართებენ login გვერდზე — ეს ლოგიკა ჩვეულებრივ იტანება ერთ, ხელახლა გამოსაყენებელ კომპონენტში.

3. E-commerce აპლიკაციის არქიტექტურა

დავხატოთ, საიდან შედგება მარტივი მაღაზიის აპლიკაცია — ეს არის ის სტრუქტურა, რომელსაც დამოუკიდებლად ააშენებ ამ გაკვეთილის ბოლო დავალებაში: 

src/

├── App.jsx                // BrowserRouter + Routes

Cart-ის მდგომარეობა (რომელი პროდუქტებია კალათაში) საჭიროებს „გაზიარებას" ბევრ კომპონენტს შორის (ProductCard-ს „დამატება" ღილაკიდან, Navbar-ს რაოდენობის ჩვენებამდე, Cart გვერდამდე) — ამისთვის React გვთავაზობს Context API-ს (props-ის ყოველ დონეზე ხელით გადაცემის თავიდან ასაცილებლად): 

// CartContext.jsx — გამარტივებული მაგალითი
import { createContext, useState, useContext } from "react";

const CartContext = createContext();

export function CartProvider({ children }) {
  const [items, setItems] = useState([]);

  function addToCart(product) {
    setItems(prev => [...prev, product]); // spread — უცვლელი (immutable) განახლება, მე-14 გაკვეთილიდან
  }

  return (
    <CartContext.Provider value={{ items, addToCart }}>
      {children}
    </CartContext.Provider>
  );
}

export function useCart() {
  return useContext(CartContext); // custom hook, კონტექსტთან წვდომისთვის
}
// ProductCard.jsx — ნებისმიერ სიღრმეზე, props-ის გადაცემის გარეშე
function ProductCard({ product }) {
  const { addToCart } = useCart();
  return (
    <div className="card">
      <h3>{product.name}</h3>
      <button onClick={() => addToCart(product)}>კალათაში დამატება</button>
    </div>
  );
}

4. React კომპონენტების, როუტინგისა და Material UI შერწყმა

ერთ პატარა მაგალითში — ProductList გვერდი, რომელიც იყენებს Custom Hook-ს მონაცემებისთვის, Material UI-ს ღილაკებისთვის და Router-ის Link-ს ნავიგაციისთვის: 

import { Link } from "react-router-dom";
import Button from "@mui/material/Button";
import useFetch from "../hooks/useFetch";
import { useCart } from "../context/CartContext";

function ProductList() {
  const { data: products, loading } = useFetch("/api/products");
  const { addToCart } = useCart();

  if (loading) return <p>იტვირთება...</p>;

  return (
    <div>
      {products.map(p => (
        <div key={p.id}>
          <h3>{p.name}</h3>
          <Button variant="contained" onClick={() => addToCart(p)}>
            კალათაში დამატება
          </Button>
        </div>
      ))}
      <Link to="/cart">კალათის ნახვა</Link>
    </div>
  );
}

5. კურსის შემაჯამებელი — საუკეთესო პრაქტიკები

  • სემანტიკური HTML ყოველთვის — ეს დღემდე რჩება ხელმისაწვდომობისა და SEO-ს საფუძვლად, React-ის კომპონენტებშიც კი.
  • Mobile-First CSS — დაწერე პატარა ეკრანისთვის ჯერ, შემდეგ გააფართოვე @media (min-width: ...)-ით.
  • State-ის უცვლელი (immutable) განახლება — spread ოპერატორის გამოყენება, არა state-ის პირდაპირი მუტაცია.
  • Custom Hooks გამოიყენე განმეორებადი ლოგიკის (fetch, ფორმის ვალიდაცია) ერთ ადგილას შესაკრებად.
  • კომპონენტების პატარა ზომა — ერთი კომპონენტი, ერთი პასუხისმგებლობა; დიდი კომპონენტი დაშალე პატარებად.
  • Git commit-ები ხშირად — მცირე, გასაგები commit-ები, მკაფიო შეტყობინებებით.
  • AI ასისტენტები — გამოსადეგია აჩქარებისთვის, მაგრამ ყოველთვის გადამოწმებადია, არა უპირობო ნდობის საგანი.

ეს კურსი დაფარა გზა ერთი HTML ტეგიდან სრულ React აპლიკაციამდე — შემდეგი ნაბიჯი შენია: ააგე რეალური პროექტი, გაუზიარე კოდი GitHub-ზე და გააგრძელე სწავლა პრაქტიკით.

საბოლოო პროექტი — პრაქტიკული დავალებები

  1. ააწყვე ავტორიზაციის მარტივი ფორმა — username/password ველებით, ვალიდაციით, და sessionStorage-ში „ავტორიზებული" მდგომარეობის შენახვით.
  2. შექმენი CartContext ზემოთ მოცემული მაგალითის მსგავსად და დაარეგისტრირე ის App.jsx-ში.
  3. ააწყვე ProductList გვერდი — 6+ პროდუქტით (მასივი static მონაცემით ან useFetch-ით), თითოეულს ჰქონდეს „კალათაში დამატება" ღილაკი.
  4. ააწყვე Cart გვერდი, რომელიც useCart()-ის გამოყენებით აჩვენებს დამატებულ პროდუქტებს და ჯამურ ფასს (reduce()-ის გამოყენებით).
  5. (საბოლოო, კომპლექსური დავალება) გააერთიანე ყველაფერი ერთ სრულ, მუშა React აპლიკაციაში: React Router-ით ნავიგაცია (მთავარი/პროდუქტები/კალათა/შესვლა), Material UI-ის კომპონენტებით გაფორმებული, Context-ით მართული კალათა, და მინიმუმ ერთი custom hook — ატვირთე პროექტი GitHub-ზე.
